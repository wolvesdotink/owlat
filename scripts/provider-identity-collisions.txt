# Vocabulary collisions — scripts/check-provider-identity.sh.
#
# NOT the allowlist, and deliberately a separate file. Every entry here spells a
# string that LOOKS like a send-provider kind but belongs to a different
# vocabulary that happens to share the spelling. There is no coupling to remove,
# so no piece owns them and no sweep clears them: carrying them as "debt with an
# owner" would have made scripts/provider-identity-allowlist.txt permanently
# non-empty, and acceptance criterion A1 unreachable by construction. Split out,
# the debt list can actually reach zero and this one can stay honest about being
# permanent.
#
# ONE ENTRY PER SPELLING, NOT PER FILE. `path:literal` licenses that literal and
# nothing else; a bare path would license the whole file FOREVER, and these
# entries never expire — a `kind === 'ses'` branch added to the setup-apply
# handler next year would inherit a licence granted for a docker compose
# profile. Anything in these files that is not the named other-alphabet word is
# still a violation.
#
# ADDING a line here is a claim that needs evidence in review — name the other
# alphabet and where it is declared. "It reads better this way" is not another
# alphabet. The ratchet still enforces the other direction mechanically: an
# entry that excuses nothing fails the gate, so a file that stops speaking the
# other vocabulary loses its licence.
#
# ONE PLACE PER ENTRY. The note travels on the entry line (`path:literal  #
# note`, `#` comments and blank lines ignored) and the alphabet is described in
# the block header above it. Nothing here is written twice — a list that
# restates its own entries in prose is a list where a sweep deletes one copy.
