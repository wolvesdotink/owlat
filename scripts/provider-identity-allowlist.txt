# Provider-identity allowlist — scripts/check-provider-identity.sh.
#
# The files that may still compare a send-provider kind against a literal.
# Everything else asks the capability catalog. One repo-relative path per line;
# `#` comments and blank lines ignored.
#
# THIS LIST ONLY SHRINKS. That is a review convention, not a suggestion: a pull
# request that ADDS a line is asking to reintroduce the coupling the seams plan
# exists to remove, and has to argue why the seam cannot read a declaration
# instead. The ratchet enforces the other direction mechanically — an entry
# whose file no longer holds a kind literal FAILS the gate, so a cleanup cannot
# leave its licence behind for the next restatement to inherit.
#
# EVERY ENTRY IS DEBT WITH AN OWNER. A file whose kind-shaped literal belongs to
# a DIFFERENT vocabulary (the MTA routing API's answer, a docker compose
# profile, the contact-import registry) is not debt and is not licensed here —
# it lives in scripts/provider-identity-collisions.txt, so that this list can
# reach zero. THE ENTRY COUNT BELOW IS WHAT ACCEPTANCE CRITERION A1 MEASURES.
#
# SCOPE NOTE — WIDER THAN P0.5'S CARD READS. The card names the D3 definitional
# sites (the own-arm constant, delivery/relayConfiguration.ts, the hybrid
# detection in route.ts / routing.ts) as the expected contents. After the P0.1–
# P0.4 sweep none of those four files COMPARES a kind any more — the own-arm
# site is a declaration (`export const OWN_ARM_TRANSPORT_KIND = 'mta'`, which
# the backend's kindLiteralCustody.test.ts owns), and the other three retain
# the literal only in the prose explaining what replaced it. Listing them would
# trip the stale-entry check and turn the gate red. So the scan was widened to
# all of apps/ and packages/ instead of stopping at the backend, and what it
# found — the setup wizard, the transport editor, the CLI and the shared
# validators, none of which any Wave-0 piece touched — is carried here as named
# debt rather than left invisible. That is the ecosystem goal's real surface:
# while these branches exist, a provider that needs no backend edit still
# cannot ship without a host edit.
#
# THE OWNING PIECE MUST DELETE ITS LINES. Each family below names the piece
# that clears it; because the ratchet fails on a stale entry, that piece's diff
# has to include the deletion here or the lint job goes red. P1.1 additionally
# turns SEND_TRANSPORT_KINDS into a derivation, which means repointing the kind
# parser at the top of check-provider-identity.sh in the same change.
#
# Kind DECLARATIONS inside apps/api/convex are a different rule with a different
# list: SURVIVING_KIND_LITERALS in
# apps/api/convex/lib/sendProviders/__tests__/kindLiteralCustody.test.ts. That
# test reads THIS file for the comparison half rather than restating it, so a
# swept backend file is de-licensed by exactly one deletion — here.
#
#
# ── return-path (owner: the sending-domain adapter interface) ─────────────────
#
# Which `mailFrom` bundle a custom return-path host publishes, and which kinds
# accept one at all, is branched on 'mta'/'ses' while the catalog already
# declares `supportsCustomReturnPath`. The capability has no home on
# `SendingDomainProviderModule` yet; `domains/providers/index.ts` states the gap.
# No wave-0 or wave-1 piece clears this one — whichever piece finally grows that
# capability (D1's field reaching the module contract) deletes these two lines.
#
# apps/api/convex/domains/lifecycle.ts          — the record-set derivation
# apps/api/convex/delivery/checklistDomainValidators.ts — restates it as a check
#
#
# ── adapter-adjacent (owner: one kind's scheduled work moving beside it) ──────
#
# Mandrill adapter code that cannot sit in domains/providers/mandrill/: these
# are a scheduled action and its mutation, so the module path IS the Convex
# function path. Both literals ask "is this row/domain mine?" of the
# deliberately kind-agnostic sendingDomainRelayIdentities table; when a second
# kind wants the same sweep, that question becomes the table's own dispatch.
#
# apps/api/convex/domains/mandrillRelay.ts
# apps/api/convex/domains/mandrillRelayMutations.ts

#
# ── provider-shaped-ui (owner: P1.2 — the UI renders descriptors, D5) ─────────

# branches exist, a provider that needs no backend edit still cannot ship
# without a UI edit. The catalog's typed `credentialFields` descriptors and a
# renderer that loops over them retire the whole family at once — P1.2 deletes
# these seven lines with the branches.
