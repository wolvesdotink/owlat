# oxlint-plugin-owlat

Owlat's own oxlint rules. The root `oxlintrc.json` loads `src/index.ts` through
`jsPlugins`, so every `oxlint --config …/oxlintrc.json` run (the root gates and
each workspace's `lint`) applies them. oxlint imports the source directly with
Node's type stripping: there is no build step, and the code must stay erasable
TypeScript with explicit `.ts` import specifiers.

| Rule                                       | What it enforces                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `owlat/require-suppression-reason`         | Every `oxlint-disable` / `eslint-disable` / `@ts-*` directive says why: a `-- reason` tail or a comment on the line above. TypeScript directives are recognized in every comment form the compiler obeys (`///` and block comments included, checked against the real compiler). Generated files are exempt. The root config keeps `@ts-ignore` / `@ts-nocheck` banned through `ban-ts-comment` and leaves the `@ts-expect-error` reason to this rule.                                                                                           |
| `owlat/no-test-environment-pragma`         | No per-file `@vitest-environment` pragma; the package's vitest config selects the environment. Matched with vitest's own pattern over the whole file text (comments, prose and strings alike). Deliberate exceptions are listed under the rule's `allow` option in `oxlintrc.json`.                                                                                                                                                                                                                                                              |
| `owlat/no-inline-backoff`                  | Exponential backoff is computed by `nextDelay` from `@owlat/shared/retryPolicy`, never inline. Outside test files and the policy module, reports a growing exponentiation (`a ** n` / `Math.pow(a, n)` with a literal base above 1 other than 10, or a base named as a factor, multiplier or backoff, and an exponent that is neither constant nor negated) and a wait multiplied in place (`x = Math.min(x * k, cap)`, `x *= k`, where `x` names a delay, backoff, retry, wait or interval, or ends in `Ms`).                                   |
| `owlat/no-test-in-loop`                    | No vitest `it` / `test` / `describe` declared inside a loop, including modifier chains, curried factories and tagged-template `.each` tables; use `.each`.                                                                                                                                                                                                                                                                                                                                                                                       |
| `owlat/no-test-timeout-or-unreasoned-skip` | A per-test, per-suite or per-hook timeout names a constant from the root `vitest.timeouts.ts`, never a local number. No `retry`, in a test's options, `vi.setConfig` or a vitest config file. `.skip` / `.todo` (and `skipIf(true)`-style literals) need `// quarantine: #<issue> <why>` directly above; `skipIf` / `runIf` on a real condition stay allowed. A warning: existing local timeouts are frozen in `scripts/owlat-lint-baseline.txt`.                                                                                                |
| `owlat/no-real-time-wait-in-tests`         | No real-clock sleep in a test file (`*.test.*`, `*.spec.*`, `__tests__/`): a `new Promise` resolved by a timer with a delay (global or `node:timers`), a `node:timers/promises` timer, a `sleep` / `delay` helper, `Bun.sleep`, Playwright's `waitForTimeout`. Await the event or drained queue, or drive fake timers; a sleep on a global timer that the same function advances with `vi.advanceTimers*` / `vi.run*Timers`, with that timer in the faked set and `shouldAdvanceTime` off, is allowed. Warning, debt in the owlat lint baseline. |
| `owlat/no-wall-clock-in-tests`             | No elapsed wall-clock measurement in a test file: every `performance.now()` / `process.hrtime()` (globals or `node:perf_hooks` / `node:process` imports), and a subtraction or comparison between two `Date.now()` readings (stopwatches, deadline loops, clock spins). Single fixture timestamps such as `createdAt: Date.now()` stay allowed, and so do readings taken after the same function calls `vi.setSystemTime` on a faked `Date`. Warning, debt in the owlat lint baseline.                                                           |
| `owlat/no-polling-loop-in-tests`           | No polling loop in a test file: a `for` / `while` / `do…while` whose body awaits a sleep or tick (timer promise, `Promise.resolve()`, `flushPromises`, `nextTick`, or a local helper wrapping one) while a predicate decides when it stops. A fixed number of flushes (a counter moved only by a fixed, nonzero step) is fine. Warning, debt in the owlat lint baseline.                                                                                                                                                                         |

## Adding a rule

1. Write `src/rules/<name>.ts` and its RuleTester suite in
   `src/rules/__tests__/` (oxlint's own `RuleTester` from `oxlint/plugins-dev`,
   wired to vitest in `src/__tests__/ruleTester.ts`).
2. Register it in `src/index.ts` and turn it on in `oxlintrc.json`.
3. If code still breaks it, configure it as `"warn"` and seed the ratchet
   baseline with `bash scripts/check-owlat-lint.sh --write-baseline`; the
   `lint:owlat` gate then fails on any new finding. Otherwise use `"error"`.

Keep the visitor cheap: the rules run on every linted file, so skip a file by
a plain text check in `create` when it cannot match, before asking for
comments or scope. Shared helpers live next to the rules: `src/ast.ts` (scope
resolution, imports, the test-file pattern), `src/waits.ts` (what counts as a
sleep or tick) and `src/fakeClock.ts` (whether vitest's fake timers drive a
piece of test code).
