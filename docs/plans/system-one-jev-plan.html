A third plane: decisions, typed and priced at nothing.

TypeSafe shipped Jev, a model that does not write text. You hand it state and a set of typed questions, and it hands back choices, scores and probabilities in a fraction of a second, charging for input tokens only. Fourteen of our decision call sites are exactly that shape and we currently pay a text model to fake it. This plan adds a decision plane next to the language and embedding planes, makes Jev the default provider within that plane, and never sends a byte anywhere until an operator enters their own key.

00

What Jev actually is

One endpoint, POST https://api.typesafe.ai/v1/systemone, bearer auth, one model id (jev-1.13.0, aliased by both jev-latest and jev-preview). You send a state (string, object or array) and a map of named questions. You get back one typed answer per question. There is no prose, no token stream and no schema to validate, because the answer space is the set of options you sent.

Question typeYou sendYou get backUse it for
Noulinstructions, optional criteria: {true, false}noul: a probability 0 to 1. No confidence field.Yes/no where the probability itself is the signal. Needs a reply? Contains an injection?
Choiceinstructions, criteria: a map of option to description (descriptions may be null)choice, probabilities over all options, confidenceUnordered labels. Category, intent, relation type.
Scoreinstructions, criteria: an ordered list of at least 2 level descriptionsscore (can land between levels), legend, probabilities keyed by level, confidenceOrdered judgement. Urgency, frustration, passage relevance.
Two distinctions the rest of this plan depends on

Probability is not confidence. Choice and Score return a distribution plus a derived confidence (how peaked that distribution is). Noul returns a bare probability and no confidence. Any threshold we write has to name which one it reads, and Noul thresholds are distance from 0.5, not peakedness. Calibration is a group property. TypeSafe's own wording: calibration is measured across groups of predictions and "does not guarantee that an individual answer is correct", and the right threshold "depends on your domain". So a calibrated probability is a better input to a gate than a self-reported one. It is not a correctness guarantee, and §11's P5 is written accordingly.

01

What it buys the product

Not "we save money on tokens", although we do. Four things change that we have wanted and could not afford.

01 · triage

Mail lands triaged, not eventually triaged

The agent pipeline spends roughly 9 to 25 seconds in fast-tier decisions before a human sees a verdict, because guard, classify and clarify each wait on their own round trip. Two batched decision calls do the same work in about a second. The Postbox Reply Queue and the Team Inbox stop showing a heuristic placeholder that gets overwritten a minute later.

02 · autonomy

A second real signal for auto-send

Auto-send already gates on a real number: resolveAutoApproveScore(input.draftQuality) in agent/steps/route/index.ts:142, which is the draft self-check, not the classifier's self-report. That self-check is itself an LLM guessing about itself (agent/shared/draftService.ts:111). Replacing that with a calibrated probability improves the number the gate already reads, which is a much smaller and much safer change than the one I proposed in rev 1.

03 · headroom

The dollar ceiling stops binding

analytics/spendBudget.ts is an enforced daily and monthly USD ceiling. When it runs low, mail/ai/gate.ts cuts advisory features first to reserve the tail for drafting, and spendBudgetGate withholds auto-send. Decisions are what fills that ledger fastest and they are the cheapest thing to move. Moving them buys headroom for the drafting that actually needs a text model.

04 · honesty

Fewer silent degradations

28 of 40 dispatch calls sit inside a try; 6 of those degrade to a computed heuristic baseline and 21 degrade to null or empty. Twelve sit in no try at all, including classify/index.ts:80. Most of those catches exist for malformed JSON and schema drift, which this model cannot produce.

The honest counterweight

Jev cannot write. Every draft, reply variant, translation, summary and assistant turn stays on the language plane. This is an addition, not a replacement. It also puts a third party on the path of customer mail, which in a self-hosted product is the operator's decision to make and ours to document precisely. Nothing here ships enabled.

03

The decision plane

We run two decoupled planes today: LANGUAGE (everything that writes) and EMBEDDING (retrieval, local by default so it resolves under any language choice). Both go through lib/llmProvider.ts and a registry of one-file adapters guarded by a mapped-type assignment (llmProviders/index.ts:63), the pattern documented in decisions/8.007-pluggable-llm.md. Jev fits neither. It is not an AI SDK LanguageModel, and wrapping it in generateObject would throw away the probabilities, which are the entire reason to use it.

So: a third plane, built like its neighbours. Note the two existing adapter shapes already differ (the embedding adapter has no listModels, no per-tier models and an extra dimension guard), so "like its neighbours" means a deliberate choice, made here: the decision adapter follows the language shape, minus tiers, since there is one model.

File plan

lib/llmProvider.ts is exactly 500 lines and scripts/check-file-size.sh caps new files at 500 with a frozen baseline. So the resolver does not grow a third plane inline. It gets a sibling.

Purity matters for types.ts and questions.ts for a specific reason: schema/instance.ts imports the validators, which import the registry's kind tuple, so nothing in that chain may pull in node:crypto or @ai-sdk/*. Every call site that will use the plane is already 'use node', so isolate-safety is about the schema chain, not the callers.

The question DSL

// lib/decision/questions.ts
export const noul = (instructions, criteria) => ({ type: 'noul', instructions, criteria })
export const choice = (instructions, criteria) => ({ type: 'choice', instructions, criteria })
export const score = (instructions, criteria) => ({ type: 'score', instructions, criteria })

// Answers mirror the set's keys. Noul returns a probability and NO confidence.
type NoulAnswer   = { kind: 'noul'; probability: number }
type ChoiceAnswer = { kind: 'choice'; value: string; probabilities: Record<string, number>; confidence: number }
type ScoreAnswer  = { kind: 'score'; value: number; levels: string[]; probabilities: Record<string, number>; confidence: number }

Our answer shape is not the wire shape. The wire returns { type, noul } or { type, choice, probabilities, confidence } or { type, score, legend, probabilities }, with Score probabilities keyed by level and Choice descriptions allowed to be null. wire.ts owns that translation in one place, exactly as normalizeUsage owns the AI SDK's field-name history in lib/llm/dispatch.ts.

The dispatch contract

Rev 1 said "retry, fallback, usage" and left six behaviours undefined. They belong in ADR-0060 before a line of adapter code is written.

BehaviourRule
DeadlineEvery request carries AbortSignal.timeout(). fetchGuarded passes init through and adds no timeout of its own, and a plane selling sub-second answers must not inherit an unbounded socket.
RetryReuse isRetriableLlmError rather than forking it. 5xx (including 529) and 429 retry, 401/403/422 do not. Add jitter, which the language plane lacks, and honour Retry-After: one shared upstream bucket plus our synchronized ingest is exactly the shape that produces a retry storm.
AbortrunLlmObject takes no AbortSignal today (dispatch.ts:294), so the llm-backed adapter cannot honour one. Widening LlmObjectOptions with an optional signal is a three-line prerequisite and belongs in the same PR.
Partial or foreign answersA missing requested key, an extra key, or a Choice value outside criteria is a hard error, not a coerced answer. It means our question set and the model disagree, and silently repairing it would corrupt the calibration statistics that every later phase gates on.
FallbackOne hop to the llm adapter, never from 401/403/422 (those are our bug or our config, and falling back would hide them forever), and never without the circuit breaker below.
AccountingEvery call writes an llmUsageEvents row with a plane tag before the answer is used, so the enforced ceiling sees it.
The fallback hop is a cost lever an outsider can pull

Default-on fallback means anything that breaks the decision plane (an expired key, a 429, a vendor outage) silently re-routes every inbound message onto a model that costs 24 to 50 times more, on the path that is fed by strangers sending us email. analytics/spendBudget.ts exists because of that exact threat: "an org (or a prompt-injected auto-reply loop) can run up unbounded spend". So the hop needs a circuit breaker modelled on the llm_failure breaker in agentHealth.ts:488, it is default-OFF for the high-volume background classifiers, and the plane gets its own share of the ceiling. Also: MAX_EVENTS_SCANNED = 10_000 in spendBudget.ts:200 is a bounded scan, and one extra row per message will push a busy day past it, which makes the ceiling under-report. That constant has to move with this work.

04

Staying exchangeable

Three separate promises, and they are also what make the default safe.

1. Any adapter answers any question set

The llm adapter renders a question set into a zod schema plus a deterministic prompt, calls runLlmObject on the existing language plane, and returns the same result shape. Choice becomes an enum, Score a bounded integer with the levels in the prompt, Noul a 0-to-1 number. Probabilities come back degenerate and the result is stamped calibrated: false. This is not a stub: it is the path every install without a key runs, it must reproduce today's labels, and it is why reverting is a dropdown.

2. One conformance suite, both adapters

Every question set is exported and registered in a catalog. One vitest suite runs the whole catalog through both adapters against recorded fixtures, asserting shape, key sets, value domains, and the fallback path. An unregistered question set fails the suite.

3. A third adapter is one file

One adapter file, one registry line, a validator union that widens itself, one settings option. The mapped-type guard makes a missing method a compile error.

Design rule

No call site imports an adapter. Call sites import runDecision and their own question set. The single exception is the calibrated flag, which gates every threshold and must be read from the result rather than assumed.

05

Opt-in, and what default means

Owlat is self-hosted and ships infrastructure. We do not run a hosted platform, we do not broker third-party keys, and there are no plan tiers. Every operator brings their own key for every provider, and that is as true for a decision provider as it is for OpenAI today. Rev 1 of this plan had several passages that assumed otherwise. They are gone.

So "make Jev the default" resolves to four different defaults, and they are not the same question:

Default at this levelIs Jev the default?
A fresh install going through setupYes. The decision provider defaults to TypeSafe Jev in the wizard and in the settings UI. The operator supplies their own key, as they do for every other provider; skipping is one keystroke and leaves the language-backed adapter.
Which provider the decision plane uses once configuredYes. TypeSafe is the recommended adapter and the one we document first.
Which plane answers a decision once a key worksYes. All fourteen migrated call sites route through it and the language plane becomes the fallback.
What an install resolves to with no keyNo, necessarily. DEFAULT_DECISION_KIND = 'llm'. A provider with no credential cannot answer, so resolution degrades to the language plane, which is exactly today's behaviour.
What happens to an existing install on upgradeNothing. No migration, no banner, no preselected vendor in an existing config. It appears as an available option in the AI provider page and in the docs.
Two constants, deliberately different

SETUP_DEFAULT_DECISION_KIND = 'typesafe' is the wizard's pre-filled answer for a brand-new install. DEFAULT_DECISION_KIND = 'llm' is what resolution falls back to when no key resolves. Giving them one name would collapse "what we recommend" into "what happens to an install that never opted in", and those must stay separable. We still never ship, broker or proxy a key.

The fresh-install wizard asks once, alongside the existing provider questions, with Jev pre-filled and skip as a first-class answer. Enabling it anywhere shows one consent screen that names the vendor, the endpoint host, exactly what content leaves the deployment, the region if they confirm one, and their retention and training position. An operator should be able to read that screen and answer their own DPO without opening a browser.

Who is the controller here

In a self-hosted deployment the operator is the data controller and TypeSafe would be their processor, not ours. We cannot and should not sign anything on their behalf, and this repo has no privacy policy or subprocessor list to add a line to. The correct artefact is an operator-facing data-flow note in 3.developer/15.providers.md (both languages): what leaves, to which host, under which key, with the vendor's own privacy contact. That is more useful than a legal paragraph we are not entitled to write.

The settings surface

A third card in apps/web/app/pages/dashboard/admin/instance/ai-provider.vue, same anatomy as the other two: provider select, key field with masked preview, model id, base URL, test button. Three controls are new.

  • Fall back to the language model. Per-surface rather than global: on for the agent pipeline, off for the high-volume background classifiers, because that is where an outage turns into a bill.
  • Thresholds. Named per answer type, because Noul has no confidence. A Noul threshold is distance from 0.5; a Choice threshold is confidence.
  • A visible degraded state. When the resolved adapter is uncalibrated, or the breaker is open, or the key failed its last test, the card says so in words and the thresholds are inert. This is the visible payoff of the calibrated flag and it needs real copy in en.json and de.json, not a disabled attribute.
06

Call-site migrations

Each is separately shippable: add a question set, swap runLlmObject for runDecision, keep the surrounding fail-soft and the deterministic baselines. Ordered by value, not by ease.

The draft self-check, first

This is the one that matters and rev 1 buried it. agent/steps/route/index.ts:142 computes resolveAutoApproveScore(input.draftQuality) and that score, not the classifier's confidence, is what tier 2 and tier 3 compare against a threshold. draftQuality comes from the self-check in agent/shared/draftService.ts:112, which is a text model rating its own draft. Replacing that number with a calibrated one improves the input the gate already reads, without touching the gate structure.

classify

Four Choices replace one runLlmObject, and the self-reported confidence field is deleted. Two invariants must survive verbatim and both are already load-bearing: the spam fork still archives, and a natural-language categorize rule may only restrict auto-send and may never relabel a safety-critical verdict.

Found while auditing

classify/index.ts:80 has no try/catch around its model call. A provider failure today throws, the walker catches it, and the run goes to failed. So the claim that every call site fails soft is false for the flagship migration. Adding a decision provider without adding a fail-soft path here would widen an existing hole. Fix it in the same PR.

security_scan

The four disjoint windows become one call with an array state and a Noul per window. The deterministic regexes in patterns.ts stay, and so does the OR. Their jaggedness page states plainly that Jev does not treat state as hostile and that injected instructions can move answers. That is our threat model exactly, so it becomes the second opinion, never the only one.

Both thresholds get re-derived from measured calibration, not carried over by eye: LLM_INJECTION_CONFIDENCE_THRESHOLD (0.8, index.ts:45) and the differently-valued INJECTION_CONFIDENCE_THRESHOLD (0.7, patterns.ts:14) which also feeds the quarantine gate and autoSendGates.ts:125.

Postbox category and needs-reply

The two highest-volume background classifiers, both already shaped as "persist a deterministic baseline, refine with the model, fail soft". Category is one Choice. Needs-reply becomes a Noul plus an urgency Score plus a scheduling Noul in one call.

askSummary is generated prose and stays. dueHint is an ISO date, and Jev reads dates as text rather than as ordered quantities, so the split is: Jev answers "does this state a concrete deadline" as a Noul, and only a yes buys a language-plane call to extract and normalise it. Cheaper than today and more correct, because we stop asking a text model to volunteer a date field on every thread.

clarify, slots and divergence

Slot extraction writes text, so it stays. What moves is the two judgements per slot (answerable from context, decision-relevant) and the divergence judgement over sampled candidates. Six candidate slots cost one call instead of one fat schema.

Rev 1 proposed deleting the high_coverage_short_circuit path now that the expensive stage is cheap. That was wrong twice: narrowing a persisted union needs a version bump under our own schema conventions, and it contradicts the promise that nothing is removed. Lower its threshold instead, measure, and leave the union alone.

Autonomy, done the way the code is actually built

The gate registry is restrict-only by design (ADR-0051, "ordered restrict-only autonomy gates"): each gate returns safe or unsafe, any throw fails closed, and plugins get no way to skip or replace. A three-way router that unlocks auto-send above a threshold cannot live there. Rev 1 put it there. Corrected placement:

  • The calibrated probability feeds resolveAutoApproveScore and the tier comparisons in route/index.ts:142,170,218. That is where a score already decides.
  • A new restrict-only uncalibrated_decision gate joins CORE_FINAL_AUTO_SEND_GATES. It can only block: if the persisted verdict was answered by an uncalibrated adapter, or by a different provider than the one now configured, no auto-send.
  • The shadow scorecard records the probability alongside each would-have-sent decision, so graduation rests on a measured relationship rather than a raw match rate over ten samples.

07

What becomes affordable

Migrations pay for the plane; these are the reasons to build it. Rev 1 listed six. Two are cut and one is descoped, because their own cookbooks say so.

assistant

Guardrails on both directions

The agent pipeline has a guard step. The chat assistant does not: assistant/runner.ts streams user text to a capable model with tools bound. One call per turn screens in and out. Their guardrails cookbook is one request per message, which is the shape we need and the budget we can afford.

knowledge

Citation checking on every answer

Quick Query cites knowledge and files and nothing verifies the citation. Their cookbook does this with one Choice per claim against the source, not a Noul per citation. Cheap enough to run always instead of never.

search · self-hosting

Semantic find without an embedder

The embedding plane is local by default and many installs never stand up the sidecar, so retrieval quietly degrades to lexical. Scoring candidate lines against a query gives those installs semantic search with no vectors. Worth a measured experiment, sized by the rate limit.

plugins

A decision capability for plugins

The better fit for what plugin steps do: classify, gate, route. The budget maths also gets easier when output is free and the input bound is known before the call. The wire ripple is smaller than rev 1 claimed: only packages/plugin-kit carries the LLM contract; the SDKs are REST clients with no LLM references.

Cut, with reasons

Pre-send content screening in the MTA. apps/mta is a separate Node service with no Convex context, no access to aiProviderConfig and no envelope decryption. Giving it a decision credential is a cross-service key-distribution design, which is its own plan, not a bullet in this one.

Search reranking, as scoped. Their rerank cookbook is one request per query-candidate pair, so 30 candidates is 30 requests, not one, and it lifted top-1 from 5% to 18%, which leaves 82% wrong. At 30 requests a search we would cap the deployment at roughly 40 searches a minute against their published limit. It may still be worth doing on a shortlist of five. It is not the free win rev 1 described.

The plugin capability is last for a structural reason: scripts/check-hosted-seams.sh fails CI unless a new capability ships a plugins/<x>Authorization.ts that calls authorizeHostedContribution(), and the codegen, orphan and public-type checks all run against it. It is also the point where the question DSL gets lifted into packages/decision-kit, because a second consumer will finally exist.

Cost and latency

Modelled, not measured, and recomputed after review. P0 replaces every figure here with real numbers.

Assumptions

  • Fast tier is gpt-5.6-luna at $1 per M input, $6 per M output (lib/llm/pricing.ts:19).
  • Jev at $0.042 per M input, output returned but billed at $0.
  • A message body of about 8,000 characters, roughly 2,000 tokens, plus retrieved context. Question text is billed too and adds a few hundred tokens per call.
  • Fan-out consolidates the four guard windows into one request and the classify plus clarify judgements into a second. The windows are disjoint, so this removes round trips, and the token saving comes from classify, slots and divergence no longer each re-sending the message.

Where this model is optimistic

Consolidating seven calls into two assumes the state fits the budget and that accuracy holds when one state answers a dozen questions. Their jaggedness page warns the opposite direction: accuracy falls as state grows with content unrelated to the decision. P0 tests one fat call against two or three focused ones and scores on agreement, not on price.

The redaction policy, written down

Rev 1 said "filter before sending", which is a sentence, not a design. The rule: strip quoted history and signatures, strip HTML to visible text with the same helper security_scan uses, drop attachments entirely (they are not text), cap state at a stated character budget with the head and tail kept, and honour a per-mailbox opt-out so a mailbox can be excluded from third-party decisions without disabling AI for the deployment. Accuracy and privacy want the same thing here, which is convenient.

Vendor and operational risk

  • Early access, no published SLA, region unconfirmed. Mitigated by the breaker and by fail-soft paths, two of which we have to add first (classify, handlingRulesCompile). A chaos test that fails every decision call is part of P1, not a nice-to-have.
  • Version pinning. Pin jev-1.13.0. Both jev-latest and jev-preview point there today, and a silent model swap under a threshold that gates sending mail is the worst version of this idea. A bump re-runs the calibration harness before it ships.
  • Rate limits are explicitly dynamic. Never hard-code 1,200 rpm. The named bucket in rateLimiter.ts is our own ceiling, and Retry-After is authoritative when they push back.
  • No idempotency. Their API documents none. A retried POST double-writes usage and, worse, double-counts in the agreement statistics every later phase gates on. Dedupe on a client-side request id, the way plugins/llmAccounting.ts uses reservationId.
  • Key handling. Same AES-GCM envelope, decrypted only in the Node action, never returned by a query, request through the SSRF guard. Note fetchGuarded refuses redirects, so a 3xx from their host surfaces as a guard error and needs a clear message.
  • Jurisdiction is the operator's call. We document the host, the payload and the vendor's own privacy contact, and we ship the opt-out. We do not decide for them and we do not sign for them.
10

Testing and calibration

Swapping the model behind fourteen decisions is a behaviour change dressed as a refactor. The only honest way to ship it is to measure agreement before each flip.

The replay harness, and its artefacts

scripts/decision-replay.ts (root scripts/, which is where hand-run tools live; everything in apps/api/scripts/ is a CI check-* guard chained into lint). It runs a registered question set through both adapters over a fixture corpus and reports per-question agreement, the disagreement cases with their probabilities, and calibration as reliability buckets plus a Brier score.

The corpus and the labels are checked in, anonymised, starting from the fixtures already in agent/steps/*/__tests__. If only the author can regenerate the evidence for a flip, it is not evidence. And since we have no fleet, "a week of shadow data" means one dogfood mailbox, which the phase gates should say out loud rather than imply a scale we do not have.

Shadow, reused

agent/shadowScorecard.ts already runs a full decision without acting on it and reconciles against what the human did. Pointing it at a second provider gives us disagreement data from real mail with no risk.

In CI

  • No network. The TypeSafe adapter runs against a mocked fetch: 401, 403, 404, 422, 429, 5xx, 529, timeout, connection failure, malformed body, missing key, extra key, out-of-domain Choice value.
  • Conformance across adapters. The whole question catalog through both, asserting shape, key sets and value domains.
  • Chaos. Every decision call fails; every touched call site still produces its documented outcome, including the two that need a fail-soft path added.
  • The uncalibrated gate. Auto-send stays blocked when the persisted verdict is uncalibrated or came from a different provider than the one now configured.
  • Budget. A test that a decision row lands in llmUsageEvents before the answer is used, and that the fallback hop respects the breaker.
  • Live smoke behind TYPESAFE_API_KEY, skipped by default, run before a version bump.

Gates this work has to clear, beyond vitest and bun run ci:test: lint:env, the convexRuntimeEnv key-sync check, check-env-docs.sh (both languages), check-file-size.sh (500 lines, frozen baseline), lint:adr, lint:patterns, the web and docs locale-parity suites, and for any new admin mutation check-public-functions.sh, check-permissions.sh and check-session-threading.sh. P6 additionally faces check-hosted-seams.sh. Never bun test.

If you only read one paragraph

Fourteen of our decision call sites ask a text model to pick a label and then guess how sure it is. Jev is built for exactly that, costs about 2% of what we pay for it, answers in a fraction of the time, and returns a probability that is calibrated across groups. Build it as a third plane with its own adapter registry, ship it switched off, let the operator bring their own key and see exactly what leaves their deployment, and let a checked-in replay report rather than a price list decide each cutover.
