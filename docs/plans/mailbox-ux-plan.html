Mailbox UX Improvement Plan

A prioritized plan to improve the day-to-day experience of Owlat's two mailbox surfaces — the personal Postbox and the admin Team Inbox — grounded in what already ships today. Eight recommendations, each with evidence, a concrete proposal, and a visual example.

01

What's already strong

The mailbox is unusually well-built for this stage. These are deliberate design decisions — the plan below extends them; none of them should be regressed while improving UX.

KEEP

Keyboard-first triage

Full Gmail-class shortcut model (j/k, e, #, s, x, ? cheat sheet), focus that survives live updates and virtualization.

KEEP

Live everything

All feeds are Convex live queries — new mail, presence rings, and draft badges appear without refresh.

KEEP

Optimistic hide + one-slot undo

Triage feels instant; Cmd+Z reverses it. This is the interaction backbone — build on it, don't replace it.

KEEP

Error ≠ empty discipline

Failed loads render an explicit error alert, never a fake "nothing here" state. Rare and correct.

KEEP

Listbox semantics + reduced motion

role="listbox" with aria-activedescendant, skeletons aria-hidden, transitions disabled under prefers-reduced-motion.

KEEP

Two landing modes

Today (focused single column) vs Browse (three panes), persisted per user — a real point of view, not a settings dump.

R1

A mobile shell for Postbox

R1
Phase 2 · Flagship · Impact: High · Effort: Large

Collapse the three panes into a stack: drawer → list → full-screen reader

Evidence PostboxLayout.vue hard-codes w-56 + w-96 panes inside h-[calc(100vh-4rem)]. Only 4 of 88 Postbox components carry any sm:/md:/lg: class. Meanwhile the dashboard shell itself is responsive — so phone users pass the gate and land on a squeezed desktop layout.

What changes

  • Below lg: single-pane stack. Folder rail becomes a slide-over drawer (hamburger in the list top bar). Opening a message pushes a full-screen reader over the list; back returns with scroll position intact (the list already remembers scroll per folder).
  • Touch adaptations: rows get ≥44px targets; the existing right-click context menu becomes the long-press menu (it already exists — PostboxThreadRow.vue — so this is wiring, not new UI). Hover quick-actions stay desktop-only behind hover: hover.
  • Compose: floating compose button on touch; the existing composer popup mode becomes the mobile sheet.
  • Keyboard model untouched on desktop — all of this lives behind a useMediaQuery-style breakpoint, exactly like the existing Today↔Browse mode switch.

How

  1. Land R8's reader/list splits first (see below) so pane components can be reused across layouts.
  2. Introduce a paneMode: 'three' | 'stack' computed from viewport in PostboxLayout.vue — the same seam that already switches Today↔Browse.
  3. In stack mode: rail → drawer overlay; list fills width; selecting a row routes to the existing [messageId] child route rendered full-screen (Nuxt page transition, --motion-moderate).
  4. Add min-h-[44px] row hit targets and pointer-coarse variants; gate hover-only affordances behind @media (hover: hover).
  5. Verify against the dashboard shell's existing mobile sidebar so there is exactly one navigation layer on small screens.
R2

Triage filters in the list header

R2
Phase 1 · Quick win · Impact: High · Effort: Small

One tap from "everything" to "what needs me"

Evidence The most common triage question — "show me only unread" — currently requires opening search and typing is:unread (usePostboxSearch.ts). The flags it needs (flagSeen, flagFlagged, hasAttachments) are already projected onto every list row (PostboxThreadRowMessage).

What changes

  • Add a chip row under the folder title: All · Unread · Starred · Attachments, with live counts.
  • Filters apply client-side over the fetched window — instant, no new queries, works offline.
  • Selection persists per folder (same mechanism that persists Today↔Browse), resets sensibly on folder switch.
  • Counts come free from the existing unread-badge plumbing (listFolders already computes unread totals).

How

  1. Extract the list header into PostboxListHeader.vue (needed anyway for R1/R8).
  2. Add a flagFilter: 'all' | 'unread' | 'starred' | 'attachments' ref in usePostboxThreads.ts; filter the projected rows before virtualization.
  3. Persist per (mailbox, folder) in the same localStorage namespace used for landing mode.
  4. Empty-result state reuses PostboxEmptyState with copy like "You're all caught up — Show all".
R3

Search you can trust: counts, pagination, guided refinement

R3
Phase 2 · Impact: Medium · Effort: Medium

Show the ceiling, raise it, and help users narrow

Evidence mail/mailbox.ts:search caps at 200 results with no cursor, and from:/to:/subject: matching happens as post-filter substring scans after the snippet index. Users see the first page of a result set whose true size is invisible.

What changes

  • Honest counts: "Showing 1–50 of 200+" — when the cap binds, say so explicitly instead of silently truncating.
  • Cursor pagination: add a continuation cursor to search so "Load more" walks deeper than 200.
  • Guided empty state: zero results offers the operator cheat sheet inline (the ? overlay content) instead of a dead end.
  • Later (backend): promote from: to a search-index field so sender-scoped searches stop being substring scans.

How

  1. Backend: extend search with a cursor arg (continue the time scan / index scan from the last seen receivedAt + id pair — keyset, mirroring listMessages' take(limit+1) shape).
  2. Return { messages, hasMore, cappedAt }; UI renders "of 200+" when cappedAt is set even while more pages remain loadable.
  3. Frontend: extend usePostboxSearch.ts with accumulate-and-dedupe (copy the pattern useInbox.ts already uses for keyset pages).
  4. Build the refinement empty state from the parsed operator AST the composable already produces — each chip removes one node.
R4

Permission-aware Team Inbox states

R4
Phase 1 · Quick win · Impact: Medium · Effort: Small

"No access" must never look like "all done"

Evidence inbox/queries.ts:listThreads returns empty arrays for non-admin/owner callers, while the route passes the requiresFeature: 'inbox' gate. A member who clicks Team Inbox sees a legitimately-styled empty state — indistinguishable from a cleared queue.

What changes

  • Backend: make the access boundary explicit — either a discriminated return ({ access: 'forbidden' }) or a cheap capability query the page checks first.
  • UI: forbidden renders an access explainer — who can help, and where to go instead — never a fake zero.
  • This preserves the security posture (still no data leaked) while fixing the meaning of the screen.

How

  1. Add canAccessTeamInbox to the existing capability/permission helpers the web app already consumes for gating.
  2. Check it in pages/dashboard/inbox/index.vue before subscribing to listThreads; render the explainer when false.
  3. Optionally harden the backend return to { access: 'forbidden' } so the contract is explicit for future API consumers.
R5

Server-side label views (retire the P7 debt)

R5
Phase 1 · Impact: Medium · Effort: Small–Medium

Correctness past 500 messages, for free

Evidence pages/dashboard/postbox/label/[labelId].vue fetches up to 500 messages and filters by label client-side; the in-file comment defers this to "P7". Labels with more than 500 messages silently miss entries, and every label visit pays for 500 rows regardless.

What changes

  • Add an indexed by_label_and_received query (listByLabel) returning the same row projection the folder list uses.
  • The page swaps its fetch-and-filter for the query — zero visual change, which is the point: this is invisible correctness plus speed.
  • Unlocks per-label unread counts in the folder rail (same denormalized-count pattern folders already use).

How

  1. Add the index in schema/ and the listByLabel query next to listMessages in mail/mailbox.ts, reusing its projection helper.
  2. Swap the page's data source; delete the client-side filter and the P7 comment.
  3. Follow-up (optional): rail badge per label via a bounded count query, mirroring listFolders.
R6

Keyset pagination for Postbox thread lists

R6
Phase 3 · Impact: Medium · Effort: Medium

Make "Load more" O(page), not O(total)

Evidence useGrowableLimit.ts implements pagination by re-subscribing with a larger limit — page 10 costs the server a 500-row read and the client a 500-row diff. useInbox.ts (Team Inbox) already demonstrates the target pattern: keyset cursors with accumulate-and-dedupe.

What changes

  • Switch listMessages consumers to cursor args (receivedAt + _id keyset); keep live-query freshness for the first page.
  • Visible payoff: flat "Load more" latency on huge folders, lower bandwidth, fewer re-renders of already-visible rows.
  • Do this after R5 so both label and folder views share one pagination utility.

No mockup — this one is felt, not seen: it's the difference between "Load more" taking 80ms forever versus degrading as the folder grows.

R7

Offline: wider cache, louder status

R7
Phase 3 · Impact: Medium · Effort: Medium–Large

Cached should always say how stale it is

Evidence usePostboxOfflineCache.ts covers the inbox only (v1 scope), and reconnect state is communicated by a subtle shimmer hint in PostboxLayout.vue.

What changes

  • Extend the cache to Snoozed and Starred views — the two other surfaces people open on flaky connections.
  • Replace the shimmer hint with an explicit dated banner while disconnected.
  • Stretch: queue outbound replies while offline (drafts marked "sending when online"), consistent with the existing PostboxUndoSendToast mental model.
R8

Component health — the enabler

R8
Phase 1 · Prerequisite for R1/R2 · Impact: Enabling · Effort: Medium

Split the reader and list before adding to them

Evidence PostboxThreadReader.vue is 1,184 lines and PostboxThreadList.vue is 454 — at or near the repo's file-size ratchet. Both need edits for R1 (responsive restaging) and R2 (header extraction).

What changes

  • Split the reader along its natural seams — the codebase already models this: PostboxMessageBody, PostboxSecurityBadge, attachments lightbox are separate; extract message-header, message-toolbar, and conversation-map logic the same way.
  • Extract PostboxListHeader.vue (title, mode switch, new filter chips) and PostboxBulkToolbar wiring from the list.
  • Pure moves, no behavior change — covered by the existing vitest suites; run npx vitest related per moved chunk.

This is deliberately scheduled first: R1 and R2 are materially cheaper and safer once these files are under the ratchet.

Roadmap

Phase 1 · Weeks 1–2 · Quick wins

Ship the cheap, daily-use improvements

  • R2 filter chips — the highest traffic-to-effort ratio on this list.
  • R4 truthful access states — one query + one component.
  • R5 label query — retires acknowledged debt, unlocks rail counts.
  • R8 begins: reader/list splits land incrementally (pure moves, reviewed separately).
Phase 2 · Weeks 3–6 · The flagship

Mobile Postbox + trustworthy search

  • R1 mobile shell: stack mode, drawer, full-screen reader, touch targets, compose FAB. Behind one breakpoint seam; desktop keyboard model untouched.
  • R3 search: cursor pagination backend, honest counts, guided empty state.
  • Dogfood gate: run a week where the team does morning triage on phones only.
Phase 3 · Weeks 7+ · Depth

Performance floor and resilience

  • R6 keyset pagination across folder + label views (shared utility born in R5).
  • R7 offline: Snoozed/Starred caching, dated offline banner, then the offline-reply queue stretch goal.
  • Polish pass: aria-live announcements for triage actions ("Conversation archived"), audit focus order after the R1 restaging.

07

Guardrails — what not to change

Everything above extends the existing design language. These invariants are load-bearing; regressions here would cost more than the improvements gain.

Keyboard grammar

Single-key triage, ? cheat sheet, focus persistence through live updates. New controls (chips, drawer) must join this grammar, not bypass it.

Optimistic hide + undo

All new triage surfaces (mobile long-press, bulk toolbar) route through the same mutation handlers so undo semantics stay uniform.

Error ≠ empty

R4's fix goes through this principle: access-denied is a third state, distinct from both.

Warm Minimal restraint

New chrome (FAB, banners, chips) uses existing token recipes — brand-subtle fills, border-default hairlines, motion tiers ≤ 240ms. No new colors, no decorative glow.

Personal vs org boundary

Postbox stays deliberately unlinked from audience Contacts; contact linking remains a Team Inbox behavior.

Accessibility baseline

Listbox semantics, aria-hidden skeletons, reduced-motion handling survive every restaging — verify with each split in R8.
