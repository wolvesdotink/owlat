Jeder Teil des Monorepos hat einen klar abgegrenzten Scope. Apps sind deploybare Services, Packages sind gemeinsam genutzte Bibliotheken, die von einer oder mehreren Apps eingebunden werden.

## Apps

| App | Stack | Scope |
| --- | --- | --- |
| `apps/web` | Nuxt 4 + Vue 3 | Haupt-Dashboard für Nutzer — E-Mail-Builder, Kampagnen, Zielgruppenverwaltung, Automationen, Einstellungen |
| `apps/api` | Convex | Serverless-Backend — Datenbank, Authentifizierung (BetterAuth), Echtzeit-Subscriptions, REST-API, Cron-Jobs |
| `apps/mta` | Hono + GroupMQ | Eigener Mail Transfer Agent — direkte SMTP-Zustellung, DKIM-Signierung, IP-Warming, Bounce-Verarbeitung, Rate Limiting |
| `apps/imap` | Node + IMAP | IMAP-Server (Port 993) — übersetzt IMAP4rev1-Befehle in Convex-Queries gegen die Postfächer der einzelnen Nutzer |
| `apps/mail-sync` | Node-Worker | Synchronisiert die externen IMAP-/SMTP-Konten der Nutzer — eingehende Mail nahezu in Echtzeit über IMAP IDLE, Relay für ausgehende Sendungen |
| `apps/code-worker` | Node-Worker | Fragt Convex nach eingereihten Code-Tasks ab und führt sie aus (GitHub Task Runner) |
| `apps/desktop` | Tauri 2 + Rust | Desktop-Shell — bündelt die SPA aus `apps/web`, verbindet sich mit einem oder mehreren Deployments (Multi-Workspace) |
| `apps/setup-cli` | TypeScript (Bun) | Setup-CLI für Self-Hosting — der `owlat quickstart`-Installer, der eine vollständige Instanz deployt |
| `apps/updater` | Node | Update-Worker für Self-Hosting — HTTP-Steuerfläche, die Docker-Compose-Updates zieht und anwendet |
| `apps/docs` | Nuxt + Content | Entwicklerdokumentation — Anleitungen, API-Referenz, Architekturentscheidungen |
| `apps/marketing` | Nuxt | Öffentliche Marketing-Site — Landingpages, Preise, Changelog |

## Packages

| Package | Stack | Scope |
| --- | --- | --- |
| `packages/shared` | TypeScript | Gemeinsame Typen und Daten — Block-Definitionen, Editor-Typen, Kompatibilitätsmatrix der E-Mail-Clients |
| `packages/email-renderer` | TypeScript | Headless-Engine für E-Mail-HTML — tabellenbasierte Layouts, VML für Outlook, CSS-Inlining, Dark Mode, AMP-Format |
| `packages/email-builder` | Vue 3 | Notion-artiger E-Mail-Editor — Dokument-Canvas, Block-Vorschauen, Einstellungs-Popover, Slash-Befehle |
| `packages/email-previewer` | Vue 3 | Vorschau und Analyse — Simulation des Renderings über Clients hinweg, Kompatibilitätsbewertung, E-Mail-Diffs |
| `packages/email-scanner` | TypeScript | Sicherheitsprüfung von E-Mails — Erkennung von Spam-/Phishing-Schlüsselwörtern, Validierung von Magic Bytes in Dateien, ClamAV-Client, URL-Reputation (Safe Browsing) |
| `packages/channels` | TypeScript | Normalisierung eingehender Mail — eine quellenbasierte Registry (`mta`, `resend`, …) auf eine kanonische `InboundEmailMessage` |
| `packages/ui` | Nuxt Layer | Gemeinsame UI-Primitive — Toast-Benachrichtigungen, Error Boundaries, automatisch importierte Composables |
| `packages/plugin-kit` | TypeScript | Öffentliche Plugin-Verträge (npm) — `definePlugin`, Capability-Konstanten, sämtliche Contribution-Interfaces |
| `packages/plugin-host` | TypeScript | Privater Enforcement-Kernel für Plugins — Prüfung von Capabilities/Flags, Reihenfolge, Gate-Ergebnisse, Policy für nicht vertrauenswürdigen Text; wird von Convex und Nuxt gemeinsam genutzt |
| `packages/plugin-codegen` | TypeScript | Build-Werkzeug, dem der einzige Kompositionspunkt für gebündelte Plugins sowie die generierten Kataloge/Registries gehören |
| `packages/plugin-cli` | TypeScript (Bun) | `owlat-plugins` — create/add/remove/codegen/dev über `plugins.config.ts` |
| `packages/sdk-js` | TypeScript | JavaScript-SDK (npm) — Kontakte, transaktionale Sendungen, Events, Topics |
| `packages/sdk-java` | Java | Java-SDK (Maven) — dieselbe API-Oberfläche wie sdk-js für JVM-Konsumenten |

## Wer importiert was

- **web** importiert `email-builder`, `email-previewer`, `email-renderer`, `ui`, `shared` sowie den generierten Convex-Client `@owlat/api` (Echtzeit-Queries & -Mutations)
- **api** importiert `email-renderer`, `email-scanner`, `channels` und `shared`
- **docs** und **marketing** importieren `ui`
- **imap**, **mail-sync** und **code-worker** sind eigenständige Node-Worker — sie sprechen über den Convex-Client mit `api`
- **mta** ist eigenständig — es empfängt HTTP-Requests von `api` und stellt Mail direkt zu
- **sdk-js** und **sdk-java** sind eigenständig — sie sprechen mit der öffentlichen REST-API, die `api` bereitstellt
- **plugin-kit** wird von Plugin-Packages, `plugin-host`, `plugin-codegen`, `api`, `web` und `code-worker` importiert; **plugin-host** wird von `api` und `web` importiert; **plugin-codegen** läuft ausschließlich zur Build-Zeit. Die gebündelten Plugin-Packages selbst sind **ausschließlich** aus generierten Kompositionsdateien erreichbar — siehe das Kapitel [Plugin-Plattform](/developer/plugin-platform)
