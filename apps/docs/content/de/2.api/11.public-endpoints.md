Diese Routen sind öffentlich zugänglich und werden üblicherweise über Links in E-Mails oder eingebettete Formulare aufgerufen.

## Health-Check

- `GET /api/v1/health`

Nicht authentifizierte Liveness-Probe. Antwortet auch, bevor die Bereitstellung
konfiguriert ist, und hängt daher nie von der CORS-Allowlist ab:

```json
{
  "data": { "status": "ok", "timestamp": "2026-01-01T00:00:00.000Z" }
}
```

## Kampagnen-Archiv

- `GET /archive/:token` — liefert den archivierten HTML-Snapshot einer versendeten Kampagne

Öffentlicher Endpunkt für „Im Browser ansehen“-Links. Liefert den Kampagneninhalt so, wie er zum Sendezeitpunkt aussah.

**`200 OK`** — Erfolgs-Bodys verwenden den Action-Mode-Envelope `{ "ok": true, "data": { ... } }`:

```json
{
  "ok": true,
  "data": {
    "html": "<html>...</html>",
    "subject": "Our biggest sale of the year",
    "sentAt": 1741616400000,
    "organizationName": "Acme Inc."
  }
}
```

`sentAt` ist ein Unix-Zeitstempel in Millisekunden (eine Zahl), kein ISO-String.

**`404 Not Found`** — das Token passt zu keiner archivierten Kampagne. Fehlschläge verwenden den festgelegten Fehler-Envelope:

```json
{
  "error": {
    "category": "not_found",
    "message": "Archive not found",
    "data": { "reason": "archive_not_found" }
  }
}
```

Das Archiv-Token ist pro Kampagne eindeutig und im „Im Browser ansehen“-Link der E-Mail enthalten. Archiv-Endpunkte sind rate-limitiert und CORS-fähig. Erfolgreiche Antworten setzen `Cache-Control: public, max-age=3600`.

## Vorschau über Freigabelink

- `GET /share/:token` — liefert den HTML-Snapshot einer freigegebenen Vorschau einer E-Mail-Vorlage

Öffentlicher Endpunkt für ablaufende Freigabelinks, die im E-Mail-Editor erstellt wurden. Liefert den E-Mail-Inhalt so, wie er beim Erstellen des Links aussah. Links laufen nach 48 Stunden ab.

**Antworten:**

- `200 OK` — gültiger Freigabelink. Erfolgs-Bodys verwenden den Action-Mode-Envelope `{ "ok": true, "data": { ... } }`:

```json
{
  "ok": true,
  "data": {
    "html": "<html>...</html>",
    "subject": "Welcome to our product",
    "previewText": "Here's what you need to know",
    "organizationName": "Acme Inc.",
    "expiresAt": 1742486400000
  }
}
```

`expiresAt` ist ein Unix-Zeitstempel in Millisekunden (eine Zahl).

- `404 Not Found` — das Token ist ungültig oder der Link wurde widerrufen. Der festgelegte Fehler-Envelope trägt `category: "not_found"` und `data.reason: "share_link_not_found"`:

```json
{
  "error": {
    "category": "not_found",
    "message": "Share link not found",
    "data": { "reason": "share_link_not_found" }
  }
}
```

- Abgelaufener Link (48-Stunden-Fenster verstrichen) — `data.reason` ist `expired`:

```json
{
  "error": {
    "category": "not_found",
    "message": "This share link has expired",
    "data": { "reason": "expired" }
  }
}
```

::callout{type="info" title="Status bei abgelaufenem Link"}
Der Ablauf-Fall wird auf HTTP `404` (`not_found`) abgebildet, nicht auf `410 Gone` — die Hülle leitet den Status aus der Fehlerkategorie ab und kennt keine Zuordnung zu `410`. Unterscheiden Sie anhand von `data.reason: "expired"` statt anhand des Statuscodes.
::

Das Freigabe-Token ist eine 24 Zeichen lange Zufallszeichenkette. Endpunkte für Freigabelinks setzen `Cache-Control: no-store` (anders als das Archiv, das eine Stunde lang cachebar ist), da der Inhalt abläuft.

## Nicht authentifizierte Token-Endpunkte

Diese tragen weder Sitzung noch Signatur: Das Token in der URL ist die gesamte Berechtigung, und jedes Tor wird pro Anfrage im Handler selbst entschieden.

- `GET /attachment-share/:token` — lädt eine aus einer Nachricht geteilte Datei herunter. Das Token wird auf Widerruf, Ablauf, den Geltungsbereich `anyone` und darauf geprüft, ob die Bytes noch existieren. Jede Token-Ablehnung ist dieselbe `404` im Fehler-Envelope, sodass sich über die Route nicht herausfinden lässt, welche Token echt sind (das Rate-Limit pro IP und Token antwortet mit `429`). Die Antwort wird als Download erzwungen (`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`) und setzt `Cache-Control: no-store, private`.
- `GET /sealed-blob` — der entschlüsselnde Proxy für einen versiegelten Storage-Blob, genutzt vom Postbox-Reader, der IMAP-Bridge und der ausgehenden MTA. Der Query-String trägt ein Capability-Token, das erst geprägt wird, nachdem der Aufrufer an der Query-Stelle autorisiert wurde; hier werden nur Signatur und Ablauf geprüft, ein ungültiges Token ergibt schlicht `403`. Nur Bilder und PDFs werden inline dargestellt, alles andere wird heruntergeladen. Anders als bei den Token-Endpunkten oben ist die CORS-Freigabe auf den App-Origin beschränkt statt auf `*`.
- `POST /unsub/probe/:token` — das Ziel der One-Click-Abmeldung nach RFC 8058, das eine Zustellbarkeits-Seed-Probe mitführt. Das Token ist in einem eigenen Namensraum signiert und kann daher nie gegen den Kontakt-Endpunkt wiederverwendet werden; ein Aufruf vermerkt die Interaktion in der Ledger-Zeile der Probe, statt jemanden abzumelden.

## Eingehende MTA-Callbacks

Diese Routen liegen im selben HTTP-Router, sind aber Server-zu-Server-Callbacks der mitgelieferten MTA- und IMAP-Dienste und keine Browser- oder E-Mail-Link-Abläufe. Sie werden auf Transportebene authentifiziert (Shared Secret / HMAC), allgemeine Clients sollten sie daher nicht aufrufen.

- `POST /webhooks/mta-inbound` — eingehende Zustellung ins Team-Postfach (gemeinsames Agenten-Postfach) vom MTA, mit der Rohnachricht. Siehe [Webhooks](/api/webhooks).
- `POST /webhooks/mta-mailbox` — eingehende Postbox-Zustellung (persönliche E-Mail) vom MTA. Siehe [Postbox-Architektur](/developer/postbox-architecture).
- `POST /webhooks/mta-verify-credential` — Verifizierung von App-Passwörtern für die SMTP-Einlieferung über den MTA und die IMAP/SMTP-Client-Authentifizierung (HMAC-signiert). Siehe [Postbox-Architektur](/developer/postbox-architecture#app-password-auth-flow).
- `POST /mail-sync/raw-message` — Upload der rohen `.eml` durch den Mail-Sync-Worker, authentifiziert über das Shared Secret `MAIL_SYNC_API_KEY` und sicherheitshalber geschlossen, wenn es nicht gesetzt ist. Eine HTTP-Action statt eines Funktionsarguments, weil der Body eines Funktionsaufrufs auf 16 MiB begrenzt ist — dadurch fiel jede Nachricht über rund 12 MiB Quellgröße stillschweigend aus.

Der Callback für Bounce-/Beschwerde-/IP-Zustellereignisse `POST /webhooks/mta` ist auf der Seite [Webhooks](/api/webhooks) dokumentiert.

## Hinweise

- CORS ist überall dort aktiviert, wo es für browserbasierte Abläufe erforderlich ist
- Öffentliche Endpunkte werden pro IP rate-limitiert (empfängerbezogene Token-Endpunkte wie Archiv/Freigabe/Abmeldung werden nach IP+Token geschlüsselt)
- Tokenbasierte Endpunkte liefern für ungültige/abgelaufene Token strukturiertes JSON zurück
