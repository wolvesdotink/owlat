Das offizielle Paket `owlat-sdk` stellt einen typisierten Client bereit, um aus jeder JVM-Anwendung mit der Owlat-API zu arbeiten. Erfordert Java 11+.

## Installation

::code-group

```xml [Maven]
<dependency>
    <groupId>com.owlat</groupId>
    <artifactId>owlat-sdk</artifactId>
    <version>0.1.0</version>
</dependency>
```

```groovy [Gradle]
implementation 'com.owlat:owlat-sdk:0.1.0'
```

::

## Schnellstart

```java
import com.owlat.sdk.Owlat;
import com.owlat.sdk.OwlatConfig;
import com.owlat.sdk.model.contact.Contact;
import com.owlat.sdk.model.contact.CreateContactParams;

Owlat owlat = new Owlat(
    OwlatConfig.builder("lm_live_...")
        .baseUrl("https://rest.api.example.com")
        .build()
);

Contact contact = owlat.contacts().create(
    CreateContactParams.builder("mira@acme.io")
        .firstName("Mira")
        .lastName("Chen")
        .build()
);
```

`baseUrl` ist die API-URL deiner Instanz: Die Web-App zeigt sie als **Deine
API-Basis-URL** unter **Einstellungen → API → API-Schnellstart**. Es ist die
`NUXT_PUBLIC_CONVEX_SITE_URL`, die dein Betreiber gesetzt hat,
`https://rest.api.<deine-domain>`, wenn der Einrichtungsassistent sie aus deiner
Domain abgeleitet hat. Ohne sie schickt der Client Anfragen und deinen API-Key
an `https://api.owlat.app`, also nicht an deine Instanz, und schreibt eine
Warnung über `java.util.logging`. Die Basis-URL wird Pflicht, deshalb ist
`new Owlat(String apiKey)` als veraltet markiert.

Der Builder nimmt außerdem weitere Einstellungen, etwa das Timeout:

```java
import java.time.Duration;

Owlat owlat = new Owlat(
    OwlatConfig.builder("lm_live_...")
        .baseUrl("https://rest.api.example.com")
        .timeout(Duration.ofSeconds(60))
        .build()
);
```

## Ressourcen

### Kontakte

Kontakte in deiner Zielgruppe verwalten.

```java
// Create a contact
Contact contact = owlat.contacts().create(
    CreateContactParams.builder("mira@acme.io")
        .firstName("Mira")
        .lastName("Chen")
        .build()
);

// Get by ID or email
Contact found = owlat.contacts().get("mira@acme.io");

// Update a contact
Contact updated = owlat.contacts().update("mira@acme.io",
    UpdateContactParams.builder()
        .lastName("Chen-Lopez")
        .build()
);

// List with cursor-based pagination
PaginatedResponse<Contact> page = owlat.contacts().list(
    PaginationParams.builder()
        .limit(25)
        .search("jane")
        .build()
);

// Fetch the next page with the returned cursor
if (!page.getPagination().isDone()) {
    PaginatedResponse<Contact> next = owlat.contacts().list(
        PaginationParams.builder()
            .cursor(page.getPagination().getCursor())
            .build()
    );
}

// Or let the SDK follow cursors for you — listAll() returns a lazy
// Stream<Contact> that fetches pages on demand (limit/search honored,
// any supplied cursor ignored), so you never hold the full set in memory
owlat.contacts().listAll().forEach(c -> System.out.println(c.getEmail()));

// Delete a contact
DeleteContactResponse deleted = owlat.contacts().delete("mira@acme.io");
```

### Transaktional

Transaktionale E-Mails mit vorgefertigten Vorlagen versenden.

```java
import com.owlat.sdk.model.transactional.SendTransactionalParams;
import com.owlat.sdk.model.transactional.SendTransactionalResponse;

SendTransactionalResponse result = owlat.transactional().send(
    SendTransactionalParams.builder("buyer@example.com")
        .slug("order-confirmation")
        .dataVariables(Map.of(
            "orderId", "ORD-7291",
            "total", "$142.00"
        ))
        .language("en")
        .build()
);
```

Du kannst die Vorlage über `slug` oder `transactionalId` identifizieren. Mindestens eines von beiden muss angegeben werden.

#### Anhänge

Du kannst Dateien über Base64-kodierten Inhalt oder HTTPS-URLs anhängen:

- Maximal **10 Anhänge** pro E-Mail.
- Maximal **10 MB** (10 MiB, 10.485.760 Bytes) insgesamt, gezählt als dekodierte Bytes von `content`. Dateien, die du per `url` angibst, werden später abgerufen und zählen nicht dazu.
- `content` muss einfaches Base64 ohne Zeilenumbrüche sein. Kodiere mit `Base64.getEncoder()`, nicht mit `Base64.getMimeEncoder()`: Der MIME-Encoder bricht alle 76 Zeichen um, und `build()` lehnt solchen Inhalt mit einer `IllegalArgumentException` ab.

Alle Limits findest du auf der Seite [Transaktionale API](/api/transactional).

```java
import com.owlat.sdk.model.transactional.TransactionalAttachment;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Base64;

byte[] pdfBytes = Files.readAllBytes(Path.of("invoice.pdf"));
// Plain base64 without line breaks: getEncoder(), not getMimeEncoder()
String base64String = Base64.getEncoder().encodeToString(pdfBytes);

SendTransactionalResponse result = owlat.transactional().send(
    SendTransactionalParams.builder("buyer@example.com")
        .slug("order-confirmation")
        .attachment(TransactionalAttachment.builder("invoice.pdf")
            .content(base64String)
            .contentType("application/pdf")
            .build())
        .attachment(TransactionalAttachment.builder("receipt.pdf")
            .url("https://your-api.com/receipts/ORD-7291.pdf")
            .build())
        .build()
);
```

#### Sendestatus

`transactionalEmailId` ist die ID der Sendung. `owlat.transactional().get(id)` liest, wo diese Sendung steht (`queued`, `sent`, `delivered`, `bounced`, `failed`, ...), mit `errorCode` und `errorMessage`, sobald sie fehlgeschlagen ist, und mit `bounceType`, `bounceCause` und der Antwort des empfangenden Servers in `errorMessage`, sobald sie gebounct ist. Jeder `email.*`-Webhook für die Sendung trägt dieselbe ID als `sendId`, sodass dir ein Webhook auf `email.failed` einen Fehlschlag ohne Polling meldet. Siehe [Sendestatus](/api/transactional#sendestatus).

```java
import com.owlat.sdk.model.transactional.TransactionalSendStatus;

TransactionalSendStatus send = owlat.transactional().get(result.getTransactionalEmailId());
if ("failed".equals(send.getStatus())) {
    System.err.println(send.getErrorCode() + ": " + send.getErrorMessage());
}
```

Ohne die ID findet `owlat.transactional().list(params)` die Sendungen nach Empfänger oder nach Status, die neueste zuerst, in höchstens den letzten 30 Tagen. Siehe [Sendungen auflisten](/api/transactional#sendungen-auflisten) und [Eine fehlende E-Mail finden](/api/transactional#eine-fehlende-e-mail-finden).

```java
import com.owlat.sdk.model.CursorPaginatedResponse;
import com.owlat.sdk.model.transactional.ListTransactionalSendsParams;

CursorPaginatedResponse<TransactionalSendStatus> sends = owlat.transactional().list(
    ListTransactionalSendsParams.builder().email("buyer@example.com").build());
```

### Events

Eigene Ereignisse senden, um Automationen auszulösen und Segmente aufzubauen.

```java
import com.owlat.sdk.model.event.SendEventParams;
import com.owlat.sdk.model.event.SendEventResponse;

SendEventResponse result = owlat.events().send(
    SendEventParams.builder("mira@acme.io", "plan_upgraded")
        .eventProperties(Map.of(
            "plan", "pro",
            "mrr", 49
        ))
        .createContactIfNotExists(true)
        .build()
);

// result.getTriggeredAutomations() — number of automations triggered (int)
```

### Themen

Themen auflisten und Themen-Mitgliedschaften verwalten. Das Auflisten braucht
den Scope `topics:read`, das Hinzufügen und Entfernen eines Kontakts
`topics:write`. `getId()` eines Themas ist die Themen-ID, die die
Mitgliedschafts-Aufrufe nehmen.

```java
import com.owlat.sdk.model.PaginatedResponse;
import com.owlat.sdk.model.topic.*;

// Find a topic by name
PaginatedResponse<Topic> page = owlat.topics().list();
Topic updates = page.getData().stream()
    .filter(topic -> topic.getName().equals("Product updates"))
    .findFirst().orElseThrow();

// Add a contact to a topic
AddToTopicResponse added = owlat.topics().addContact(
    AddToTopicParams.builder(updates.getId())
        .email("mira@acme.io")
        .build()
);
// added.getDoiStatus() — NOT_REQUIRED, PENDING, or CONFIRMED

// Remove a contact from a topic
RemoveFromTopicResponse removed = owlat.topics().removeContact(
    new RemoveFromTopicParams(updates.getId(), "mira@acme.io")
);
```

### Status

Lies, ob die Instanz senden kann, und wenn nicht, warum und was es behebt.
Braucht den Scope `status:read`. Die Felder und alle Grund-Codes stehen unter
[Status-API](/api/status).

```java
import com.owlat.sdk.model.status.DeliveryStatus;

DeliveryStatus status = owlat.status().get();
if (!"ok".equals(status.getLevel())) {
    System.out.println(status.getReasonCode() + ": " + status.getExplanation());
    if (status.getFix() != null) System.out.println("Fix it on " + status.getFix().getRoute());
}
// status.getSendingHold() — gesetzt, solange das Senden gesperrt ist, sonst null
```

### Domains

Liste die Absenderdomains mit den DNS-Einträgen, die jede braucht, und mit dem,
was die letzte Prüfung gefunden hat. Braucht den Scope `status:read`. Siehe
[Domains-API](/api/domains).

```java
import com.owlat.sdk.model.domain.*;

for (SendingDomainSetup domain : owlat.domains().list()) {
    for (SendingDomainRecord record : domain.getRecords()) {
        if (!"found".equals(record.getState())) {
            System.out.println(domain.getDomain() + " " + record.getType() + " "
                + record.getHost() + " " + record.getValue() + " " + record.getState());
        }
    }
}
```

Nach dem Veröffentlichen forderst du eine neue Prüfung an und fragst die Liste
ab, bis sie gelaufen ist. Das braucht den Scope `domains:verify`; eine Prüfung
pro Domain und Minute.

```java
DomainCheckRequest check = owlat.domains().verify("news.example.com");
String requestedAt = check.getRequestedAt();
```

### Limits

Lies die transaktionalen Sendelimits, die für diesen Key gelten, und was vom
Tageslimit noch übrig ist. Jeder Key darf seine eigenen lesen. Siehe
[Rate Limits](/api#rate-limits).

```java
import com.owlat.sdk.model.limits.DailySendLimit;

DailySendLimit daily = owlat.limits().get().getDailySends();
if (daily.getRemaining() != null && daily.getRemaining() < batch.size()) {
    System.err.println("Only " + daily.getRemaining() + " sends left until " + daily.getResetsAt());
}
```

Nenne eine Vorlage und eine Adresse, um zu lesen, was vom Limit pro Empfänger
für dieses Paar übrig ist, per Slug oder mit `GetLimitsParams.byTransactionalId`.
Das braucht den Scope `transactional:send`.

```java
import com.owlat.sdk.model.limits.GetLimitsParams;
import com.owlat.sdk.model.limits.RecipientSendUsage;

RecipientSendUsage usage = owlat.limits()
        .get(GetLimitsParams.bySlug("ada@example.com", "password-reset"))
        .getRecipientSends()
        .getUsage();
if (usage.getRemaining() != null && usage.getRemaining() == 0) {
    System.err.println("Try again after " + usage.getResetsAt());
}
```

### Transaktions-E-Mails und gespeicherte Blöcke

Transaktions-E-Mails und gespeicherte Blöcke lesen, schreiben und
veröffentlichen. Lesen braucht den Scope `templates:read`, Schreiben und
Veröffentlichen `templates:write`. Lesen ist der Export: `toInput()` liefert,
was `upsert` nimmt. Siehe [Vorlagen-API](/api/templates).

```java
import com.owlat.sdk.model.template.ContentIssue;
import com.owlat.sdk.model.template.TransactionalEmail;
import com.owlat.sdk.model.template.TransactionalEmailWriteOptions;
import com.owlat.sdk.model.template.TransactionalEmailWriteResult;

TransactionalEmail email = owlat.transactionalEmails().get("order-confirmation");
// Lehnt den Zugriff ab, wenn jemand die E-Mail seit dem Lesen geändert hat.
TransactionalEmailWriteResult result = owlat.transactionalEmails().upsert(
        email.getSlug(), email.toInput(),
        TransactionalEmailWriteOptions.ifRevision(email.getRevision()).whilePublished());
for (ContentIssue issue : result.getIssues()) {
    System.err.println(issue.getBlockId() + ": " + issue.getMessage());
}
owlat.transactionalEmails().publish("order-confirmation");
```

## Fehlerbehandlung

Alle Exceptions erben von `OwlatException` (unchecked) und enthalten den HTTP-Statuscode sowie Informationen zum Rate-Limit.

```java
import com.owlat.sdk.exception.*;

try {
    owlat.transactional().send(
        SendTransactionalParams.builder("user@example.com").slug("welcome").build()
    );
} catch (InvalidStateException e) {
    // 422 — unverified sending domain, blocked recipient, unpublished template.
    // The most common transactional failure mode.
    System.err.println("Cannot send yet: " + e.getMessage());
} catch (ForbiddenException e) {
    // 403 — suspended / abuse-blocked account.
    System.err.println("Not permitted: " + e.getMessage());
} catch (LimitReachedException e) {
    System.err.println("Plan limit reached: " + e.getMessage());
} catch (NotFoundException e) {
    System.err.println("Not found: " + e.getMessage());
} catch (AuthenticationException e) {
    System.err.println("Invalid API key");
} catch (RateLimitException e) {
    System.err.println("Rate limited. Retry after " + e.getRetryAfter() + "s");
} catch (ValidationException e) {
    System.err.println("Invalid request: " + e.getMessage());
} catch (ConflictException e) {
    System.err.println("Conflict: " + e.getMessage());
} catch (UnexpectedResponseException e) {
    // The answer did not come from the Owlat API: check baseUrl.
    System.err.println("Not an Owlat API: " + e.getUrl() + " " + e.getStatusCode() + " " + e.getBodyExcerpt());
} catch (OwlatException e) {
    System.err.println("API error " + e.getStatusCode() + ": " + e.getMessage());
}
```

| Exception-Klasse              | HTTP-Status | Wann                                                                                                                                                                                                                        |
| ----------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AuthenticationException`     | 401         | Ungültiger oder fehlender API-Key                                                                                                                                                                                           |
| `LimitReachedException`       | 402         | Tarif- oder Kontingentgrenze erreicht                                                                                                                                                                                       |
| `ForbiddenException`          | 403         | Authentifiziert, aber nicht berechtigt (gesperrt / wegen Missbrauchs blockiert)                                                                                                                                             |
| `NotFoundException`           | 404         | Ressource existiert nicht                                                                                                                                                                                                   |
| `ConflictException`           | 409         | Doppelte Ressource (z. B. bereits vorhandene E-Mail-Adresse)                                                                                                                                                                |
| `InvalidStateException`       | 422         | Der Zustand der Ressource blockiert die Operation (nicht verifizierte Domain, blockierter Empfänger, nicht veröffentlichte Vorlage)                                                                                         |
| `RateLimitException`          | 429         | Zu viele Anfragen                                                                                                                                                                                                           |
| `ValidationException`         | 400         | Der Request-Body besteht die Validierung nicht                                                                                                                                                                              |
| `UnexpectedResponseException` | jeder       | Die Antwort kommt nicht von der Owlat-API: meist eine falsche Basis-URL oder ein Proxy, der für die Instanz antwortet. `getUrl()` (ohne Query-String), `getStatusCode()` und `getBodyExcerpt()` zeigen, was geantwortet hat |

Jede Exception stellt `getRateLimit()` bereit, das ein `RateLimitInfo` mit `getLimit()`, `getRemaining()` und `getReset()` zurückliefert.

`getReason()` liefert den Code aus `data.reason`, wenn die API einen mitschickt, zum Beispiel `domain_unverified` oder `missing_scope`, sonst `null`. Verzweige darauf statt auf die Nachricht; [Ablehnungsgründe](/api/transactional#ablehnungsgründe) und [Authentifizierung](/api/authentication#häufige-auth-fehler) führen die Codes auf.

## Rate-Limit-Tracking

Rate-Limit-Header werden aus jeder Antwort automatisch geparst. Greif über `getRateLimit()` an jeder Exception darauf zu oder sieh dir die Response-Header direkt an:

| Header                  | Beschreibung                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------- |
| `X-RateLimit-Limit`     | Dauerhaft zulässige Anfragen pro Sekunde für den Key                                      |
| `X-RateLimit-Remaining` | Ein fester Wert: `0` bei einer `429` des Limits pro Key, sonst eins weniger als das Limit |
| `X-RateLimit-Reset`     | Ein Unix-Zeitstempel (Sekunden) eine Sekunde nach der Antwort, kein Auffüllzeitpunkt      |

Regle bei einer `RateLimitException` nach `getRetryAfter()` zurück, nicht nach diesen Werten; [Authentifizierung](/api/authentication#rate-limit-überschritten-429) sagt, was jeder Header enthält.

::callout{type="info" title="Retries und Idempotenz"}
Das Java-SDK wiederholt vorübergehende Fehler automatisch — bis zu **2 Wiederholungen**
(insgesamt 3 Versuche) mit exponentiellem Backoff (500 ms Basis, jeweils verdoppelt).
Ein `429` wird unabhängig von der Methode nach der Wartezeit wiederholt, die er nennt
(`data.retryAfter` im Fehler-Body, sonst der `Retry-After`-Header),
bis 30 s. Bei einer längeren Wartezeit (ein Sendelimit, das sich erst in Minuten auffüllt, oder das
Tageslimit) wird sofort eine `RateLimitException` geworfen; `getRetryAfter()` sagt dir, wann du es
erneut versuchen kannst. Das können Stunden sein, also gib eine lange Wartezeit an eine Job-Queue
ab, statt den Thread so lange schlafen zu lassen. Widersprechen sich `data.retryAfter` im Fehler-Body und der `Retry-After`-Header, gilt der Body,
denn der Header kann von einem Proxy stammen. Einen Bruchteil im Body rundet das SDK auf; einen
Header, der keine positive ganze Zahl von Sekunden ist (etwa ein HTTP-Datum), ignoriert es. Ohne
lesbare Wartezeit wartet es wie bei einem `5xx` und meldet 1 Sekunde. Mehr als 2147483647
Sekunden kürzt es auf diesen Wert. Ein `5xx` oder ein Netzwerk-/Timeout-Fehler wird nur bei
**idempotenten Methoden** (`GET`/`PUT`/`DELETE`) wiederholt.

`POST`-Sendungen — `transactional().send(...)` und `events().send(...)` — werden bei einem `5xx`
oder Netzwerkfehler **nur dann** wiederholt, wenn du `RequestOptions.idempotencyKey(...)` übergibst.
Der Server führt eine Anfrage mit Schlüssel 24 Stunden lang höchstens einmal pro Schlüssel aus und
beantwortet eine Wiederholung mit der ersten Antwort, sodass der Retry nicht doppelt senden kann.
Ohne Schlüssel wird eine Sendung, die der Server vielleicht schon verarbeitet hat, nie erneut
abgespielt; diese Fehler erscheinen als Exceptions, die du selbst behandelst.

```java
owlat.transactional().send(
        SendTransactionalParams.builder("user@example.com").slug("order-confirmation").build(),
        RequestOptions.idempotencyKey("order-" + orderId + "-confirmation"));
```

Ein Schlüssel besteht aus 1 bis 255 druckbaren ASCII-Zeichen ohne Leerzeichen (eine UUID oder
deine eigene Bestellnummer). Verwendest du ihn für eine andere Anfrage erneut, wirft das SDK eine
`ConflictException` (409). Das gilt auch für eine Wiederholung, deren Kontakt nach dem ersten Versuch gelöscht wurde, weil ihre Antwort nicht mehr aufbewahrt wird. Idempotenzschlüssel brauchen einen Owlat-Server, der nach 0.6.16
veröffentlicht wurde: Ein älterer Server ignoriert den Header, und eine wiederholte Sendung könnte
dann doppelt rausgehen.
::

```bash
cd packages/sdk-java
mvn compile
mvn test
```
