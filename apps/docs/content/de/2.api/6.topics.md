---
title: 'Themen-API'
description: 'Themen auflisten und Themen-Mitgliedschaften über authentifizierte Endpunkte verwalten.'
---

Liste die Themen, die Kontakte abonnieren können, und füge einen Kontakt hinzu
oder entferne ihn.

## Authentifizierung

Das Auflisten der Themen braucht einen API-Key mit dem Scope `topics:read`.
Das Hinzufügen und Entfernen eines Kontakts braucht `topics:write`. Übergib den
Key als Bearer-Token:

```http
Authorization: Bearer <key>
```

Anfragen ohne gültigen Key liefern `401`; Anfragen mit einem Key ohne den Scope
der Route liefern `403`.

## Endpunkte

| Methode  | Pfad                                          | Beschreibung                 |
| -------- | --------------------------------------------- | ---------------------------- |
| `GET`    | `/api/v1/topics`                              | Themen auflisten             |
| `POST`   | `/api/v1/topics/:topicId/contacts`            | Kontakt zum Thema hinzufügen |
| `DELETE` | `/api/v1/topics/:topicId/contacts/:emailOrId` | Kontakt aus Thema entfernen  |

## Themen auflisten

```http
GET /api/v1/topics?limit=25&cursor=...
```

Die Themen kommen, die ältesten zuerst, seitenweise wie die
[Kontaktliste](/api/contacts): `limit` (höchstens 100, Standard 25) und der
`pagination.cursor` der vorigen Seite. Themen lassen sich nicht durchsuchen;
auf einen Parameter `search` antwortet die Route mit `400`.

Erfolgsantwort (`200 OK`):

```json
{
	"data": [
		{
			"id": "k57t0pic0000000000000000000000",
			"name": "Product updates",
			"description": "New features and changes, about once a month.",
			"requiresDoubleOptIn": true,
			"createdAt": "2026-01-10T08:00:00.000Z"
		}
	],
	"pagination": { "limit": 25, "totalItems": 1, "cursor": null, "isDone": true }
}
```

`id` ist die `topicId`, die die Mitgliedschafts-Routen unten nehmen.
`requiresDoubleOptIn` sagt, ob das Thema Double-Opt-in verlangt: Ein Kontakt,
dessen Abonnement auf die Double-Opt-in-Bestätigung wartet, zählt als Abonnent,
sobald er seine Adresse bestätigt. `doiStatus` in der Antwort auf das
Hinzufügen nennt den Bestätigungsstand des Kontakts.

## Kontakt zum Thema hinzufügen

```http
POST /api/v1/topics/:topicId/contacts
```

Der Body akzeptiert entweder `email` oder `contactId`:

```json
{
  "email": "jane@example.com"
}
```

oder

```json
{
  "contactId": "j57..."
}
```

Erfolgsantwort (`201 Created`):

```json
{
  "data": {
    "success": true,
    "contactId": "j57...",
    "topicId": "k19...",
    "doiStatus": "pending"
  }
}
```

`doiStatus` kann folgende Werte annehmen:

- `not_required`
- `pending`
- `confirmed`

## Kontakt aus Thema entfernen

```http
DELETE /api/v1/topics/:topicId/contacts/:emailOrId
```

`emailOrId` kann eine URL-kodierte E-Mail-Adresse oder eine Kontakt-ID sein.

Erfolgsantwort (`200 OK`):

```json
{
  "data": {
    "success": true,
    "removed": true
  }
}
```
