Das offizielle Paket `@owlat/sdk-js` stellt einen typisierten Client bereit, um aus Node.js, Bun, Deno oder jeder serverseitigen JavaScript-Laufzeitumgebung mit der Owlat-API zu arbeiten.

## Installation

::code-group

```sh [bun]
bun add @owlat/sdk-js
```

```sh [npm]
npm install @owlat/sdk-js
```

```sh [pnpm]
pnpm add @owlat/sdk-js
```

::

## Schnellstart

```typescript
import { Owlat } from '@owlat/sdk-js';

const owlat = new Owlat({
	apiKey: 'lm_live_...',
	baseUrl: 'https://rest.api.example.com',
});

// Send a transactional email
await owlat.transactional.send({
	email: 'recipient@example.com',
	slug: 'welcome-email',
	dataVariables: { firstName: 'Mira' },
});
```

`baseUrl` ist die API-URL deiner Instanz: Die Web-App zeigt sie als **Deine
API-Basis-URL** unter **Einstellungen → API → API-Schnellstart**. Es ist die
`NUXT_PUBLIC_CONVEX_SITE_URL`, die dein Betreiber gesetzt hat,
`https://rest.api.<deine-domain>`, wenn der Einrichtungsassistent sie aus deiner
Domain abgeleitet hat. Ohne `baseUrl` schickt der Client Anfragen und deinen
API-Key an `https://api.owlat.app`, also nicht an deine Instanz, und gibt eine
Warnung aus. `baseUrl` wird Pflicht.

Das Konfigurationsobjekt nimmt außerdem ein Timeout und Retry-Einstellungen:

```typescript
const owlat = new Owlat({
	apiKey: 'lm_live_...',
	baseUrl: 'https://rest.api.example.com',
	timeout: 30000,
	retry: { maxRetries: 2, initialDelayMs: 500, backoffMultiplier: 2 },
});
```

::callout{type="info" title="Retries und Idempotenz"}
Das SDK wiederholt vorübergehende Fehler automatisch — bis zu **2 Wiederholungen**
(insgesamt 3 Versuche) mit exponentiellem Backoff (500 ms Basis, jeweils verdoppelt).
Ein `429` wird unabhängig von der Methode nach seinem `Retry-After`-Header wiederholt,
bis 30 s. Eine längere Wartezeit (ein Sendelimit, das sich erst in Minuten auffüllt, oder das
Tageslimit) kommt sofort als `RateLimitError` zurück; dessen `retryAfter` sagt dir, wann du es
erneut versuchen kannst. Ein `5xx` oder ein Netzwerk-/Timeout-Fehler wird nur bei **idempotenten
Methoden** (`GET`/`PUT`/`DELETE`) wiederholt.

`POST`-Sendungen — `transactional.send(...)` und `events.send(...)` — werden bei einem `5xx`
oder Netzwerkfehler **nur dann** wiederholt, wenn du einen `idempotencyKey` übergibst. Der Server
führt eine Anfrage mit Schlüssel 24 Stunden lang höchstens einmal pro Schlüssel aus und beantwortet
eine Wiederholung mit der ersten Antwort, sodass der Retry nicht doppelt senden kann. Ohne Schlüssel
wird eine Sendung, die der Server vielleicht schon verarbeitet hat, nie erneut abgespielt; diese
Fehler behandelst du selbst. Übergib `retry: false`, um Wiederholungen vollständig zu deaktivieren,
oder justiere `maxRetries` / `initialDelayMs` / `backoffMultiplier`.

```typescript
await owlat.transactional.send(
	{ email: 'user@example.com', slug: 'order-confirmation' },
	{ idempotencyKey: `order-${orderId}-confirmation` }
);
```

Ein Schlüssel besteht aus 1 bis 255 druckbaren ASCII-Zeichen ohne Leerzeichen (eine UUID oder
deine eigene Bestellnummer). Verwendest du ihn für eine andere Anfrage erneut, wirft das SDK einen
`ConflictError` (409). Das gilt auch für eine Wiederholung, deren Kontakt nach dem ersten Versuch gelöscht wurde, weil ihre Antwort nicht mehr aufbewahrt wird. Idempotenzschlüssel brauchen einen Owlat-Server, der nach 0.6.16
veröffentlicht wurde: Ein älterer Server ignoriert den Header, und eine wiederholte Sendung könnte
dann doppelt rausgehen.
::

## Ressourcen

### Kontakte

Kontakte in deiner Zielgruppe verwalten.

```typescript
// Create a contact
const contact = await owlat.contacts.create({
	email: 'mira@acme.io',
	firstName: 'Mira',
	lastName: 'Chen',
});

// Get a contact by ID
const found = await owlat.contacts.get('contact_abc123');

// Update a contact
const updated = await owlat.contacts.update('contact_abc123', {
	firstName: 'Mira',
	lastName: 'Chen-Lopez',
});

// List contacts with cursor-based pagination
const result = await owlat.contacts.list({ limit: 25 });
// result.data       — Contact[]
// result.pagination  — { limit, totalItems, cursor, isDone }

// Fetch the next page with the returned cursor
if (!result.pagination.isDone) {
	const next = await owlat.contacts.list({ cursor: result.pagination.cursor });
}

// Or iterate every contact automatically (follows cursors until isDone)
for await (const contact of owlat.contacts.listAll()) {
	console.log(contact.email);
}

// Delete a contact
await owlat.contacts.delete('contact_abc123');
```

### Transaktional

Transaktionale E-Mails mit vorgefertigten Vorlagen versenden.

```typescript
const result = await owlat.transactional.send({
	// Identify the template by slug or ID
	slug: 'order-confirmation',

	// Recipient
	email: 'buyer@example.com',

	// Data variables merged into the template
	dataVariables: {
		orderId: 'ORD-7291',
		total: '$142.00',
	},

	// Optional: override language
	language: 'de',
});
// result.status === 'queued'
// result.transactionalEmailId — id of the send, carried as sendId by every email.* webhook
// result.contactId, result.contactCreated, result.language
```

#### Anhänge

Du kannst Dateien über Base64-kodierten Inhalt oder HTTPS-URLs anhängen:

- Maximal **10 Anhänge** pro E-Mail.
- Maximal **10 MB** (10 MiB, 10.485.760 Bytes) insgesamt, gezählt als dekodierte Bytes von `content`. Dateien, die du per `url` angibst, werden später abgerufen und zählen nicht dazu.
- `content` muss einfaches Base64 ohne Zeilenumbrüche sein. MIME-Base64 mit Zeilenumbrüchen alle 76 Zeichen wird mit einem `ValidationError` abgelehnt, bevor etwas gesendet wird.

Alle Limits findest du auf der Seite [Transaktionale API](/api/transactional).

```typescript
// Plain base64 without line breaks (pdfBytes is a Uint8Array or Buffer)
const base64String = Buffer.from(pdfBytes).toString('base64');

await owlat.transactional.send({
	email: 'buyer@example.com',
	slug: 'order-confirmation',
	attachments: [
		// Base64-encoded content
		{
			filename: 'invoice.pdf',
			content: base64String,
			contentType: 'application/pdf',
		},
		// URL (fetched server-side)
		{
			filename: 'receipt.pdf',
			url: 'https://your-api.com/receipts/ORD-7291.pdf',
		},
	],
});
```

#### Sendestatus

`transactionalEmailId` ist die ID der Sendung. `owlat.transactional.get(id)` liest, wo diese Sendung steht (`queued`, `sent`, `delivered`, `bounced`, `failed`, ...), mit `errorCode` und `errorMessage`, sobald sie fehlgeschlagen ist, und mit `bounceType`, `bounceCause` und der Antwort des empfangenden Servers in `errorMessage`, sobald sie gebounct ist. Jeder `email.*`-Webhook für die Sendung trägt dieselbe ID als `sendId`, sodass dir ein Webhook auf `email.failed` einen Fehlschlag ohne Polling meldet. Siehe [Sendestatus](/api/transactional#sendestatus).

```typescript
const { transactionalEmailId } = await owlat.transactional.send({
	email: 'buyer@example.com',
	slug: 'password-reset',
});

const send = await owlat.transactional.get(transactionalEmailId);
if (send.status === 'failed') {
	console.warn(send.errorCode, send.errorMessage); // e.g. MTA_UNREACHABLE
}
```

### Events

Eigene Ereignisse senden, um Automationen auszulösen und Segmente aufzubauen.

```typescript
await owlat.events.send({
	email: 'mira@acme.io',
	eventName: 'plan_upgraded',
	eventProperties: {
		plan: 'pro',
		mrr: 49,
	},
});
```

### Themen

Themen auflisten und Themen-Mitgliedschaften verwalten. Das Auflisten braucht
den Scope `topics:read`, das Hinzufügen und Entfernen eines Kontakts
`topics:write`. Die `id` eines Themas ist die `topicId`, die die
Mitgliedschafts-Aufrufe nehmen.

```typescript
// Find a topic by name
const { data: topics } = await owlat.topics.list();
const updates = topics.find((topic) => topic.name === 'Product updates');

// Add a contact to a topic
await owlat.topics.addContact({
	topicId: 'topic_abc123',
	email: 'mira@acme.io',
});

// Remove a contact from a topic
await owlat.topics.removeContact({
	topicId: 'topic_abc123',
	emailOrId: 'mira@acme.io',
});
```

### Status

Lies, ob die Instanz senden kann, und wenn nicht, warum und was es behebt.
Braucht den Scope `status:read`. Die Felder und alle Grund-Codes stehen unter
[Status-API](/api/status).

```typescript
const status = await owlat.status.get();
if (status.level !== 'ok') {
	console.warn(status.reasonCode, status.explanation);
	console.warn('Fix it on', status.fix?.route, 'as', status.fix?.who);
}
if (status.sendingHold) console.warn('Suspended since', status.sendingHold.since);
```

### Domains

Liste die Absenderdomains mit den DNS-Einträgen, die jede braucht, und mit dem,
was die letzte Prüfung gefunden hat. Braucht den Scope `status:read`. Siehe
[Domains-API](/api/domains).

```typescript
for (const domain of await owlat.domains.list()) {
	for (const record of domain.records.filter((r) => r.state !== 'found')) {
		console.log(domain.domain, record.type, record.host, record.value, record.state);
	}
}
```

## Fehlerbehandlung

Das SDK exportiert typisierte Fehlerklassen für häufige Fehlerfälle:

```typescript
import {
	Owlat,
	OwlatError,
	AuthenticationError,
	RateLimitError,
	NotFoundError,
	ValidationError,
	ConflictError,
	ForbiddenError,
	InvalidStateError,
	LimitReachedError,
	UnexpectedResponseError,
} from '@owlat/sdk-js';

try {
	await owlat.transactional.send({ email: 'user@example.com', slug: 'welcome' });
} catch (error) {
	if (error instanceof ValidationError) {
		console.error('Validation failed:', error.message);
	} else if (error instanceof InvalidStateError) {
		// 422 — unverified sending domain, blocked recipient, unpublished template.
		// The most common transactional failure mode.
		console.error('Cannot send yet:', error.message);
	} else if (error instanceof ForbiddenError) {
		// 403 — suspended / abuse-blocked account.
		console.error('Not permitted:', error.message);
		// Bei gesperrtem Versand: ob die Sperre sich selbst aufhebt, und unter welcher Bedingung.
		if (error.abuseBlocked) console.error('Lifts:', error.abuseBlocked.lift?.mode);
	} else if (error instanceof LimitReachedError) {
		console.error('Plan limit reached:', error.message);
	} else if (error instanceof RateLimitError) {
		console.error('Rate limited — retry after backoff');
	} else if (error instanceof AuthenticationError) {
		console.error('Bad API key');
	} else if (error instanceof ConflictError) {
		console.error('Contact already exists');
	} else if (error instanceof NotFoundError) {
		console.error('Resource not found');
	} else if (error instanceof UnexpectedResponseError) {
		// The answer did not come from the Owlat API: check baseUrl.
		console.error('Not an Owlat API:', error.url, error.statusCode, error.bodyExcerpt);
	} else if (error instanceof OwlatError) {
		console.error('API error:', error.message, error.statusCode);
	}
}
```

| Fehlerklasse              | HTTP-Status | Wann                                                                                                                                                                                     |
| ------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AuthenticationError`     | 401         | Ungültiger oder fehlender API-Key                                                                                                                                                        |
| `LimitReachedError`       | 402         | Tarif- oder Kontingentgrenze erreicht                                                                                                                                                    |
| `ForbiddenError`          | 403         | Authentifiziert, aber nicht berechtigt (gesperrt / wegen Missbrauchs blockiert)                                                                                                          |
| `NotFoundError`           | 404         | Ressource existiert nicht                                                                                                                                                                |
| `ConflictError`           | 409         | Doppelte Ressource (z. B. bereits vorhandene E-Mail-Adresse)                                                                                                                             |
| `InvalidStateError`       | 422         | Der Zustand der Ressource blockiert die Operation (nicht verifizierte Domain, blockierter Empfänger, nicht veröffentlichte Vorlage)                                                      |
| `RateLimitError`          | 429         | Zu viele Anfragen                                                                                                                                                                        |
| `ValidationError`         | 400         | Der Request-Body besteht die Validierung nicht                                                                                                                                           |
| `UnexpectedResponseError` | jeder       | Die Antwort kommt nicht von der Owlat-API: meist eine falsche `baseUrl` oder ein Proxy, der für die Instanz antwortet. Enthält `url` (ohne Query-String), `statusCode` und `bodyExcerpt` |

Jeder Fehler hat außerdem `reason`, den Code aus `data.reason`, wenn die API einen mitschickt (zum Beispiel `domain_unverified`), typisiert als `ApiErrorReason`. Verzweige darauf statt auf die Nachricht; [Ablehnungsgründe](/api/transactional#ablehnungsgründe) sagt, was jeder transaktionale Grund bedeutet.
