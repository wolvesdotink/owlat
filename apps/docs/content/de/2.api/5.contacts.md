Kontakte Ihrer Organisation verwalten.

## Endpunkte

| Methode | Pfad                  | Beschreibung                          |
| ------ | --------------------- | ------------------------------ |
| `GET`  | `/api/v1/contacts`    | Kontakte auflisten                  |
| `POST` | `/api/v1/contacts`    | Kontakt anlegen                 |
| `GET`  | `/api/v1/contacts/:id`| Abruf über Kontakt-ID oder E-Mail     |
| `PUT`  | `/api/v1/contacts/:id`| Aktualisierung über Kontakt-ID oder E-Mail  |
| `DELETE`| `/api/v1/contacts/:id`| Löschung über Kontakt-ID oder E-Mail |

## Kontakte auflisten

Kontakte werden **Cursor-paginiert**. Es gibt keine Zeilenobergrenze — jeder Kontakt ist
erreichbar, und Suchergebnisse erstrecken sich tatsächlich über mehrere Seiten (nach Relevanz sortiert).

```http
GET /api/v1/contacts?limit=25&search=jane
```

Query-Parameter:

- `limit` (max. `100`, Standard `25`)
- `cursor` — opaker Fortsetzungs-Cursor aus dem Feld `pagination.cursor` der
  vorherigen Antwort. Lassen Sie ihn weg, um die erste Seite abzurufen.
- `search`

Antwort:

```json
{
  "data": [ /* …contacts… */ ],
  "pagination": {
    "limit": 25,
    "totalItems": 1342,
    "cursor": "opaque-cursor-string",
    "isDone": false
  }
}
```

Um alle Seiten zu durchlaufen, rufen Sie den Endpunkt wiederholt mit `cursor` auf, gesetzt auf das
`pagination.cursor` der vorherigen Antwort, bis `pagination.isDone` den Wert `true` hat (ab da ist `cursor`
gleich `null`).

## Kontakt anlegen

```http
POST /api/v1/contacts
```

Body:

```json
{
  "email": "jane@example.com",
  "firstName": "Jane",
  "lastName": "Smith"
}
```

Liefert `201` mit dem angelegten Kontakt zurück.

## Kontakt abrufen

`id` kann entweder sein:

- eine Convex-Kontakt-ID
- eine URL-kodierte E-Mail-Adresse (zum Beispiel `jane%40example.com`)

## Kontakt aktualisieren

```http
PUT /api/v1/contacts/:id
```

Teilweise Aktualisierungen werden unterstützt.

## Kontakt löschen

```http
DELETE /api/v1/contacts/:id
```

::callout{type="info" title="Eigene Eigenschaften"}
Eigene Kontakteigenschaften (etwa `language`, `timezone` sowie selbst definierte Felder) werden über das Dashboard verwaltet. Die REST-API verarbeitet derzeit ausschließlich die zentralen Kontaktfelder (`email`, `firstName`, `lastName`, `source`, `createdAt`, `updatedAt`).
::
