Lies und ändere das [Markenkit](/guide/email-theme): die Farben, Schriften,
den Button-Stil und die Fußzeile, mit denen jede E-Mail beginnt. Ein Skript
oder ein KI-Agent, der Vorlagen baut, kann so die Webschrift einschalten, die
ein Design verwendet, oder den Firmennamen und die Postanschrift eintragen, die
in der Fußzeile jeder Marketing-E-Mail stehen, ohne die Web-App zu öffnen.

## Authentifizierung

Lesen braucht einen API-Schlüssel mit dem Scope `brand-kit:read`, Ändern
`brand-kit:write`. Die Vorlagen-Scopes gewähren keinen von beiden. Ein
Schlüssel, den du angelegt hast, bevor es diese Scopes gab, hat sie nicht: Leg
unter **Einstellungen → API** einen Schlüssel mit den nötigen Scopes an.

## Endpunkte

| Methode | Pfad                | Zweck                                  |
| ------- | ------------------- | -------------------------------------- |
| `GET`   | `/api/v1/brand-kit` | Das Markenkit lesen                    |
| `PUT`   | `/api/v1/brand-kit` | Einzelne oder alle seine Felder ändern |

## Das Markenkit

```json
{
	"data": {
		"isConfigured": true,
		"primaryColor": "#0f766e",
		"secondaryColor": "#282d3a",
		"textColor": "#374151",
		"backgroundColor": "#ffffff",
		"linkColor": "#0f766e",
		"swatches": ["#f59e0b"],
		"headingFontFamily": "'Montserrat', Arial, sans-serif",
		"bodyFontFamily": "'Inter', Arial, sans-serif",
		"buttonRadius": 6,
		"buttonPaddingX": 24,
		"buttonPaddingY": 12,
		"baseWidth": 600,
		"footerCompanyName": "Example Shop GmbH",
		"footerAddress": "1 Example Street\n12345 Example City",
		"footerSocialLinks": [{ "platform": "github", "url": "https://github.com/example" }],
		"logo": { "url": "https://files.owlat.example/logo.png", "width": 160 },
		"logoDark": null
	}
}
```

`isConfigured` ist `false`, bis das Markenkit einmal gespeichert wurde, auf der
Markenkit-Seite oder über die API. Bis dahin hat jedes Feld seinen
Standardwert.

## Ändern

Schick nur die Felder, die sich ändern sollen. Ein weggelassenes Feld behält
seinen gespeicherten Wert, und die Antwort ist das ganze Markenkit nach dem
Schreiben, in der Form oben. Ein Body ohne Feld ändert nichts und antwortet
mit dem Markenkit, wie es ist.

```sh
curl -X PUT "$OWLAT_API/api/v1/brand-kit" \
  -H "Authorization: Bearer $OWLAT_KEY" \
  -H 'Content-Type: application/json' \
  --data @brand-kit.json
```

```json
{
	"headingFontFamily": "'Montserrat', Arial, sans-serif",
	"footerCompanyName": "Example Shop GmbH",
	"footerAddress": "1 Example Street\n12345 Example City"
}
```

Die Werte werden geprüft wie auf der Markenkit-Seite:

- Farben sind Hex-Farben, `#rgb` oder `#rrggbb`. Es gibt höchstens sechs
  `swatches`.
- `headingFontFamily` und `bodyFontFamily` sind einer der Schrift-Stacks, die
  die Markenkit-Seite anbietet, genau so geschrieben; das OpenAPI-Dokument
  listet sie. Die Webschriften darunter laden von Google Fonts in Clients, die
  entfernte Schriften laden, und zeigen anderswo, etwa in Gmail und Outlook,
  die Ersatzschrift, die nach ihnen steht.
- Button-Radius 0 bis 40 px, Innenabstand 4 bis 64 px quer und 4 bis 32 px
  hoch, Breite 400 bis 800 px.
- Der Firmenname hat höchstens 120 Zeichen, die Anschrift 300. Es gibt
  höchstens acht Social-Links, jeder eine absolute http(s)-URL.

Ein abgelehnter Wert ist ein `400` mit `invalid_input`, das das Feld in
`data.field` nennt, etwa `linkColor`, `swatches.2` oder
`footerSocialLinks.0.url`. Gespeichert wird dann nichts.

Anders als bei den anderen Routen wird ein Feld, das die API nicht kennt,
abgelehnt statt ignoriert, damit ein vertipptes Feld nicht wie eine gelungene
Änderung aussieht. Auch die Logos werden abgelehnt (`logo`, `logoDark`): Sie
sind Dateien in der Mediathek, und nur die Markenkit-Seite kann sie setzen. Ein
Schreiben behält die gespeicherten Logos.

Ein Schreiben mit mindestens einem Feld markiert das Markenkit als eingerichtet, wie das Speichern der
Markenkit-Seite. Wie dort gestaltet eine Änderung die Blöcke bestehender
E-Mails nicht um; siehe
[wie das Markenkit mit bestehenden E-Mails zusammenspielt](/guide/email-theme#wie-das-markenkit-mit-bestehenden-e-mails-zusammenspielt).

## Grenzen und Ablehnungen

Schreiben teilt sich das Limit pro Schlüssel mit den
[Vorlagen-Schreibzugriffen](/api/templates#grenzen): 60 pro Minute, mit Spitzen
bis 30.

| Status | `data.reason`                    | Bedeutung                                              |
| ------ | -------------------------------- | ------------------------------------------------------ |
| `400`  |                                  | Ein Feld wurde abgelehnt; `data.field` nennt es        |
| `403`  | `missing_scope`                  | Dem Schlüssel fehlt der Scope; `data.scope` nennt ihn  |
| `422`  | `workspace_deletion_in_progress` | Der Workspace wird gerade gelöscht                     |
| `429`  | `template_write_rate_limited`    | Zu viele Vorlagen-Schreibzugriffe mit diesem Schlüssel |
