Kontaktereignisse senden, um Segmentierung und Automations-Trigger zu steuern.

## Endpunkt

| Methode | Pfad             |
| ------- | ---------------- |
| `POST`  | `/api/v1/events` |

## Authentifizierung

Dieser Endpunkt erfordert einen API-Key mit dem Scope `events:write`, übergeben als Bearer-Token:

```http
Authorization: Bearer <key>
```

Anfragen ohne gültigen Key liefern `401`; Anfragen mit einem Key ohne den Scope `events:write` liefern `403`. Der Endpunkt ist auf 10 Anfragen pro Sekunde begrenzt; darüber hinaus liefert er `429`.

## Request-Body

```json
{
	"email": "john@example.com",
	"eventName": "purchase_completed",
	"eventProperties": {
		"orderId": "ORD-123",
		"amount": 99.99
	},
	"createContactIfNotExists": true
}
```

Felder:

- `email` (erforderlich)
- `eventName` (erforderlich)
- `eventProperties` (optionales flaches Objekt; jeder Wert ist ein String, eine Zahl, ein Boolean oder `null`)
- `createContactIfNotExists` (optionaler Boolean, Standard `false`)

Einschränkungen für `eventName`:

- muss mit einem Buchstaben beginnen
- erlaubte Zeichen: Buchstaben, Ziffern, `_`, `-`
- maximale Länge: 100

## Erfolgsantwort

Liefert `201` mit dem Ergebnis des Ereignisses:

```json
{
	"data": {
		"eventId": "evt_m6e...",
		"contactId": "j57...",
		"eventName": "purchase_completed",
		"triggeredAutomations": 1,
		"contactCreated": true
	}
}
```

## Idempotente Wiederholungen

Sende einen `Idempotency-Key`-Header, damit du ein Ereignis nach einem Timeout oder einem `5xx`
gefahrlos wiederholen kannst:

```http
Idempotency-Key: 3f0c1d9e-6c2b-4a51-9a3e-2f6d1b7c8e90
```

- Der Schlüssel besteht aus 1 bis 255 druckbaren ASCII-Zeichen ohne Leerzeichen, etwa einer UUID
  oder deiner eigenen Ereignis-ID. Er gilt für deine Organisation.
- Die erste Anfrage mit einem Schlüssel wird normal verarbeitet. Eine Wiederholung **derselben**
  Anfrage mit diesem Schlüssel innerhalb von 24 Stunden legt keinen Kontakt an und startet keine Automatisierung, liefert die erste Antwort
  (gleicher Status und Body) und trägt den Header `Idempotent-Replayed: true`.
- Verwendest du den Schlüssel für eine **andere** Anfrage (anderer Body oder anderer Endpunkt),
  wird sie mit `409` `conflict` (`reason: "idempotency_conflict"`) abgelehnt und bewirkt nichts.
- Wurde der Kontakt, den die erste Anfrage betraf, inzwischen gelöscht, wird eine Wiederholung
  innerhalb der 24 Stunden mit `409` `conflict` (`reason: "idempotency_erased"`) abgelehnt und
  bewirkt nichts: Die Anfrage wurde schon ausgeführt, aber ihre Antwort nannte die gelöschte Person
  und wird nicht mehr aufbewahrt.
- Eine abgelehnte Anfrage (zum Beispiel `404` oder `400`) oder eine, die vor dem Ausführen
  fehlschlug, speichert nichts; eine Wiederholung mit demselben Schlüssel führt sie erneut aus.
- Nach 24 Stunden kannst du den Schlüssel für eine neue Anfrage verwenden.
- Ohne den Header wird wie bisher jede Anfrage verarbeitet.

## Häufige Fehler

Fehler verwenden den Standard-Envelope `{ "error": { "category", "message", "data"? } }`:

- `404` `not_found` — der Kontakt existiert nicht und `createContactIfNotExists` ist nicht aktiviert
- `400` `invalid_input` — ungültiger Ereignisname, fehlendes Pflichtfeld oder fehlerhafter JSON-Body
- `401` — fehlender oder ungültiger API-Key
- `403` — dem Key fehlt der Scope `events:write`
- `409` `conflict` — der `Idempotency-Key` wurde schon für eine andere Anfrage verwendet (`idempotency_conflict`), oder seine Anfrage lief schon für einen inzwischen gelöschten Kontakt (`idempotency_erased`)
- `429` — mehr als 10 Anfragen pro Sekunde
