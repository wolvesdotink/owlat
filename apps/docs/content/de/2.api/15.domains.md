---
title: 'Domains-API'
description: 'Liste die Absenderdomains und die DNS-Einträge, die jede noch braucht.'
---

Liste deine Absenderdomains mit ihrem Prüfstatus und jedem DNS-Eintrag, den
jede braucht: wo er hingehört, sein Wert und was die letzte Prüfung dort
gefunden hat. Ein Skript oder ein KI-Agent, der die Absender-Einrichtung
abschließt, liest so, was noch fehlt, ohne die Web-App zu öffnen.

## Endpunkt

| Methode | Pfad              | Zweck                                           |
| ------- | ----------------- | ----------------------------------------------- |
| `GET`   | `/api/v1/domains` | Absenderdomains und ihre DNS-Einträge auflisten |

## Authentifizierung

Die Route braucht einen API-Schlüssel mit dem Scope `status:read`, demselben
wie die [Status-API](/api/status), die den Prüfstatus jeder Domain nennt. Ein
Schlüssel ohne ihn bekommt `403` mit `data.reason` `missing_scope`. Jedes
Mitglied deines Workspaces sieht dieselben Einträge auf der Seite der
Absenderdomains; Anbieter-Tokens und gespeicherte Fehlermeldungen gehören nicht
zur Antwort.

## Antwort

```json
{
	"data": [
		{
			"id": "k57d0main0000000000000000000000",
			"domain": "news.example.com",
			"status": "failed",
			"lastCheckedAt": "2026-11-21T07:30:00.000Z",
			"records": [
				{
					"purpose": "dkim",
					"type": "CNAME",
					"host": "s1._domainkey.news.example.com",
					"value": "s1.dkim.owlat.example",
					"priority": null,
					"state": "wrong",
					"foundValue": "old.dkim.example.net"
				},
				{
					"purpose": "dmarc",
					"type": "TXT",
					"host": "_dmarc.news.example.com",
					"value": "v=DMARC1; p=none",
					"priority": null,
					"state": "missing",
					"foundValue": null
				}
			]
		}
	]
}
```

- `status` ist `registering`, `pending`, `verified` oder `failed`. Nur eine
  verifizierte Domain kann senden.
- `records` listet jeden zu veröffentlichenden Eintrag: `spf`, jeden
  `dkim`-Schlüssel, `dmarc` und `mail_from` für den Return-Path-Host, der die
  Bounces empfängt. Die Liste ist leer, solange die Domain noch registriert
  wird.
- `host` ist der volle Name des Eintrags. Ein `mail_from`-Eintrag kann auf
  einer Return-Path-Domain außerhalb deiner Domain liegen; veröffentliche ihn
  dort, wo `host` es sagt.
- `priority` ist bei einem `MX`-Eintrag gesetzt, sonst `null`.
- `state` ist, was die letzte Prüfung gefunden hat: `found` mit dem erwarteten
  Wert, `wrong` (dort steht ein anderer Wert, zu sehen in `foundValue`),
  `missing` oder `unchecked` (noch keine Prüfung, oder DNS hat nicht
  geantwortet).

Die Liste ist nicht seitenweise: Eine Instanz hat eine Handvoll
Absenderdomains.

## Wann sich die Zustände ändern

Die Zustände stammen aus der letzten Prüfung, zu sehen in `lastCheckedAt`
(`null` vor der ersten). Owlat prüft jede Domain, die einmal verifiziert war,
täglich neu. Eine Domain, die noch eingerichtet wird, wird erneut geprüft,
solange ihre Zeile auf der Seite der Absenderdomains aufgeklappt ist. Klapp sie
nach dem Veröffentlichen also dort auf oder klicke auf **Prüfen**; die API
startet keine Prüfung.
