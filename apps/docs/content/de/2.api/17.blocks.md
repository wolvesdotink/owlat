E-Mail-Vorlagen, Transaktions-E-Mails und gespeicherte Blöcke speichern ihren
Inhalt als JSON-Array von Blöcken, in der Reihenfolge, in der sie gerendert
werden. Diese Seite beschreibt dieses JSON für alle, die es ohne den Editor
schreiben: eine Integration, ein Skript oder einen KI-Agenten.

## Das Schema

Jede Instanz liefert das JSON-Schema (2020-12) des Block-Inhalts ohne
API-Schlüssel, neben ihrem [OpenAPI-Dokument](/api#openapi-dokument):

```txt
GET <deine API-Basis-URL>/api/v1/schemas/blocks.json
```

Dieselbe Datei liegt für das aktuelle Release unter
[docs.owlat.app/schemas/blocks.json](https://docs.owlat.app/schemas/blocks.json).
Prüfe Blöcke dagegen, bevor du sie schreibst. Es hat einen `$defs`-Eintrag pro
Blocktyp, gewählt über das `type` des Blocks, mit dem Typ jedes Felds, den
Pflichtfeldern, den erlaubten Werten und einem ausgearbeiteten Beispiel. Das
Schema lehnt Felder ab, die ein Block nicht kennt: Ein vertipptes Feld fällt
bei der Prüfung auf, statt gespeichert und ignoriert zu werden.

## Ein Block

```json
{
	"id": "greeting",
	"type": "text",
	"content": {
		"html": "<p>Hi {{first_name|'there'}}.</p>",
		"blockType": "paragraph",
		"fontSize": 16,
		"textColor": "#1f2937"
	}
}
```

- `id` ist innerhalb der E-Mail eindeutig. Übersetzungen und Verknüpfungen zu
  gespeicherten Blöcken verweisen darüber auf Blöcke, also lass sie stabil,
  wenn du eine E-Mail neu schreibst.
- `type` ist einer der Blocktypen unten und legt fest, was `content` enthält.
- `savedBlockRef` steht an den Blöcken eines verknüpften gespeicherten Blocks.
  Eine Änderung am gespeicherten Block ersetzt sie.

Größen sind Zahlen in Pixeln, wenn das Feld nichts anderes sagt. Die `width`
eines Bilds, eines Videos und einer Trennlinie ist ein Prozentwert (1 bis 100)
des Platzes, in dem der Block steht. Farben sind CSS-Farben. Ein Schreibvorgang
macht aus einem Zahlen-String wie `"16"` eine Zahl und verwirft jeden anderen
Nicht-Zahlenwert, das Schema erwartet aber Zahlen.

## Verschachtelung

Die meisten Blöcke stehen nur auf oberster Ebene. Drei Stellen enthalten
andere Blöcke:

- **Eine Spalte** eines `columns`-Blocks enthält `text`-, `image`-,
  `button`-, `divider`- und `spacer`-Blöcke (`ColumnItem`).
- **Ein Container**, die `items` eines `hero` und jeder Abschnitt eines
  `accordion` enthalten diese fünf und dazu `columns`-, `social`- und
  `container`-Blöcke (`ContainerItem`).
- Container lassen sich ineinander verschachteln. Es gibt keine feste Grenze;
  die Validierung warnt ab drei Ebenen.

Ein Block eines anderen Typs an einer dieser Stellen wird vom Schema abgelehnt
und beim Rendern übersprungen.

## Spaltenbreiten

Ein `columns`-Block hat 1 bis 5 Spalten (`columnCount`). Ihre Breiten kommen
aus `ratio`, einer von fünf Vorgaben, oder aus `columnWidths`: ganze
Prozentwerte, einer pro Spalte, jeder mindestens 10, zusammen genau 100.
Gültige `columnWidths` haben Vorrang vor `ratio`. Eine einzelne Spalte nimmt
immer die volle Breite. `columns` enthält ein Array von Blöcken pro Spalte,
Einträge über `columnCount` hinaus werden ignoriert.

<!-- block-reference:column-widths -->

| Verhältnis     | 2 Spalten | 3 Spalten                | 4 Spalten                      |
| -------------- | --------- | ------------------------ | ------------------------------ |
| `equal`        | 50% · 50% | 33.33% · 33.33% · 33.33% | 25% · 25% · 25% · 25%          |
| `left-wide`    | 67% · 33% | 50% · 25% · 25%          | 40% · 20% · 20% · 20%          |
| `right-wide`   | 33% · 67% | 25% · 25% · 50%          | 20% · 20% · 20% · 40%          |
| `left-narrow`  | 33% · 67% | 25% · 37.5% · 37.5%      | 15% · 28.33% · 28.33% · 28.33% |
| `right-narrow` | 67% · 33% | 37.5% · 37.5% · 25%      | 28.33% · 28.33% · 28.33% · 15% |

<!-- /block-reference:column-widths -->

## Variablen

Ein Textfeld kann Variablen enthalten, die beim Versand gefüllt werden:

```txt
{{first_name}}
{{first_name|'there'}}
```

- Ein Name besteht aus Buchstaben, Ziffern und Unterstrichen: keine
  Leerzeichen, Punkte oder Verschachtelung.
- Die zweite Form hat einen Fallback in einfachen Anführungszeichen, der greift,
  wenn der Wert fehlt oder leer ist. Der Fallback darf kein einfaches
  Anführungszeichen enthalten.
- Ohne Fallback wird eine fehlende Variable zum leeren String. Ein
  Transaktionsversand lehnt eine Anfrage ab, der eine Variable fehlt, die die
  E-Mail ohne Fallback nutzt, außer die E-Mail markiert sie als optional.
- Werte und Fallbacks werden HTML-escaped, wenn sie in den E-Mail-Text kommen,
  ein Wert kann also kein Markup einfügen. Im Betreff werden Zeilenumbrüche zu
  Leerzeichen.
- Variablen funktionieren im `html` eines Textblocks und in anderem Text, der
  in der E-Mail landet, etwa im `text` und in der `url` eines Buttons oder im
  `alt` und in der `src` eines Bilds.

Für eine Transaktions-E-Mail sind die Werte die `dataVariables` des Versands
(siehe die [Transaktions-API](/api/transactional)). Für eine Vorlage sind es
die Felder des Kontakts.

## Bedingungen und Wiederholungen

Ein Block auf oberster Ebene kann eine `condition` tragen, die ihn nur zeigt,
wenn eine Variable passt, und ein `repeat`, das ihn einmal pro Eintrag einer
Array-Variable rendert. In einem `repeat` ist `{{item.name}}` der `name` des
aktuellen Eintrags (mit `itemAlias` auf `item`) und `{{$index}}` seine
Position, ab 0. Verschachtelte Blöcke, etwa die Blöcke in einer Spalte,
ignorieren beide Felder.

```json
{
	"condition": { "variable": "coupon_code", "operator": "exists" },
	"repeat": { "variable": "items", "itemAlias": "item", "maxItems": 20 }
}
```

Wann sie aufgelöst werden, hängt von der Art der E-Mail ab.

In einer Transaktions-E-Mail werden sie bei jedem Versand aufgelöst, gegen die
`dataVariables` der Anfrage, im HTML-Teil wie im Text-Teil (text/plain). Ein
`repeat` liest eine Listenvariable (Typ `array` im `dataVariablesSchema`): bis
zu 500 Einträge, jeder ein einfacher Wert oder ein flaches Objekt aus einfachen
Werten. Eine Liste, die die E-Mail wiederholt, muss mitgeschickt werden, außer
die E-Mail markiert sie als optional. Eine Variable, die nur in einem Block
vorkommt, den seine Bedingung ausblendet, ist nicht erforderlich. Siehe
[Transaktions-E-Mails](/guide/transactional).

In einer Marketing-Vorlage werden sie beim Speichern der Vorlage aufgelöst. Das
gespeicherte HTML wird ohne Variablenwerte gerendert, in diesem Moment ist also
jede Variable leer:

- ein Block mit einer `exists`-, `equals`- oder `contains`-Bedingung fehlt in
  der E-Mail, einer mit `notExists` oder mit `notEquals` gegen einen Wert
  bleibt;
- ein Block mit `repeat` fehlt, weil seine Array-Variable keine Einträge hat.

Der erzeugte Text-Teil (text/plain) einer Vorlage ignoriert `condition` und
`repeat`: Jeder Block liefert seinen üblichen Text höchstens einmal, egal
welche Bedingung er hat, und die `{{item.…}}`- und `{{$index}}`-Platzhalter
eines wiederholten Blocks bleiben wie geschrieben. Variablen in den Blöcken,
die bleiben, werden weiterhin pro Versand gefüllt. In einer Vorlage kann sich
Inhalt, der je nach den Daten des Kontakts erscheinen oder sich wiederholen
soll, nicht auf eine Bedingung oder ein `repeat` stützen.

## Übersetzungen

Eine Übersetzung speichert nur den übersetzbaren Text eines Blocks. Über die
`id` des Blocks: das `html` eines Textblocks, den `text` eines Buttons, das
`alt` eines Bilds und den Titel jedes Akkordeon-Abschnitts. Die Einträge einer
Liste, der Text einer Tabelle (Kopfzeilen, Zellen, Fußzeile und Beschriftung)
und die Beschriftungen eines Menüs werden über ihren Text in der
Standardsprache zugeordnet. Eine Übersetzung folgt also ihrem Eintrag, wenn die
Reihenfolge wechselt, und ein Eintrag, dessen Text sich ändert, zeigt den
Standardtext, bis er neu übersetzt ist. Links und Bilddateien sind in jeder
Sprache gleich. Alles andere kommt aus den Blöcken der Standardsprache. Siehe
[Übersetzungen](/guide/translations).

## HTML in einem Textblock

Ein Schreibvorgang bereinigt das `html` eines Textblocks für die Speicherung. Tags, Attribute,
URL-Schemata und CSS-Eigenschaften außerhalb der Listen unten werden entfernt,
und eine Stilangabe bleibt nur, wenn ihr Wert auf das dafür genannte Muster
passt. Ein Variablen-Chip (ein `<span>` mit `data-variable`) behält
`contenteditable` nur als `"false"`.

<!-- block-reference:text-html -->

Erlaubte Tags: `<h1>`, `<h2>`, `<h3>`, `<h4>`, `<h5>`, `<h6>`, `<p>`, `<br>`, `<hr>`, `<span>`, `<div>`, `<section>`, `<article>`, `<header>`, `<footer>`, `<b>`, `<i>`, `<u>`, `<em>`, `<strong>`, `<small>`, `<sub>`, `<sup>`, `<mark>`, `<a>`, `<ul>`, `<ol>`, `<li>`, `<blockquote>`, `<pre>`, `<code>`, `<figure>`, `<figcaption>`, `<table>`, `<thead>`, `<tbody>`, `<tfoot>`, `<tr>`, `<td>`, `<th>`, `<img>`, `<picture>`, `<source>`, `<s>`, `<strike>`

| Tag                | Attribute                                                             |
| ------------------ | --------------------------------------------------------------------- |
| jedes erlaubte Tag | `style`, `class`, `id`, `lang`, `dir`                                 |
| `<a>`              | `href`, `title`, `name`, `target`, `rel`                              |
| `<img>`            | `src`, `srcset`, `alt`, `width`, `height`, `loading`                  |
| `<source>`         | `srcset`, `media`, `type`                                             |
| `<span>`           | `data-variable`, `contenteditable`                                    |
| `<table>`          | `width`, `cellspacing`, `cellpadding`, `border`, `align`, `bgcolor`   |
| `<td>`             | `colspan`, `rowspan`, `align`, `valign`, `bgcolor`, `width`, `height` |
| `<th>`             | `colspan`, `rowspan`, `align`, `valign`, `bgcolor`, `width`, `height` |
| `<tr>`             | `align`, `valign`, `bgcolor`                                          |

URLs in `href`, `src` und `srcset` dürfen `http`, `https`, `mailto`, `tel` nutzen. Auf `<img>` stattdessen `http`, `https`, `cid`. Auf `<source>` stattdessen `http`, `https`, `cid`.

| Eigenschaft        | Wert muss passen auf                                    |
| ------------------ | ------------------------------------------------------- |
| `color`            | `/^.+$/`                                                |
| `background-color` | `/^.+$/`                                                |
| `font-size`        | `/^[\d.]+(px\|pt\|em\|rem\|%)$/i`                       |
| `font-family`      | `/^[A-Za-z0-9 ,"'\-_]+$/`                               |
| `font-weight`      | `/^(normal\|bold\|bolder\|lighter\|[1-9]00)$/i`         |
| `font-style`       | `/^(normal\|italic\|oblique)$/i`                        |
| `text-align`       | `/^(left\|right\|center\|justify\|start\|end)$/i`       |
| `text-decoration`  | `/^(none\|underline\|overline\|line-through)( \w+)*$/i` |
| `line-height`      | `/^[\d.]+(px\|pt\|em\|rem\|%)?$/i`                      |
| `padding`          | `/^[\d.\s\-a-z%]+$/i`                                   |
| `margin`           | `/^[\d.\s\-a-z%]+$/i`                                   |
| `border`           | `/^[\d.\s\-a-z#%(),]+$/i`                               |
| `border-radius`    | `/^[\d.\s\-a-z%]+$/i`                                   |
| `width`            | `/^[\d.\-a-z%]+$/i`                                     |
| `height`           | `/^[\d.\-a-z%]+$/i`                                     |
| `max-width`        | `/^[\d.\-a-z%]+$/i`                                     |

Beim Rendern der E-Mail läuft das HTML eines Textblocks durch die Raw-HTML-Regeln: dieselben Listen ohne `<s>`, `<strike>` und ohne die Attribute der Variablen-Chips auf `<span>`. Die bleiben in den gespeicherten Blöcken für den Editor, kommen aber nicht in der E-Mail an. Ein Raw-HTML-Block nutzt dieselben Regeln.

## Blocktypen

A paragraph or heading of rich text.

| Feld             | Typ                                                    | Pflicht | Beschreibung                                                                                |

| `textAlign`      | `"left"`, `"center"`, `"right"`, `"justify"`           |         |                                                                                             |
| `lineHeight`     | `number`                                               |         | Line height as a multiple of the font size, such as 1.5.                                    |

| `letterSpacing`  | `number`                                               |         | Letter spacing in px                                                                        |

```json
		"fontSize": 16,
		"textColor": "#1f2937",

	}
}
```
