Owlat bietet API-Keys für den programmatischen Zugriff und ausgehende Webhooks für Echtzeit-Ereignisbenachrichtigungen. Zusammen ermöglichen sie es dir, Owlat in deinen Anwendungs-Stack zu integrieren — Kontakte synchronisieren, transaktionale E-Mails auslösen und auf E-Mail-Ereignisse wie Bounces und Klicks reagieren.

## API-Keys

### Einen API-Key erstellen

1. Öffne **Einstellungen > Technik > API-Keys**.
2. Klicke auf **API-Key erstellen**.
3. Gib dem Key einen sprechenden Namen (z. B. „Production Backend“ oder „Staging Sync“).
4. Wähle die Scopes (Berechtigungen) aus, die der Key haben soll — mindestens ein Scope ist erforderlich; Keys folgen dem Prinzip der minimalen Rechte.
5. Kopiere den Key sofort — er wird kein zweites Mal angezeigt.

::callout{type="warning"}
Bewahre deinen API-Key sicher auf. Committe ihn niemals in die Versionskontrolle, binde ihn nicht in clientseitigen Code ein und gib ihn nicht im Klartext weiter. Verwende Umgebungsvariablen oder einen Secrets-Manager.
::

### Deinen API-Key verwenden

Übergib den API-Key in Anfragen an die Owlat-API. Details zur Authentifizierung, verfügbaren Endpunkten und SDK-Optionen findest du in der [API-Dokumentation](/api).

Häufige API-Anwendungsfälle:

- Kontakte aus deiner Anwendung heraus anlegen und aktualisieren
- Transaktionale E-Mails versenden (Passwort-Resets, Benachrichtigungen)
- Eigene Ereignisse als Auslöser für Automationen erfassen
- Kontakte programmatisch für Themen an- und abmelden

### Keys verwalten

Die Key-Liste zeigt, wann jeder Key zuletzt verwendet wurde (bzw. **Nie verwendet** bis zum ersten Aufruf), sodass du Zugangsdaten erkennst, die gefahrlos ausgemustert werden können. Für jeden Key kannst du:

- **Umbenennen** — den Namen des Keys direkt ändern, ohne den Key selbst zu beeinflussen.
- **Widerrufen** — einen kompromittierten oder nicht mehr benötigten Key soft-deaktivieren. Er funktioniert sofort nicht mehr, bleibt aber mit dem Badge **Widerrufen** in der Liste sichtbar.
- **Löschen** — die Zeile des Keys dauerhaft entfernen, auch bei bereits widerrufenen Keys. Das lässt sich nicht rückgängig machen.

::callout{type="tip"}
Rotiere deine API-Keys nach einem festen Zeitplan — auch wenn sie nicht kompromittiert wurden. Das begrenzt den Schaden, falls ein Key doch einmal nach außen gelangt.
::

## Webhooks

Webhooks sind ausgehende HTTP-Aufrufe, die Owlat an deinen Server sendet, wenn Ereignisse eintreten — etwa wenn eine E-Mail zugestellt, ein Link geklickt wird oder sich ein Kontakt von einem Thema abmeldet.

### Einen Webhook einrichten

1. Öffne **Einstellungen > Technik > Webhooks**.
2. Klicke auf **Webhook erstellen**.
3. Gib einen **Namen** und deine **Endpunkt-URL** ein — die URL auf deinem Server, die die Webhook-Payloads entgegennimmt.
4. Wähle die **Ereignisse** aus, die du abonnieren möchtest.
5. Speichere den Webhook. Das Signing Secret wird nur einmal bei der Erstellung angezeigt — kopiere es sofort.

### Verfügbare Ereignisse

Owlat kann dich über diese Ereignisse benachrichtigen:

| Ereignis | Wird ausgelöst, wenn |
| --- | --- |
| `email.sent` | Eine E-Mail gesendet wird |
| `email.delivered` | Eine E-Mail zugestellt wird |
| `email.bounced` | Eine E-Mail unzustellbar ist (Bounce) |
| `email.opened` | Eine E-Mail geöffnet wird |
| `email.clicked` | Ein Link in einer E-Mail geklickt wird |
| `email.complained` | Eine Spam-Beschwerde eingeht |
| `contact.created` | Ein neuer Kontakt angelegt wird |
| `topic.unsubscribed` | Ein Kontakt sich von einem Thema abmeldet |

Abonniere nur die Ereignisse, die du tatsächlich benötigst. Die Verarbeitung unnötiger Webhooks verschwendet auf beiden Seiten Ressourcen.

### Einen Webhook verwalten

Klappe einen beliebigen Webhook unter **Einstellungen > Technik > Webhooks** auf, um:

- **Test senden** — ein Beispielereignis `test` an deinen Endpunkt zu schicken, um dessen Erreichbarkeit zu prüfen (der Webhook muss aktiviert sein).
- **Aktivieren / Deaktivieren** — Zustellungen pausieren, ohne den Webhook zu löschen.
- **Secret neu erzeugen** — ein neues Signing Secret ausstellen (das alte wird ungültig).
- **Zustellprotokolle** — jüngste Zustellungen und Antworten einsehen (siehe unten).

### Zustellprotokolle

Jeder Webhook-Endpunkt zeigt ein Zustellprotokoll, mit dem du Folgendes überwachst:

- Jüngste an deinen Endpunkt gesendete Payloads
- HTTP-Statuscodes der Antworten
- Fehlgeschlagene Zustellungen und Wiederholungsversuche

Ist dein Endpunkt nicht erreichbar oder liefert Fehler, werden Webhooks automatisch erneut versucht. Prüfe das Zustellprotokoll, um Probleme zu diagnostizieren.

### Signaturprüfung

Jede Zustellung wird mit HMAC-SHA256 und dem Signing Secret des Webhooks signiert. Owlat übermittelt die Signatur im Header `X-Owlat-Signature` als `t=<timestamp>,v1=<hex digest>`, zusammen mit `X-Timestamp` (Unix-Sekunden, derselbe Wert wie `t`), `X-Webhook-Id` und `X-Webhook-Delivery-Id`. Die Signatur deckt Zeitstempel, Zustell-ID und rohen JSON-Body ab. Berechne sie mit deinem Secret neu und vergleiche sie mit `v1`, um zu bestätigen, dass die Anfrage von Owlat stammt und nicht verändert wurde, und lehne sie ab, wenn der Zeitstempel älter als 5 Minuten ist. Der ältere Header `X-Signature` deckt nur den Body ab; er ist veraltet und entfällt nach dem nächsten Release. Codebeispiele zur Verifizierung findest du in der [API-Dokumentation](/api/webhooks).

::callout{type="info"}
Verifiziere Webhook-Signaturen in der Produktion immer. Ohne Verifizierung könnte jeder, der deine Endpunkt-URL entdeckt, gefälschte Payloads senden.
::

## Best Practices

- **Sprechende Key-Namen verwenden** — „Production App v2“ sagt dir mehr als „Key 1“, wenn du ein halbes Jahr später deine Keys durchsiehst.
- **Keys nach Umgebung trennen** — verwende unterschiedliche API-Keys für Entwicklung, Staging und Produktion.
- **Webhook-Zustellung überwachen** — sieh regelmäßig in die Zustellprotokolle, um Endpunktprobleme zu erkennen, bevor sie deine Integration beeinträchtigen.
- **Ungenutzte Zugangsdaten widerrufen** — entferne alte API-Keys und inaktive Webhook-Endpunkte regelmäßig.
