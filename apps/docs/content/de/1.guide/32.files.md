Die Dateibibliothek ist ein zentraler Ort, um Dokumente, Anhänge und andere Assets neben den übrigen Daten Ihres Workspace aufzubewahren. Sie können Dateien hochladen, sie durchsuchen und filtern, sie taggen und eine Versionshistorie führen. Das Datenmodell verknüpft Dateien außerdem mit den Kontakten und Konversationen, zu denen sie gehören. Sie können eine Datei manuell mit Kontakten und mit einem Konversations-Thread verknüpfen, beim Hochladen oder auf ihrer Detailseite. Öffnen Sie die Bibliothek über **Dateien** im Dashboard (`/dashboard/files`).

::callout{type="info" title="Wer sie nutzen kann"}
Die Dateiseiten stehen jedem angemeldeten Teammitglied offen. Hochladen, Bearbeiten und Löschen von Dateien erfordern die Rolle **Admin** — Ansehen und Durchsuchen nicht.
::

## Die Dateibibliothek

Die Bibliothek listet Ihre Dateien mit den neuesten zuerst. Eine Werkzeugleiste am oberen Rand bietet Ihnen drei Steuerelemente:

- **Suche** — tippen Sie in das Suchfeld, um Dateien nach **Name**, **Titel**, **Tags**, **KI-Zusammenfassung**, **automatisch erkannten Tags** oder dem Anfang ihres **extrahierten Texts** zu finden. Die Suche nutzt einen Volltextindex und aktualisiert sich während der Eingabe. Semantische (bedeutungsbasierte) Suche ist an dieses Feld nicht angebunden — siehe [Suche](#search).
- **Quellenfilter** — Chips für **Alle Quellen**, **Uploads**, **E-Mail-Anhänge** und **KI-generiert** engen die Liste auf eine einzelne Herkunft ein.
- **Ansichtsumschalter** — wechseln Sie zwischen einem **Raster** aus Karten und einer kompakten **Listen**-Tabelle.

Jede Datei zeigt ihren Namen (oder Titel, falls Sie einen gesetzt haben), Typ, Größe, Quelle und Erstellungsdatum. Klicken Sie eine beliebige Datei an, um ihre Detailseite zu öffnen.

### Dateiquelle

Jede Datei hält fest, woher sie stammt. Die Quelle wird als Badge in der Liste und auf der Detailseite angezeigt:

| Quelle | Badge | Bedeutung |
| --- | --- | --- |
| `upload` | Upload | Von einem Teammitglied über den Upload-Dialog hinzugefügt. |
| `email_attachment` | E-Mail | Als aus einem eingehenden E-Mail-Anhang stammend gekennzeichnet. |
| `agent_generated` | KI | Als vom KI-Agenten erzeugt gekennzeichnet. |

::callout{type="info" title="Die Quelle wird beim Hochladen gesetzt"}
Die Quelle ist eine Bezeichnung, die Sie im Upload-Dialog wählen. Heute wird jede Datei über diesen Dialog hinzugefügt, selbst eine „KI-generierte“ Datei ist also eine, die Sie selbst hochgeladen und so gekennzeichnet haben. Eingehende E-Mail-Anhänge werden allerdings bei der Zustellung automatisch in die Bibliothek übernommen (Quelle `email_attachment`); nur Agentenausgaben werden noch nicht automatisch erfasst.
::

## Dateien hochladen

Klicken Sie auf **Hochladen**, um den Upload-Dialog zu öffnen, und dann:

::steps

### Eine Datei wählen

Ziehen Sie eine Datei auf die Ablagefläche oder klicken Sie, um zu durchsuchen. Jeder Dateityp wird akzeptiert. Der Dialog erzwingt eine Grenze von **50 MB**; zu große Dateien werden von der Create-Mutation des Servers abgelehnt, nicht bloß hinter einem UI-Hinweis versteckt.

### Titel und Tags ergänzen (optional)

Geben Sie der Datei einen aussagekräftigen **Titel** (andernfalls wird der ursprüngliche Dateiname als Anzeigename verwendet) und eine kommagetrennte Liste von **Tags**, um sie zu kennzeichnen und zu ordnen. Beides ist sofort durchsuchbar — eine Datei ist über ihre Tags auffindbar, noch bevor die KI-Verarbeitungsstrecke gelaufen ist.

### Eine Quelle wählen

Wählen Sie **Manueller Upload**, **E-Mail-Anhang** oder **KI-generiert**, um zu kennzeichnen, woher die Datei stammt. Das setzt lediglich das Quellen-Badge — es ändert nichts daran, wie die Datei verarbeitet wird.

### Hochladen

Die Datei wird gespeichert und sofort der Bibliothek hinzugefügt. Sie landen wieder in der Liste, mit der neuen Datei ganz oben.

::

## Dateidetails

Beim Öffnen einer Datei sehen Sie alles, was Owlat über sie weiß. Die linke Spalte enthält die Inhaltsabschnitte der Datei; die rechte Spalte die Metadaten.

- **Titel** — klicken Sie den Titel an, um ihn direkt umzubenennen. Der ursprüngliche Dateiname wird immer darunter angezeigt.
- **Herunterladen** — öffnet die gespeicherte Datei in einem neuen Tab.
- **Details** — MIME-Typ, Größe, Erstellungsdatum und Quellen-Badge.
- **Tags** — bearbeiten Sie die kommagetrennten Tags über die Stift-Schaltfläche. **Automatisch erkannte** Tags erscheinen, sofern vorhanden, in einer eigenen Gruppe. Das Bearbeiten von Tags oder Titel indiziert die Datei sofort neu, sodass sie über die neuen Werte auffindbar ist.
- **Verknüpfte Kontakte** — Kontakte, denen diese Datei zugeordnet ist, jeweils mit Link zum Kontaktdatensatz.
- **Verknüpfte Konversation** — der Thread, zu dem diese Datei gehört, mit Link in das [Team-Postfach](/guide/team-inbox). Nutzen Sie die Stift-Schaltfläche, um Konversationen nach Betreff oder Absender zu durchsuchen und eine auszuwählen oder die Verknüpfung zu entfernen.

### KI-Zusammenfassung, extrahierter Text und Auto-Tags

Die Detailseite hat aufklappbare Abschnitte für eine **KI-Zusammenfassung**, den **extrahierten Text** der Datei und eine Gruppe **automatisch erkannter** Tags. Diese erscheinen nur, wenn die zugrunde liegende Datei diese Daten tatsächlich besitzt.

::callout{type="info" title="Erfordert einen konfigurierten LLM- und Embedding-Anbieter"}
Eine Verarbeitungsstrecke (`apps/api/convex/semanticFileProcessing.ts`) extrahiert Text, schreibt eine KI-Zusammenfassung, erzeugt Auto-Tags und berechnet für jede Datei ein Such-Embedding. **Sie wird beim Hochladen eingeplant** (`semanticFileProcessing.processFile`, angestoßen von der Create-Mutation), und ein Cron als Sicherheitsnetz führt sie alle 15 Minuten erneut für kürzlich hinzugekommene Dateien aus, denen noch ein Embedding fehlt. Zusammenfassung, Auto-Tags und Embedding entstehen nur, wenn ein **LLM- und Embedding-Anbieter konfiguriert** sind — ohne sie bleiben diese Abschnitte ausgeblendet. Beachten Sie, dass aus reinem Text, HTML, JSON, CSV und PDF Text extrahiert wird, Word, Excel und Bilder hingegen nur einen Platzhalter mit dem Dateinamen liefern und Bilder nicht per OCR gelesen werden.
::

Sobald eine Datei echten extrahierten Text hat, schürft die Verarbeitungsstrecke ihn außerdem in den [Wissensgraphen](/guide/knowledge-graph) ein (Quelle **Datei**), sodass Fakten aus Ihren Dokumenten zu typisierten Einträgen werden, die Sie neben dem aus E-Mail erfassten Wissen durchstöbern und durchsuchen können. Binäre Stubs (ein Word-/Excel-/Bild-Platzhalter) tragen keinen Text und erzeugen deshalb keine Wissenseinträge.

### Versionshistorie

Jede Datei führt eine **Versionsnummer** und einen Verweis auf ihre Vorgängerversion, und die Detailseite stellt die vollständige Versionskette als Zeitleiste dar. Die aktuelle Version ist markiert.

::callout{type="warning" title="Neue Versionen anlegen"}
Das Datenmodell unterstützt Versionen (ein neuer Upload kann eine `previousVersionId` referenzieren), aber der Upload-Dialog bietet noch keine Option „ersetzen / neue Version“, in der Praxis ist deshalb jeder Upload eine eigenständige Datei in Version 1.
::

## Dateien mit Kontakten und Konversationen verknüpfen

Eine Datei kann einem oder mehreren **Kontakten** und einem einzelnen **Konversations-Thread** zugeordnet werden:

- **Kontakte** — verknüpfte Kontakte erscheinen in der rechten Spalte der Datei und verweisen direkt auf den jeweiligen Kontaktdatensatz. Auf der eigenen Seite eines Kontakts listet der Tab **Dateien** jede mit diesem Kontakt verknüpfte Datei auf (Uploads wie Anhänge gleichermaßen). Siehe [Kontakte](/guide/contacts) und [Identitäten & Beziehungen](/guide/audience-data).
- **Konversation** — ist eine Datei an einen Thread gebunden, verweist das Panel **Verknüpfte Konversation** auf diese Konversation im [Team-Postfach](/guide/team-inbox).

Beide Arten von Verknüpfung setzen Sie an denselben zwei Stellen:

- **Beim Hochladen** — der Upload-Dialog hat eine Auswahl **Verknüpfte Kontakte** und eine Auswahl **Verknüpfte Konversation**. Suchen Sie einen Kontakt nach Name oder E-Mail und fügen Sie so viele hinzu, wie zutreffen; suchen Sie eine Konversation nach Betreff oder Absender und wählen Sie eine aus. Beides wird mit der Datei gespeichert.
- **Nach dem Hochladen** — die Panels **Verknüpfte Kontakte** und **Verknüpfte Konversation** auf der Dateidetailseite haben jeweils ein Bearbeiten-Element (Stift), das dieselbe Auswahl öffnet, sodass Sie Verknüpfungen jederzeit hinzufügen, ändern oder entfernen können.

Die Konversationsauswahl durchsucht die jüngsten Threads des gemeinsamen Postfachs nach Betreff und Teilnehmeradresse. Sie ist Admins vorbehalten, wie jede andere Dateibearbeitung auch.

Eingehende E-Mail-Anhänge werden bei der Zustellung erfasst und, wenn die Absenderadresse bereits zu einem vorhandenen Kontakt passt, automatisch mit diesem **Absenderkontakt** verknüpft (sie erscheinen dann im Tab **Dateien** dieses Kontakts). Ein Absender ohne vorhandenen Kontakt bleibt organisationsweit allgemein — die Erfassung legt nie einen Kontakt an. Erfasste Anhänge tragen die Message-ID der Quellnachricht als Herkunftsnachweis. Die automatische Thread-Verknüpfung bei der Erfassung ist weiterhin nicht angebunden (siehe unten).

::callout{type="info" title="Automatische Konversationsverknüpfung"}
Die manuelle Thread-Verknüpfung steht sowohl im Upload-Dialog als auch auf der Detailseite zur Verfügung. Was noch fehlt, ist der *automatische* Weg: Ein erfasster E-Mail-Anhang erbt den Thread seiner Quellnachricht nicht, Sie müssen die Konversation also selbst auswählen.
::

## Suche

Das Suchfeld führt eine **Volltextsuche** über den durchsuchbaren Text jeder Datei aus. Sie ist schnell, verzeiht Wortfragmente und berücksichtigt den aktiven Quellenfilter.

Der durchsuchbare Text einer Datei setzt sich zusammen aus ihrem **Dateinamen** (ganz und in Wörter zerlegt, sodass `q3-budget_v2.pdf` auf „budget“ passt), ihrem **Titel**, ihren **Tags** und — sobald die KI-Verarbeitungsstrecke gelaufen ist — ihrer **Zusammenfassung**, ihren **automatisch erkannten Tags** und dem ersten Stück ihres **extrahierten Texts**. Er wird jedes Mal neu aufgebaut, wenn sich die Datei ändert: beim Hochladen, wenn die Verarbeitung abgeschlossen ist und bei jeder Titel- oder Tag-Bearbeitung.

::callout{type="info" title="Dateien, die vor dieser Auslieferung hochgeladen wurden"}
Früher angelegte Datensätze tragen den alten Indexeintrag, der nur Dateiname und Titel enthält. Eine Betreiberin oder ein Betreiber indiziert sie einmalig neu mit
`npx convex run migrations/0038_rebuild_file_search_text:run` — der Befehl ist idempotent und kann gefahrlos erneut ausgeführt werden.
::

::callout{type="warning" title="Das Suchfeld im Dashboard ist Volltext, nicht semantisch"}
Die Bibliothek unterstützt **semantische (Vektor-)Suche** — Dateien tragen ein Embedding-Feld und die Tabelle hat einen Vektorindex. Die echte Vektorsuche steckt in der Action `semanticFileProcessing.semanticSearch` (die von der Agenten-Verarbeitungsstrecke genutzt wird). Das Suchfeld im Dashboard ruft hingegen die Volltext-Query `search` auf: Die Vektorsuche von Convex läuft nur auf einem Action-Kontext, nie in einer Query, das sich live aktualisierende Suchfeld kann sie also nicht aufrufen. Bedeutungsbasierter Abruf steht über Frag-alles zur Verfügung (siehe unten).
::

::callout{type="tip" title="Frag-alles durchsucht auch Ihre Dateien"}
Über das Suchfeld im Dashboard hinaus ruft das **Frag-alles**-Feld (`QuickQueryPanel`, auf dem Dashboard [Wissensgraph](/guide/knowledge-graph)) *sehr wohl* semantisch aus dem Dateispeicher ab: `quickQuery.ask` fächert über `semanticFileProcessing.semanticSearch` (echte `vector_files`-Suche) **und** den Wissensgraphen auf und lässt das LLM dann eine fundierte Antwort synthetisieren, die die genutzten Dateien und Einträge **zitiert**. Eine natürlichsprachige Frage kann so einen hochgeladenen Vertrag oder eine Rechnung über deren Bedeutung zutage fördern, während das Suchfeld der Bibliothek auf die Wörter passt, die tatsächlich in Name, Tags, Zusammenfassung und Text der Datei stehen.
::
