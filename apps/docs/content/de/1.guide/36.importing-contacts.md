---
title: "Kontakte importieren & exportieren"
description: "Kontakte per CSV oder aus Mailchimp und Stripe nach Owlat holen, sie wieder exportieren und Massenoperationen auf Ihrer Zielgruppe ausführen."
---

Owlat bietet Ihnen mehrere Wege, Kontakte hinein- und hinauszubekommen: eine CSV mit Spaltenzuordnung hochladen, direkt aus Mailchimp oder Stripe ziehen, alles (oder einen gefilterten Ausschnitt) wieder als CSV exportieren und Massenaktionen auf ganze Auswahlen anwenden. Alles in diesem Leitfaden liegt unter **Zielgruppe > Kontakte**.

Der Import von Kontakten und die destruktiven Massenaktionen (Thema hinzufügen/entfernen, löschen) erfordern die Rolle **Owner** oder **Admin**. Der Export steht jedem Teammitglied offen, das die Kontaktliste sehen darf. Die vollständige Aufschlüsselung der Rollen finden Sie unter [Team & Berechtigungen](/guide/team-permissions).

## Import aus CSV

Der CSV-Importer parst Ihre Datei im Browser, lässt Sie Spalten auf Kontaktfelder abbilden und lädt die Zeilen in Stapeln zu je 100 hoch. Öffnen Sie zum Start **Zielgruppe > Kontakte**, klicken Sie auf **Importieren** und wählen Sie **CSV-Datei**.

### Hochladen

Ziehen Sie eine `.csv`-Datei auf den Upload-Bereich oder klicken Sie, um zu suchen. Ihre Datei muss:

- Spaltenüberschriften in der **ersten Zeile** haben.
- Mindestens eine Kopfzeile und eine Datenzeile enthalten.
- Eine E-Mail-Spalte enthalten (die Sie im nächsten Schritt zuordnen).

Der Importer liest die gesamte Datei vorab ein, sodass Sie die Gesamtzahl der Zeilen schon vor der Zuordnung sehen.

### Spalten auf Felder abbilden

Owlat erkennt gängige Überschriften automatisch (es kennt Varianten wie `email`, `first name`, `lastname`, `language` und `list`/`topic`), aber Sie können jede Spalte überschreiben. Jede Spalte wird auf eines der Folgenden abgebildet:

| Feld | Hinweise |
| --- | --- |
| **E-Mail (erforderlich)** | Dient als eindeutige Kennung. Ohne eine auf E-Mail abgebildete Spalte können Sie nicht fortfahren. |
| **Vorname** | Personalisierungsfeld. |
| **Nachname** | Personalisierungsfeld. |
| **Sprache** | Bevorzugte Sprache für übersetzte Sendungen. |
| **Thema** | Themen-Mitgliedschaft pro Kontakt, aus dem Zellwert gelesen (siehe unten). |
| **Eigene Eigenschaft** | Die Spalte als eigene Kontakteigenschaft importieren. Die CSV-Überschrift wird zum Eigenschaftsschlüssel; neue Schlüssel werden vor dem Import automatisch registriert. |
| **— Diese Spalte ignorieren** | Die Spalte vollständig überspringen. |

Um irgendeine andere Spalte als eigene Eigenschaft zu übernehmen, bilden Sie sie auf **Eigene Eigenschaft** ab — die CSV-Überschrift wird zum Eigenschaftsschlüssel, und Owlat registriert alle noch nicht definierten Eigenschaftsschlüssel vor dem Import automatisch. (Mailchimp- und Stripe-Importe registrieren jedes zusätzliche Feld automatisch; der CSV-Ablauf importiert eine eigene Spalte nur dann, wenn Sie sie ausdrücklich auf **Eigene Eigenschaft** abbilden. Siehe [Integrations-Import](#import-from-mailchimp-or-stripe).)

### Umgang mit Dubletten

Legen Sie fest, was passiert, wenn die E-Mail-Adresse einer Zeile in Ihrer Zielgruppe bereits existiert:

- **Dubletten überspringen** — bestehende Kontakte bleiben unangetastet.
- **Bestehende aktualisieren** — bestehende Kontakte werden mit den neuen Feldwerten aus der CSV zusammengeführt.

Doppelte E-Mail-Adressen *innerhalb derselben Datei* werden immer auf das erste Vorkommen reduziert und als übersprungen gezählt.

### Kontakte Themen zuordnen

Sie können importierte Kontakte auf eine von zwei einander ausschließenden Arten zu [Themen](/guide/topics) hinzufügen:

- **Globale Zuordnung** — wählen Sie unter **Zu Thema hinzufügen** ein Thema aus, und jeder importierte Kontakt wird ihm hinzugefügt.
- **Spaltenzuordnung** — bilden Sie eine CSV-Spalte auf **Thema** ab. Der Importer liest den Zellwert jeder Zeile (kommagetrennte Werte für mehrere Themen werden unterstützt), sammelt die gefundenen eindeutigen Namen und zeigt einen **Listen-Zuordnungs**-Schritt, in dem Sie jeden Namen aus Ihrer Datei einem bestehenden Owlat-Thema zuordnen oder ihn **Überspringen**. Übersprungene Namen entfallen.

Eine Spaltenzuordnung auf „Thema“ hat Vorrang vor einer globalen Auswahl — sobald Sie eine Spalte auswählen, wird der globale Auswahldialog deaktiviert.

### Prüfen und importieren

Der Vorschauschritt validiert jede Zeile und zeigt eine Zusammenfassung: **gültige Kontakte**, **ungültige E-Mail-Adressen**, **Dubletten** und **fehlende E-Mail-Adressen**, dazu eine Stichprobe der ersten fünf Zeilen mit einem Statussymbol pro Zeile. Klappen Sie **Problemdetails anzeigen** auf, um genau zu sehen, welche Zeilen Probleme haben. Zeilen mit ungültigen oder fehlenden E-Mail-Adressen werden nicht importiert; nur gültige Zeilen zählen für den Import.

Wenn Sie bestätigen, werden die Kontakte stapelweise mit einem Fortschrittsbalken hochgeladen, und die Abschlussanzeige meldet, wie viele **importiert**, **aktualisiert**, **übersprungen** und **fehlgeschlagen** sind, dazu etwaige Fehler (begrenzt auf die ersten paar) und wie viele zu Themen hinzugefügt wurden.

::callout{type="tip" title="Räumen Sie Ihre Liste vorher auf"}
Entfernen Sie offensichtliche Dubletten und korrigieren Sie fehlerhafte Adressen vor dem Hochladen. Owlats E-Mail-Prüfung ist bewusst schlank — sie fängt fehlende `@` und offensichtlich kaputte Adressen ab, prüft aber nicht, ob ein Postfach tatsächlich existiert.
::

### Double Opt-in und Import

Ob ein Thema [Double Opt-in](/guide/topics) (DOI) verwendet, wird auf **Themen**-Ebene entschieden. Wenn Sie importierte Kontakte einem DOI-geschützten Thema zuordnen, muss normalerweise jeder von ihnen bestätigen, bevor er zum aktiven Abonnenten wird.

Die Kontakt-Import-Engine unterstützt einen **Admin-Attest**-Pfad: Wenn die aufrufende Stelle versichert, dass die Kontakte ihre Einwilligung bereits auf einer anderen Plattform bestätigt haben, werden diese Kontakte sofort als bestätigt markiert, statt eine Bestätigungs-E-Mail zu erhalten. Diese Attestierung wird bei jedem Kontakt und in Ihrem [Audit-Protokoll](/guide/audit-logs) festgehalten.

::callout{type="warning" title="Admin-Attest ist ein interner Importpfad"}
Admin-Attest existiert nur im internen Import-Backend, das der In-App-Importer und die Mailchimp-/Stripe-Integrationsimporte nutzen, abgesichert über Ihre Team-Session und die Berechtigung **contacts:manage**. Über die öffentliche [Kontakte-API](/api/contacts) ist er heute **nicht** erreichbar, und die In-App-Oberfläche für den **CSV-Import** bietet derzeit **keinen** DOI-Attest-Schalter — Kontakte, die über das Dashboard in ein DOI-geschütztes Thema importiert werden, durchlaufen also den normalen Bestätigungsablauf. Attestieren Sie nur Einwilligungen, die Sie tatsächlich eingeholt haben — die Verantwortung dafür bleibt bei Ihnen.
::

## Import aus Mailchimp oder Stripe

Owlat kann Kontakte ohne den Umweg über eine CSV direkt aus Mailchimp und Stripe ziehen. Öffnen Sie **Zielgruppe > Kontakte**, klicken Sie auf **Importieren** und wählen Sie **Integrationen**.

### Mailchimp

Sie benötigen:

- Einen **Mailchimp-API-Key** im Format `apikey-datacenter` (zum Beispiel `abc123def456-us21`). Sie finden ihn in Mailchimp unter **Account > Extras > API keys**.
- Eine **Audience List ID**. Sie finden sie unter **Audience > Settings > Audience name and defaults**.

Owlat bildet Mailchimps `Email` auf die E-Mail-Adresse ab und `FNAME`/`LNAME` auf Vor- und Nachname.

### Stripe

Sie benötigen einen **Stripe Secret Key** (er muss mit `sk_` beginnen). Sie finden ihn im Stripe-Dashboard unter **Developers > API keys**.

::callout{type="warning" title="Verwenden Sie einen eingeschränkten Key"}
Erstellen Sie für Stripe einen eingeschränkten API-Key, der ausschließlich auf **Customers: Read** beschränkt ist. Owlat bildet die E-Mail-Adresse eines Kunden auf die E-Mail-Adresse und dessen Namen auf die Felder Vor-/Nachname ab.
::

Ihre API-Keys werden nur für die Dauer des Imports verwendet und nicht gespeichert.

### Dubletten, Thema und Fortschritt

Beide Integrationen teilen sich dieselben Optionen wie der CSV-Ablauf:

- **Umgang mit Dubletten** — **Dubletten überspringen** oder **Bestehende aktualisieren**.
- **Zu Thema hinzufügen** — optional jeden importierten Kontakt zu einem Thema hinzufügen.

Integrationsimporte laufen im Hintergrund, Seite für Seite, auf dem Server. Der Fortschrittsdialog zeigt einen Live-Zähler (Mailchimp meldet eine Gesamtschätzung; Stripe zeigt den laufenden Fortschritt, weil es das nicht tut), und Sie können den Dialog schließen — der Import läuft weiter. Nach Abschluss erhalten Sie die Zähler **importiert / aktualisiert / übersprungen / fehlgeschlagen** sowie etwaige Fehler. Während der Ausführung können Sie **Import abbrechen**.

::callout{type="info" title="Ein Import zur Zeit"}
Es kann immer nur ein Integrationsimport gleichzeitig laufen. Starten Sie einen zweiten, während einer noch läuft, teilt Ihnen Owlat mit, dass bereits ein Import in Arbeit ist.
::

Anders als der CSV-Ablauf im Web registrieren Integrationsimporte **eigene Eigenschaften automatisch**: Zusatzfelder aus Mailchimp-Merge-Feldern oder Stripe-Metadaten werden automatisch zu [Kontakteigenschaften](/guide/contact-properties) (mit ihrer Quelle gekennzeichnet), sodass Sie sie nicht vorab definieren müssen.

## Kontakte als CSV exportieren

Öffnen Sie zum Exportieren **Zielgruppe > Kontakte** und klicken Sie auf **Exportieren**. Wählen Sie, was exportiert werden soll:

- **Alle Kontakte** — jeder Kontakt in Ihrer Zielgruppe.
- **Aktuelle Suchergebnisse** — nur Kontakte, die zu Ihrer aktuellen Suche passen (diese Option erscheint, wenn eine Suche aktiv ist).

Owlat erzeugt die CSV in Ihrem Browser und lädt sie als `contacts-export-YYYY-MM-DD.csv` herunter. Jede Zeile enthält:

| Spalte | Beschreibung |
| --- | --- |
| Email | Die E-Mail-Adresse des Kontakts. |
| First Name / Last Name | Namensfelder. |
| Language | Bevorzugte Sprache. |
| Source | Wie der Kontakt hinzugefügt wurde (api, csv, form und so weiter). |
| Created At / Updated At | ISO-8601-Zeitstempel. |
| *Eigene Eigenschaften* | Eine Spalte je definierter [Kontakteigenschaft](/guide/contact-properties), mit deren Bezeichnung als Überschrift. |

## Massenoperationen

Wählen Sie Kontakte aus, um mehrere auf einmal zu bearbeiten. Setzen Sie das Häkchen in einer beliebigen Zeile oder nutzen Sie das Häkchen in der Kopfzeile, um alle aktuell auf der Seite geladenen Kontakte auszuwählen. Wenn Ihre Suche mehr Kontakte gefunden hat, als geladen sind, erscheint eine Aktion **Alle N auswählen**, mit der Sie die gesamte gefilterte Menge auswählen können und nicht nur die sichtbaren Zeilen.

Bei aktiver Auswahl bietet das Menü **Aktionen**:

| Aktion | Was sie tut |
| --- | --- |
| **Zu Thema hinzufügen** | Die ausgewählten Kontakte für ein Thema abonnieren. Die DOI-Regeln dieses Themas gelten weiterhin. |
| **Aus Thema entfernen** | Das Abonnement der ausgewählten Kontakte für ein Thema beenden. |
| **Auswahl exportieren** | Nur die ausgewählten Kontakte als CSV herunterladen. |
| **Auswahl löschen** | Die ausgewählten Kontakte dauerhaft löschen. |

Massenweises Hinzufügen, Entfernen und Löschen wird stapelweise mit einer Fortschrittsanzeige verarbeitet. **Löschen** fragt zuerst nach einer Bestätigung und warnt, dass der Vorgang endgültig ist — das Löschen eines Kontakts entfernt ihn außerdem aus jedem Thema und löscht seine eigenen Eigenschaftswerte.

::callout{type="warning" title="Löschungen lassen sich nicht rückgängig machen"}
Für gelöschte Kontakte gibt es keinen Papierkorb und keine Wiederherstellung. Exportieren Sie die Auswahl vorher, falls Sie sie später noch brauchen könnten.
::
