**System & Updates** findest du unter **Einstellungen > System & Updates** (`/dashboard/admin/system`); der Bereich ist nur für den Owner des Deployments sichtbar. Er ist das Betriebs-Dashboard einer selbst gehosteten Owlat-Instanz: welche Version du ausführst, ob die Container gesund sind, was dich die KI kostet und ein Ein-Klick-Weg zum neuesten Release.

## Aktuelle Version

Die oberste Karte zeigt die Version, die dieses Deployment ausführt. In einem Development-Build steht dort `dev`.

## Container-Zustand

Eine Live-Tabelle aller Service-Container (Web, Convex-Backend, MTA, ClamAV und so weiter) mit ihrem Laufzustand und Image-Tag. Mit **Aktualisieren** fragst du erneut ab. Das ist der schnellste Weg, einen gestoppten oder ständig neu startenden Container zu erkennen.

## LLM-Kosten

Eine Aufschlüsselung deiner KI-Kosten der **letzten 7 Tage**, mit der Gesamtsumme oben und einer Aufteilung nach Funktion (Entwerfen, Klassifizierung, Wissensextraktion, Assistent und so weiter), die ausgegebene Dollarbeträge und die Anzahl der Aufrufe zeigt. Jeder bepreiste LLM-Aufruf im gesamten Deployment wird hier erfasst — dies ist also die einzige Stelle, an der du siehst, was deine KI-Funktionen tatsächlich kosten.

## Nach Updates suchen und sie anwenden

Die Karte **Verfügbare Updates** vergleicht deine Version mit dem neuesten GitHub-Release.

- **Jetzt prüfen** fragt bei GitHub das neueste veröffentlichte Release ab.
- **Jetzt aktualisieren** erscheint, sobald eine neuere Version verfügbar ist. Es lädt die gepinnte Docker-Compose-Vorlage für die Zielversion herunter, zieht die neuen Images, deployt die Convex-Backend-Funktionen erneut und erstellt die Container neu. Die Web-App kann mitten im Update neu starten; die Seite lädt sich selbst neu, sobald die neue Version live ist.

Die Release Notes der verfügbaren Version werden inline angezeigt, sodass du vor dem Anwenden prüfen kannst, was sich ändert.

::callout{type="warning" title="Vor dem Update ein Backup anlegen"}
Datenvolumes bleiben über ein normales Update hinweg erhalten, aber ein Release mit brechenden Schemaänderungen kann Daten migrieren oder zurücksetzen. **Lies zuerst die Release Notes und lege ein Backup an, bevor du auf „Jetzt aktualisieren“ klickst.** Schlägt ein Update fehl, verlinkt der Bildschirm auf die Wiederherstellungsschritte — siehe [Wartung & Updates](/developer/self-hosting-maintenance#recovering-from-a-failed-update).
::

## Update-Verlauf

Ein Protokoll vergangener Updates — von welcher Version auf welche gewechselt wurde, wann es startete, wie lange es dauerte und ob es erfolgreich war.

## Das Kommandozeilen-Äquivalent

Alles hier hat eine CLI-Entsprechung für Betreiberinnen und Betreiber, die die Shell bevorzugen: `owlat upgrade` auf dem Host führt denselben Update-Ablauf nicht-interaktiv aus. Das vollständige Runbook für Updates und Wiederherstellung beim Self-Hosting findest du unter [Wartung & Updates](/developer/self-hosting-maintenance).
