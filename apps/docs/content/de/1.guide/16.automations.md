Mit Automationen versendest du E-Mails automatisch anhand dessen, was deine Kontakte tun. Statt bei jeder Anmeldung von Hand eine Willkommens-E-Mail zu verschicken, richtest du das einmal ein und Owlat übernimmt den Rest — jeder neue Kontakt erhält die richtige E-Mail zur richtigen Zeit, ohne dass du einen Finger rührst.

## Grundbegriffe

Jede Automation besteht aus drei Zutaten:

- **Trigger** — das Ereignis, das die Automation für einen Kontakt startet
- **Schritte** — die Abfolge der Aktionen (E-Mail senden, warten, Bedingung prüfen)
- **Status** — ob die Automation gerade aktiv, pausiert oder im Entwurf ist

Jeder Kontakt durchläuft die Automation eigenständig. Melden sich heute 50 Personen an, bekommt jede ihren eigenen Durchlauf durch die Schritte.

## Trigger-Typen

| Trigger | Wann er auslöst | Konfiguration |
| --- | --- | --- |
| **Kontakt erstellt** | Ein Kontakt wird in deiner Zielgruppe angelegt (manuell, per Import, Formular oder API) | Keine — löst bei jedem neuen Kontakt aus |
| **Kontakt aktualisiert** | Die Daten eines Kontakts werden geändert | Die zu beobachtende Kontakteigenschaft |
| **Event empfangen** | Deine Anwendung sendet ein eigenes Event über die API | Der Eventname, auf den geprüft wird (z. B. `trial_started`) |
| **Thema abonniert** | Ein Kontakt abonniert ein bestimmtes Thema | Das zu beobachtende Thema |

Trigger tragen keine Filter oder Bedingungen — sie lösen aus, sobald ihr Ereignis eintritt. Um den Ablauf auf bestimmte Kontakte einzugrenzen, füge innerhalb der Automation einen Schritt vom Typ **Bedingung** ein (siehe unten).

::callout{type="tip"}
Der Trigger **Event empfangen** ist der flexibelste. Mit ihm startest du Automationen aus jedem Ereignis in deiner Anwendung — Kauf abgeschlossen, Testphase gestartet, Funktion aktiviert und so weiter —, indem du auf den von dir gesendeten Eventnamen prüfst. Details findest du in der [Events-API](/api/events).
::

## Schritt-Typen

| Schritt | Was er tut |
| --- | --- |
| **E-Mail senden** | Sendet eine bestimmte E-Mail-Vorlage an den Kontakt. Die Betreffzeile der Vorlage kannst du für diesen Schritt optional überschreiben. |
| **Warten/Verzögerung** | Pausiert die Automation vor dem nächsten Schritt für eine festgelegte Dauer (Minuten, Stunden, Tage oder Wochen). |
| **Bedingung** | Verzweigt den Ablauf — passende Kontakte gehen den einen Weg, die übrigen den anderen. Bedingungen prüfen auf eine Kontakteigenschaft, E-Mail-Aktivität (geöffnet/geklickt) oder Themenzugehörigkeit. |

::callout{type="info"}
Automations-E-Mails werden ohne Öffnungs-/Klick-Tracking und ohne Abmeldefußzeile versendet und erreichen ausschließlich Kontakte mit einer E-Mail-Adresse. Kontakte, die über SMS, WhatsApp oder Telefon ohne E-Mail hinzugefügt wurden, scheitern am Schritt **E-Mail senden** (protokolliert als Fehlschlag für diesen Kontakt). Ein Kontakt, der sich von allem Marketing abgemeldet hat, erhält keine Automations-E-Mails mehr: Seine Schritte **E-Mail senden** werden übersprungen, und der Rest der Automation (Verzögerungen, Bedingungen, Integrationen) läuft weiter. Das Löschen eines Kontakts beendet seine Automations-Durchläufe.
::

## Eine Automation bauen

### 1. Die Automation anlegen

1. Öffne **Kampagnen > Automationen**.
2. Klicke auf **Neue Automation**.
3. Gib ihr einen sprechenden Namen (z. B. „Willkommensserie“ oder „Erinnerung zum Testphasenende“).

### 2. Den Trigger wählen

Wähle das Ereignis, das die Automation startet. Manche Trigger benötigen etwas Konfiguration:

- **Kontakt erstellt** braucht nichts — er löst aus, sobald ein Kontakt hinzugefügt wird.
- **Event empfangen** verlangt den Eventnamen, auf den geprüft wird (z. B. `trial_started`).
- **Thema abonniert** verlangt, welches Thema beobachtet wird.
- **Kontakt aktualisiert** verlangt, welche Eigenschaft beobachtet wird.

Trigger filtern nicht nach Kontaktattributen. Wenn nur bestimmte Kontakte weiterlaufen sollen, füge später im Ablauf einen Schritt vom Typ **Bedingung** ein.

### 3. Schritte hinzufügen

Baue deine Abfolge, indem du Schritt für Schritt ergänzt:

1. **E-Mail senden** — wähle die Vorlage für deine erste E-Mail
2. **Warten/Verzögerung** — füge eine Wartezeit ein (z. B. 2 Tage)
3. **E-Mail senden** — wähle die Vorlage für deine Nachfass-E-Mail
4. **Bedingung** — prüfe, ob der Kontakt die erste E-Mail geöffnet hat, und verzweige entsprechend

Du kannst so viele Schritte hinzufügen, wie dein Workflow benötigt.

### 4. Aktivieren

Sobald deine Automation gebaut und getestet ist, setze ihren Status auf **Aktiv**. Sie beginnt dann, alle künftig zum Trigger passenden Kontakte zu verarbeiten.

## Gängige Muster

### Willkommensserie

Eine mehrstufige Abfolge für neue Anmeldungen. **Trigger: Kontakt erstellt.**

1. **Sofort**: Willkommens-E-Mail mit den wichtigsten Funktionen senden
2. **2 Tage warten**: Tipps für den Einstieg senden
3. **5 Tage warten**: Eine Fallstudie oder Erfolgsgeschichte senden
4. **7 Tage warten**: Eine **Bedingung** einfügen, die die E-Mail-Aktivität prüft (Willkommens-E-Mail geöffnet?) — falls nicht, in einen Reaktivierungsanstoß verzweigen

### Testphasen-Lebenszyklus

Führe Testnutzer zur Umwandlung. **Trigger: Event empfangen** mit dem Eventnamen `trial_started`, den deine App über die [Events-API](/api/events) sendet.

1. **Sofort**: Einrichtungsanleitung senden
2. **3 Tage warten**: Eine **Bedingung** auf eine Kontakteigenschaft setzen (z. B. `onboarding_complete`) — Hilfe an alle senden, die noch nicht fertig sind
3. **7 Tage warten**: Ein Funktions-Highlight senden
4. **Ein paar Tage länger warten**: Vor Ende der Testphase eine Umwandlungserinnerung senden

### Nachfassen nach dem Kauf

Binde Kunden nach einem Kauf. **Trigger: Event empfangen** mit dem Eventnamen `purchase`.

1. **Sofort**: Bestellbestätigung senden
2. **3 Tage warten**: Eine Bitte um Feedback oder Bewertung senden
3. **14 Tage warten**: Empfehlungen für passende Produkte senden

### Reaktivierung

Gewinne still gewordene Kontakte zurück. Es gibt keinen zeitbasierten Trigger „seit 90 Tagen inaktiv“, baue das also auf einem Event auf, das du ohnehin sendest (zum Beispiel **Event empfangen** mit `re_engage`), oder führe es als Schritt innerhalb eines längeren Ablaufs aus:

1. **Eine Bedingung** auf die E-Mail-Aktivität setzen — Kontakte abzweigen, die eine kürzliche E-Mail *nicht* geöffnet haben
2. **Sofort**: Eine „Wir vermissen dich“-E-Mail mit einem Anreiz senden
3. **7 Tage warten**: Eine zweite **Bedingung** auf die E-Mail-Aktivität setzen — falls immer noch keine Interaktion, eine letzte Erinnerung senden

## Automationsstatus

| Status | Bedeutung |
| --- | --- |
| **Entwurf** | Wird konfiguriert. Es werden keine Kontakte verarbeitet. |
| **Aktiv** | Läuft. Neue Kontakte, die zum Trigger passen, treten in den Ablauf ein. |
| **Pausiert** | Gestoppt. Es treten keine neuen Kontakte ein. Kontakte im Ablauf überstehen die Pause nur, solange sie in einer noch nicht abgelaufenen Verzögerung sitzen (siehe Warnung unten). |

::callout{type="warning" title="Pausieren ist ein weicher Stopp, kein Einfrieren"}
Während eine Automation pausiert ist, treten keine neuen Kontakte ein. Kontakte, die bereits im Ablauf sind, laufen nur weiter, wenn ihr nächster Schritt noch in einer Verzögerung wartet. Läuft die Verzögerung eines Kontakts ab, während die Automation pausiert ist, wird dessen Durchlauf **abgebrochen** — der nächste Schritt wird als fehlgeschlagen markiert und der Durchlauf endet (ein Hintergrundjob prüft alle paar Minuten auf fällige Schritte). Pausieren garantiert daher kein sauberes Fortsetzen für Kontakte im Ablauf; setze zügig fort oder betrachte die Pause als Mittel, um Neuzugänge zu stoppen, statt alle mitten im Ablauf sicher einzufrieren.
::

## Überwachung

Öffne die Detailseite einer beliebigen Automation, um zu sehen:

- **Aktueller Status** — Entwurf, aktiv oder pausiert
- **Anzahl der Durchläufe** — wie viele Kontakte in die Automation eingetreten sind
- **Schrittfortschritt** — ein Funnel, der zeigt, wie viele Kontakte in jedem Schritt ausstehend, in Ausführung oder abgeschlossen sind
- **Fehlschläge je Schritt** — wie viele Kontakte an jedem Schritt gescheitert sind (eine Zahl, im Schritt-Funnel angezeigt)

::callout{type="warning"}
Prüfe deine Automationen regelmäßig. Eine Automation mit hoher Fehlerquote hat möglicherweise eine defekte Vorlagenverknüpfung oder referenziert eine gelöschte Vorlage.
::
