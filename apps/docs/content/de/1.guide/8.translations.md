Mit Übersetzungen versenden Sie dieselbe E-Mail in mehreren Sprachen. Statt für jede Sprache eine eigene Vorlage anzulegen, fügen Sie einer einzigen Vorlage Übersetzungen hinzu — und Owlat wählt automatisch die passende Version anhand der Sprache jedes Empfängers. Das funktioniert sowohl für Marketing-Kampagnen als auch für transaktionale E-Mails.

## So funktionieren Übersetzungen

1. Sie erstellen Ihre E-Mail in ihrer **Standardsprache** im Haupteditor.
2. Sie fügen in der Ansicht **Übersetzungen** der E-Mail eine oder mehrere weitere Sprachen hinzu.
3. Beim Versand erhält jeder Empfänger die Version, die zu seinem Feld **Sprache** passt.
4. Empfänger ohne gesetzte Sprache — oder mit einer Sprache, die Sie nicht übersetzt haben — erhalten die Standardversion.

Die Auflösungsreihenfolge lautet: die beim Versand angeforderte Sprache (nur transaktional) → die gespeicherte Sprache des Kontakts → die Standardsprache der E-Mail. Existiert für die gewählte Sprache keine Übersetzung, greift Owlat auf den Standardinhalt zurück.

## Was übersetzt wird

Jede Übersetzung speichert ihre eigene Kopie der Textinhalte für die jeweilige Sprache, während Struktur, Layout, Bilder, Farben und Gestaltung über alle Sprachen hinweg gemeinsam genutzt werden. Übersetzbar sind diese Felder:

| Feld | Woher es stammt |
| --- | --- |
| Betreffzeile | Der Betreff der E-Mail |
| Vorschautext | Der Vorschau-/Preheader-Text der E-Mail (nur Marketing-E-Mails) |
| Inhalt von Textblöcken | Überschriften und Absätze in Textblöcken |
| Schaltflächenbeschriftungen | Der sichtbare Text auf Button-Blöcken |
| Alt-Text von Bildern | Der Alt-Text auf Bildblöcken |

Text innerhalb von Spalten und Containern wird rekursiv erfasst, verschachtelte Inhalte sind also ebenfalls übersetzbar. Sie gestalten die E-Mail einmal und übersetzen nur den Text, statt sie für jede Sprache neu aufzubauen.

## Übersetzungen hinzufügen

Übersetzungen leben in einer eigenen Tabellenansicht je E-Mail, nicht im Hauptblock-Editor.

::steps

### Die Ansicht „Übersetzungen“ öffnen

Öffnen Sie die E-Mail und klicken Sie dann in der Editor-Werkzeugleiste auf **Übersetzungen**. (Marketing-E-Mails öffnen sich unter `/dashboard/send/emails/{id}/translations`, transaktionale E-Mails unter `/dashboard/send/transactional/{id}/translations`.) Sie sehen ein Raster mit einer Zeile je übersetzbarem Feld und einer Spalte je Sprache.

### Eine Sprache hinzufügen

Klicken Sie auf **Sprache hinzufügen** und wählen Sie eine Sprache aus der Liste. Owlat legt eine neue Spalte an und befüllt sie als Ausgangspunkt mit einer Kopie des Texts in der Standardsprache.

### Jede Zelle bearbeiten

Klicken Sie eine beliebige Zelle in der neuen Sprachspalte an und tippen Sie die Übersetzung ein. **Änderungen werden automatisch gespeichert**, während Sie die jeweilige Zelle bearbeiten — eine separate Speichern-Schaltfläche gibt es nicht.

### Für weitere Sprachen wiederholen

Fügen Sie so viele Sprachen hinzu, wie Sie benötigen. Jede ist unabhängig, das Hinzufügen oder Entfernen einer Sprache wirkt sich also nie auf die anderen aus.

::

::callout{type="info" title="Die Standardsprache ist hier schreibgeschützt"}
In der Übersetzungsansicht wird die Spalte der Standardsprache nur zur Referenz angezeigt und kann nicht bearbeitet werden. Um den Originaltext zu ändern, bearbeiten Sie die E-Mail im Haupteditor — diese Änderungen werden zur Quelle, aus der die anderen Sprachen übersetzt werden.
::

::callout{type="tip"}
Beginnen Sie mit Ihrer wichtigsten Zweitsprache. Sie können jederzeit weitere Sprachen ergänzen, ohne bestehende Übersetzungen zu beeinträchtigen.
::

## Automatisch übersetzen mit KI

Jede Sprachspalte besitzt eine Sparkle-Schaltfläche (✨) mit der Beschriftung **Automatisch mit KI übersetzen**. Ein Klick darauf schickt jedes *leere* Feld dieser Spalte an das von Ihnen konfigurierte LLM und trägt einen Übersetzungsentwurf ein; bereits von Ihnen geschriebene Zellen bleiben unangetastet. So erhalten Sie schnell einen vollständigen ersten Durchgang, den Sie anschließend Zelle für Zelle prüfen und nachschärfen können.

::callout{type="warning" title="Erfordert einen LLM-Anbieter"}
Die automatische Übersetzung ruft den für Ihr Deployment konfigurierten KI-Anbieter auf. Ist kein Anbieter oder API-Key eingerichtet, meldet die Schaltfläche einen Konfigurationsfehler. Wie der LLM-Anbieter konfiguriert wird, beschreibt [KI-Agent & Autonomie](/guide/ai-agent).
::

## Kontaktsprache festlegen

Die Sprachpräferenz eines Kontakts lässt sich auf zwei Wegen setzen:

- **Im Dashboard** — bearbeiten Sie das Feld **Bevorzugte Sprache** auf der [Detailseite des Kontakts](/guide/contacts)
- **CSV-Import** — nehmen Sie eine Spalte `Language` in Ihre [Importdatei](/guide/importing-contacts) auf

::callout{type="info"}
Sprachwerte sollten standardisierte Sprachcodes verwenden (z. B. `en`, `fr`, `de`, `es`). So passen Kontaktpräferenzen und Vorlagenübersetzungen zuverlässig zueinander.
::

::callout{type="warning" title="Wird nicht von Formularen oder der öffentlichen API gesetzt"}
[Formulare](/guide/forms) können keine Kontaktsprache erfassen — Formularfelder sind auf die Typen E-Mail, Text und Checkbox beschränkt, und Einsendungen schreiben nie das Feld „Sprache“. Auch die öffentliche [Kontakte-API](/api/contacts) und die [SDKs](/api/sdk) akzeptieren beim Anlegen oder Aktualisieren eines Kontakts keinen Parameter `language`. Die einzige Ausnahme ist die [Transaktionale API](/api/transactional), bei der ein Versand die für diese Nachricht zu verwendende Sprache angeben kann (siehe unten); die gespeicherte Kontaktsprache ändert sich dadurch nicht.
::

## Übersetzungen in Kampagnen

Wenn Sie eine Kampagne anlegen, wählen Sie eine Vorlage aus. Besitzt diese Vorlage Übersetzungen, gilt:

- Jeder Empfänger erhält automatisch die zu seiner Sprache passende Version
- Der Kampagnenbericht zeigt die Ergebnisse über alle Sprachversionen hinweg
- Sie müssen keine separaten Kampagnen je Sprache anlegen

## Übersetzungen in transaktionalen E-Mails

Transaktionale E-Mails unterstützen dasselbe Übersetzungssystem. Eine transaktionale E-Mail kann eigene Betreffzeilen und Blockübersetzungen je Sprache tragen, und Owlat ermittelt für jeden Versand die richtige Sprache.

- Der Versand kann über die [Transaktionale API](/api/transactional) explizit eine bestimmte Sprache anfordern. Tut er das nicht, verwendet Owlat die gespeicherte Sprache des Empfängerkontakts und danach die Standardsprache der E-Mail.
- Existiert für die ermittelte Sprache keine Übersetzung, wird der Inhalt in der Standardsprache verwendet.

Das bedeutet: Eine einzige transaktionale E-Mail — zum Beispiel eine Bestellbestätigung — kann in der jeweiligen Sprache jedes Empfängers zugestellt werden, ohne dass Sie separate E-Mails pflegen müssen.

## Bewährte Vorgehensweisen

- **Übersetzungen synchron halten** — wenn Sie die Version in der Standardsprache aktualisieren, aktualisieren Sie auch die Übersetzungen
- **Einfache, klare Sprache verwenden** — kürzere Sätze lassen sich natürlicher übersetzen und wirken über verschiedene Sprachen hinweg besser
- **Jede Sprache testen** — versenden Sie Test-E-Mails für jede Übersetzung, um zu prüfen, ob der Text sauber ins Layout passt
- **Nach Zielgruppe priorisieren** — übersetzen Sie zuerst in die Sprachen, die den größten Teil Ihrer Zielgruppe abdecken
- **KI-Entwürfe prüfen** — die automatische Übersetzung liefert schnell einen ersten Durchgang, lesen Sie sie aber vor dem Versand immer Korrektur

::callout{type="warning"}
Wenn Sie Ihrer E-Mail nach dem Anlegen der Übersetzungen neue Textblöcke hinzufügen, denken Sie daran, auch diese Blöcke zu übersetzen. Nicht übersetzte Felder fallen auf den Inhalt in der Standardsprache zurück.
::
