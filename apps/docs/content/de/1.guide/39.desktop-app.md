Die Owlat-Desktop-App ist eine native Hülle (gebaut mit Tauri), die dieselbe Weboberfläche kapselt, die Sie im Browser verwenden. Sie ergänzt das, was ein Browser-Tab nicht bieten kann: mehrere Workspaces nebeneinander, eine Session im Schlüsselbund Ihres Betriebssystems statt in einem Cookie, native Benachrichtigungen, ein Ungelesen-Badge in Dock/Taskleiste, globale Tastenkürzel und die Behandlung von `mailto:`-Links.

Die App lädt exakt dieselbe Oberfläche wie die Web-App — jede Funktion, die Sie im Web sehen, ist auch hier verfügbar. Anders ist, wie Sie sich verbinden und wie sich die App in Ihr Betriebssystem integriert.

::callout{type="info" title="Alpha"}
Die Desktop-App befindet sich in der Alpha-Phase, mit demselben Status wie der Rest von Owlat — sie funktioniert durchgängig, aber rechnen Sie mit Ecken und Kanten sowie mit Breaking Changes zwischen Releases.
::

::callout{type="info" title="Selbst verteilt"}
Die Desktop-App wird aus diesem Repository gebaut und veröffentlicht, aber Owlat betreibt keinen öffentlichen Download- oder Update-Server. Wer Ihre Owlat-Instanz betreibt, ist dafür verantwortlich, den Installer zu bauen, zu signieren und auszuhändigen. Die folgenden Schritte setzen voraus, dass Ihnen jemand bereits einen Build gegeben hat.
::

## Die Desktop-App installieren

Die App wird als üblicher Installer für macOS (universelles `.dmg`/`.app`), Windows (`.exe`/`.msi`) und Linux ausgeliefert. Installieren Sie sie so, wie Sie jede andere Desktop-Anwendung Ihrer Plattform installieren würden.

::callout{type="warning" title="Unsignierte Builds"}
Code-Signing und Notarisierung sind optional und hängen davon ab, dass der Betreiber zum Build-Zeitpunkt Signaturzertifikate bereitstellt. Ist Ihr Build unsigniert, warnen Sie macOS Gatekeeper oder Windows SmartScreen beim ersten Öffnen. Das ist bei einem intern verteilten Build zu erwarten — klären Sie es mit derjenigen Person ab, die Ihnen den Installer gegeben hat, bevor Sie die Warnung umgehen.
::

### Einen unsignierten Build unter macOS öffnen

Bei einem unsignierten Build zeigt macOS **„Owlat.app“ wurde nicht geöffnet — Apple konnte nicht verifizieren, dass „Owlat.app“ frei von Schadsoftware ist** und bietet nur *In den Papierkorb legen* oder *Fertig* an. In aktuellen macOS-Versionen umgeht Rechtsklick → Öffnen das nicht mehr. Nachdem Sie mit Ihrem Betreiber geklärt haben, dass der Build erwartungsgemäß unsigniert ist, gehen Sie so vor:

1. Klicken Sie auf **Fertig** (nicht *In den Papierkorb legen*), öffnen Sie **Systemeinstellungen → Datenschutz & Sicherheit**, scrollen Sie zur Meldung über Owlat.app und klicken Sie auf **Trotzdem öffnen**. Bestätigen Sie die Rückfrage einmal; danach öffnet sich die App normal.
2. Oder entfernen Sie das Quarantäne-Flag im Terminal:
   ```sh
   xattr -dr com.apple.quarantine /Applications/Owlat.app
   ```

Das ist ein einmaliger Schritt pro heruntergeladenem Build. Veröffentlicht Ihr Betreiber signierte und notarisierte Builds, erscheint der Dialog gar nicht erst.

### Einen unsignierten Build unter Windows öffnen

SmartScreen zeigt beim ersten Start **Der Computer wurde durch Windows geschützt**. Klicken Sie auf **Weitere Informationen** und dann auf **Trotzdem ausführen**.

Wenn Sie die App zum ersten Mal ohne verbundene Workspaces starten, öffnet sie den Bildschirm **Willkommen bei Owlat**, auf dem Sie zwischen **Bestehenden Server verbinden** (führt zum Formular **Mit Ihrem Owlat-Server verbinden**) und **Neuen Server einrichten** wählen.

## Einen Workspace verbinden

Ein „Workspace“ ist eine Verbindung zu einer Owlat-Instanz. Die App ist darauf ausgelegt, mehrere gleichzeitig zu halten, wie man es von Slack kennt, aber Sie beginnen mit einem. Der Willkommensbildschirm bietet zusätzlich **Neuen Server einrichten** an, was — neben der Verbindung zu einer bestehenden Instanz — eine brandneue Owlat-Instanz per SSH auf einem VPS bereitstellt.

::steps

### Ihre Instanz-URL eingeben

Tippen Sie auf dem Willkommensbildschirm die Webadresse Ihrer Owlat-Instanz ein — zum Beispiel `https://your-instance.owlat.app`. Sie brauchen nur die Web-URL; die App fragt den Endpunkt `/api/instance-info` der Instanz ab, um den Rest ihrer Konfiguration automatisch zu ermitteln, sodass Sie nie Convex-URLs von Hand eintippen müssen.

### Über Ihren Browser anmelden

Wenn Sie auf **Workspace verbinden** klicken, öffnet die App die Anmeldeseite dieser Instanz in Ihrem **System-Browser** statt im App-Fenster. Melden Sie sich dort wie gewohnt mit E-Mail-Adresse und Passwort an.

### Zurück in die App

Nach der Anmeldung reicht der Browser über einen `owlat://auth`-Deep-Link ein Einmal-Token an die App zurück. Die App tauscht dieses Token gegen eine Session ein und setzt Sie im Dashboard des neuen Workspace ab. Die Session wird im Schlüsselbund Ihres Betriebssystems abgelegt (macOS-Schlüsselbund, Windows Credential Manager oder der Secret Service unter Linux) — nicht in einem Cookie.

::

::callout{type="info" title="Warum über den Browser?"}
Die Anmeldung über den System-Browser hält Ihre Zugangsdaten aus der Webview der App heraus und erlaubt es der App, pro Workspace eine header-basierte, cookiefreie Session zu halten. Genau das macht mehrere gleichzeitige Workspaces möglich. Sind Sie in Ihrem Browser bereits bei dieser Instanz angemeldet, läuft der Handshake sofort durch, ohne erneut nach Ihrem Passwort zu fragen.
::

## Zwischen Workspaces wechseln

Sobald mehr als ein Workspace verbunden ist, erscheint oben in der Seitenleiste eine Leiste mit Workspace-Avataren. Jeder Avatar zeigt die Initialen des Workspace und — falls dort etwas auf Sie wartet — ein rotes Ungelesen-Badge (bei `99+` gedeckelt).

- **Klicken Sie auf einen Avatar**, um zu diesem Workspace zu wechseln. Die App lädt in ihn hinein neu, damit Session und Daten sauber aus dem gewählten Workspace kommen.
- **Klicken Sie auf die Schaltfläche `+`**, um einen weiteren Workspace hinzuzufügen — damit öffnet sich der Bildschirm **Willkommen bei Owlat** erneut.
- Von diesem Bildschirm aus können Sie einen Workspace auch **entfernen**, was Sie auf diesem Gerät abmeldet und seinen Schlüsselbund-Eintrag löscht.

Einen Workspace können Sie außerdem über das Anwendungsmenü hinzufügen — **Datei > Neuer Workspace** (`Cmd/Ctrl + N`).

## Benachrichtigungen und Badges

Das Schließen des Hauptfensters **beendet** die App — es gibt kein Tray-Symbol in der Menüleiste. Öffnen Sie Owlat wieder aus Ihrem Programme-Ordner (oder über Taskleiste / Launcher). Solange Owlat noch läuft — etwa nachdem Sie das Fenster mit dem globalen Ein-/Ausblenden-Kürzel versteckt haben —, holt dasselbe Kürzel es wieder nach vorn.

Das **Ungelesen-Badge** — das Dock-Badge unter macOS, das Taskleisten-Overlay unter Windows, das Unity-Badge unter Linux — verfolgt die Anzahl ungelesener Nachrichten in Ihrem persönlichen [Postbox](/guide/postbox)-Posteingang. Trifft neue Mail ein, löst die App eine **native Betriebssystem-Benachrichtigung** aus: Eine einzelne neue Nachricht zeigt Absender und Betreff samt Aktion **Archivieren**, mehrere zeigen eine Anzahl.

Die Prüf-Warteschlange des [Team-Postfachs](/guide/team-inbox) wird separat behandelt. Steigt die Zahl der auf Prüfung wartenden Entwürfe, löst die App eine **native Betriebssystem-Benachrichtigung** mit dem Titel „Entwürfe zur Prüfung bereit“ aus. Die Prüf-Warteschlange steuert das Ungelesen-Badge **nicht** — das tut allein die Zahl ungelesener Nachrichten in Ihrem persönlichen Posteingang.

Jeder Avatar in der Multi-Workspace-Leiste trägt sein eigenes **Live-Ungelesen-Badge** (das die Prüfanzahl des Postfachs und ungelesene Chat-Erwähnungen dieses Workspace zusammenfasst), sodass Sie auf einen Blick sehen, welcher Workspace Aufmerksamkeit braucht — nicht nur der aktive. Inaktive Workspaces werden über eine schlanke Hintergrundverbindung zu jeder Instanz, bei der Sie angemeldet sind, aktuell gehalten.

## Offline-Mail-Cache

Die Desktop-App hält eine kleine, schreibgeschützte Kopie der jüngsten Mail auf dem Gerät, sodass [Postbox](/guide/postbox) beim Start sofort öffnet und Ihr aktueller Posteingang sowie bereits gelesene Nachrichten auch dann lesbar bleiben, wenn die Verbindung abreißt. Es wird ausschließlich bereinigte Mail unverschlüsselt in der lokalen Datenbank der App auf diesem Rechner gespeichert — nie die Rohnachricht und nie irgendwohin synchronisiert.

Das ist **in der Desktop-App standardmäßig aktiv** (und in einem einfachen Browser standardmäßig aus). Schalten Sie es unter **Postbox → Einstellungen → Auf diesem Gerät** aus oder löschen Sie es dort (**Aktuelle Mail auf diesem Gerät speichern** / **Lokalen Cache leeren**). Im Offline-Betrieb zeigt Postbox ein unaufdringliches Banner, liefert die zwischengespeicherte Liste und die Texte aus und pausiert Aktionen, die den Server brauchen. Details finden Sie unter [Postbox → Offline & lokaler Cache](/guide/postbox#offline--local-cache).

## Globale Tastenkürzel und der Schnellwechsler

Die App registriert einige systemweite Tastenkürzel, die auch dann funktionieren, wenn Owlat nicht das fokussierte Fenster ist (`Cmd` unter macOS, `Ctrl` sonst):

| Kürzel | Aktion |
| --- | --- |
| `Cmd/Ctrl + Shift + O` | Das Owlat-Fenster ein- oder ausblenden |
| `Cmd/Ctrl + Shift + C` | Das Verfassen-Fenster öffnen |

Solange das Owlat-Fenster fokussiert ist, öffnet `Cmd/Ctrl + K` den **Schnellwechsler**: eine filterbare Befehlspalette, mit der Sie ohne Maus zwischen Orten springen und Schnellaktionen ausführen. Innerhalb von [Postbox](/guide/postbox) ist das die Postbox-Befehlspalette; überall sonst im Dashboard die globale Suchpalette — das Kürzel öffnet also immer genau einen Wechsler, wo auch immer Sie sind. Es ist ein App-internes Kürzel, kein systemweites, sodass `Cmd/Ctrl + K` in anderen Anwendungen nie Owlat herbeiruft.

Ein globales Kürzel tut stillschweigend nichts, wenn eine andere Anwendung diese Tastenkombination auf Ihrem System bereits belegt hat.

Die App bietet außerdem ein vollständiges natives Menü — die macOS-Menüleiste bzw. ein am Fenster angebrachtes Menü unter Windows und Linux — mit **Datei**, **Bearbeiten** (Rückgängig/Wiederherstellen/Ausschneiden/Kopieren/Einfügen/Alles auswählen), **Ansicht** (Neu laden, Posteingang, Chat, Vollbild umschalten), **Fenster** und **Hilfe** (Owlat-Dokumentation, Problem melden). **Einstellungen …** (`Cmd/Ctrl + ,`) öffnet die Desktop-Einstellungen.

## Start bei der Anmeldung und Deep Links

### Start bei der Anmeldung

Öffnen Sie in der App **Einstellungen > Desktop** (diese Einstellungen erscheinen nur in der Desktop-App, nicht in der Web-Version) und aktivieren Sie **Beim Anmelden starten**. Ist das aktiviert, startet Owlat automatisch, sobald Sie sich an Ihrem Computer anmelden, sodass es bereit ist und sein Ungelesen-Badge lebt, wenn Sie sich hinsetzen.

### `owlat://`-Deep-Links

Die App registriert das URL-Schema `owlat://`. Über den Anmelde-Handshake `owlat://auth` hinaus öffnen Links dieser Formen die passende Seite im aktiven Workspace:

| Deep Link | Öffnet |
| --- | --- |
| `owlat://thread/<id>` | Einen Thread im Team-Postfach |
| `owlat://chat/<id>` | Eine Chat-Konversation |
| `owlat://knowledge/<id>` | Einen Eintrag im [Wissensgraphen](/guide/knowledge-graph) |
| `owlat://file/<id>` | Eine Datei in [Dateien](/guide/files) |
| `owlat://contact/<id>` | Einen [Kontakt](/guide/contacts) |

### Behandlung von `mailto:`

Die App registriert sich als Handler für `mailto:`-Links. Wenn Ihr Betriebssystem ein `mailto:` an Owlat schickt, öffnet die App ein eigenes Verfassen-Fenster, das aus dem Link vorbefüllt wird — Empfänger (auch mehrere, kommagetrennt, sowie `to`/`cc`/`bcc`), der Betreff und ein Klartext-Body werden allesamt übernommen.

Damit Owlat die Anwendung ist, die sich beim Klick auf einen `mailto:`-Link öffnet, setzen Sie es in Ihrem Betriebssystem als Standard-Mail-Handler — es gibt keinen verlässlichen Weg, das programmatisch zu registrieren, daher ist es ein einmaliger manueller Schritt. **Einstellungen > Desktop** in der App zeigt die Schritte für Ihre Plattform:

- **macOS** — öffnen Sie **Mail > Einstellungen > Allgemein** und setzen Sie **Standard-E-Mail-Programm** auf Owlat.
- **Windows** — öffnen Sie **Einstellungen > Apps > Standard-Apps**, suchen Sie Owlat und legen Sie es als Handler für `mailto` fest.
- **Linux** — setzen Sie Owlat als Ihren Standard für `x-scheme-handler/mailto`, z. B. mit `xdg-mime default owlat.desktop x-scheme-handler/mailto`, oder über die Standardanwendungs-Einstellungen Ihrer Desktop-Umgebung.

## Automatische Updates

Die App ist so verdrahtet, dass sie beim Start nach Updates sucht und ein gefundenes Update herunterlädt und für den nächsten Neustart installiert.

::callout{type="warning" title="Nicht produktionsreif"}
Der Updater ist mit einem öffentlichen Schlüssel und einem GitHub-Releases-Endpunkt konfiguriert, die Verkabelung steht also. Updates funktionieren nur, wenn Ihr Betreiber signierte Builds — signiert mit dem passenden privaten Schlüssel — in diesem Release-Kanal veröffentlicht; andernfalls werden neue Builds manuell ausgeliefert. Fragen Sie Ihren Betreiber, wie Updates für Ihre Installation ausgeliefert werden.
::
