Die Owlat-Desktop-App ist eine native Hülle (gebaut mit Tauri), die dieselbe Weboberfläche kapselt, die du im Browser verwendest. Sie ergänzt das, was ein Browser-Tab nicht bieten kann: mehrere Workspaces nebeneinander, eine Session im Schlüsselbund deines Betriebssystems statt in einem Cookie, native Benachrichtigungen, ein Ungelesen-Badge in Dock/Taskleiste, globale Tastenkürzel und die Behandlung von `mailto:`-Links.

Die App lädt exakt dieselbe Oberfläche wie die Web-App — jede Funktion, die du im Web siehst, ist auch hier verfügbar. Anders ist, wie du dich verbindest und wie sich die App in dein Betriebssystem integriert.

::callout{type="info" title="Alpha"}
Die Desktop-App befindet sich in der Alpha-Phase, mit demselben Status wie der Rest von Owlat — sie funktioniert durchgängig, aber rechne mit Ecken und Kanten sowie mit Breaking Changes zwischen Releases.
::

::callout{type="info" title="Selbst verteilt"}
Die Desktop-App wird aus diesem Repository gebaut und veröffentlicht, aber Owlat betreibt keinen öffentlichen Download- oder Update-Server. Wer deine Owlat-Instanz betreibt, ist dafür verantwortlich, den Installer zu bauen, zu signieren und auszuhändigen. Die folgenden Schritte setzen voraus, dass dir jemand bereits einen Build gegeben hat.
::

## Die Desktop-App installieren

Die App wird als üblicher Installer für macOS (universelles `.dmg`/`.app`), Windows (`.exe`/`.msi`) und Linux ausgeliefert. Installiere sie so, wie du jede andere Desktop-Anwendung deiner Plattform installieren würdest.

::callout{type="warning" title="Unsignierte Builds"}
Code-Signing und Notarisierung sind optional und hängen davon ab, dass der Betreiber zum Build-Zeitpunkt Signaturzertifikate bereitstellt. Ist dein Build unsigniert, warnen dich macOS Gatekeeper oder Windows SmartScreen beim ersten Öffnen. Das ist bei einem intern verteilten Build zu erwarten — kläre es mit derjenigen Person ab, die dir den Installer gegeben hat, bevor du die Warnung umgehst.
::

### Einen unsignierten Build unter macOS öffnen

Bei einem unsignierten Build zeigt macOS **„Owlat.app“ wurde nicht geöffnet — Apple konnte nicht verifizieren, dass „Owlat.app“ frei von Schadsoftware ist** und bietet nur *In den Papierkorb legen* oder *Fertig* an. In aktuellen macOS-Versionen umgeht Rechtsklick → Öffnen das nicht mehr. Nachdem du mit deinem Betreiber geklärt hast, dass der Build erwartungsgemäß unsigniert ist, geh so vor:

1. Klicke auf **Fertig** (nicht *In den Papierkorb legen*), öffne **Systemeinstellungen → Datenschutz & Sicherheit**, scrolle zur Meldung über Owlat.app und klicke auf **Trotzdem öffnen**. Bestätige die Rückfrage einmal; danach öffnet sich die App normal.
2. Oder entferne das Quarantäne-Flag im Terminal:
   ```sh
   xattr -dr com.apple.quarantine /Applications/Owlat.app
   ```

Das ist ein einmaliger Schritt pro heruntergeladenem Build. Veröffentlicht dein Betreiber signierte und notarisierte Builds, erscheint der Dialog gar nicht erst.

### Einen unsignierten Build unter Windows öffnen

SmartScreen zeigt beim ersten Start **Der Computer wurde durch Windows geschützt**. Klicke auf **Weitere Informationen** und dann auf **Trotzdem ausführen**.

Wenn du die App zum ersten Mal ohne verbundene Workspaces startest, öffnet sie den Bildschirm **Willkommen bei Owlat**, auf dem du zwischen **Bestehenden Server verbinden** (führt zum Formular **Mit deinem Owlat-Server verbinden**) und **Neuen Server einrichten** wählst.

## Einen Workspace verbinden

Ein „Workspace“ ist eine Verbindung zu einer Owlat-Instanz. Die App ist darauf ausgelegt, mehrere gleichzeitig zu halten, wie man es von Slack kennt, aber du beginnst mit einem. Der Willkommensbildschirm bietet zusätzlich **Neuen Server einrichten** an, was — neben der Verbindung zu einer bestehenden Instanz — eine brandneue Owlat-Instanz per SSH auf einem VPS bereitstellt.

::steps

### Deine Instanz-URL eingeben

Tippe auf dem Willkommensbildschirm die Webadresse deiner Owlat-Instanz ein — zum Beispiel `https://your-instance.owlat.app`. Du brauchst nur die Web-URL; die App fragt den Endpunkt `/api/instance-info` der Instanz ab, um den Rest ihrer Konfiguration automatisch zu ermitteln, sodass du nie Convex-URLs von Hand eintippen musst.

### Über deinen Browser anmelden

Wenn du auf **Workspace verbinden** klickst, öffnet die App die Anmeldeseite dieser Instanz in deinem **System-Browser** statt im App-Fenster. Melde dich dort wie gewohnt mit E-Mail-Adresse und Passwort an.

### Zurück in die App

Nach der Anmeldung reicht der Browser über einen `owlat://auth`-Deep-Link ein Einmal-Token an die App zurück. Die App tauscht dieses Token gegen eine Session ein und setzt dich im Dashboard des neuen Workspace ab. Die Session wird im Schlüsselbund deines Betriebssystems abgelegt (macOS-Schlüsselbund, Windows Credential Manager oder der Secret Service unter Linux) — nicht in einem Cookie.

::

::callout{type="info" title="Warum über den Browser?"}
Die Anmeldung über den System-Browser hält deine Zugangsdaten aus der Webview der App heraus und erlaubt es der App, pro Workspace eine header-basierte, cookiefreie Session zu halten. Genau das macht mehrere gleichzeitige Workspaces möglich. Bist du in deinem Browser bereits bei dieser Instanz angemeldet, läuft der Handshake sofort durch, ohne erneut nach deinem Passwort zu fragen.
::

## Zwischen Workspaces wechseln

Sobald mehr als ein Workspace verbunden ist, erscheint oben in der Seitenleiste eine Leiste mit Workspace-Avataren. Jeder Avatar zeigt die Initialen des Workspace und — falls dort etwas auf dich wartet — ein rotes Ungelesen-Badge (bei `99+` gedeckelt).

- **Klicke auf einen Avatar**, um zu diesem Workspace zu wechseln. Die App lädt in ihn hinein neu, damit Session und Daten sauber aus dem gewählten Workspace kommen.
- **Klicke auf die Schaltfläche `+`**, um einen weiteren Workspace hinzuzufügen — damit öffnet sich der Bildschirm **Willkommen bei Owlat** erneut.
- Von diesem Bildschirm aus kannst du einen Workspace auch **entfernen**, was dich auf diesem Gerät abmeldet und seinen Schlüsselbund-Eintrag löscht.

Einen Workspace kannst du außerdem über das Anwendungsmenü hinzufügen — **Datei > Neuer Workspace** (`Cmd/Ctrl + N`).

## Benachrichtigungen und Badges

Das Schließen des Hauptfensters **beendet** die App — es gibt kein Tray-Symbol in der Menüleiste. Öffne Owlat wieder aus deinem Programme-Ordner (oder über Taskleiste / Launcher). Solange Owlat noch läuft — etwa nachdem du das Fenster mit dem globalen Ein-/Ausblenden-Kürzel versteckt hast —, holt dasselbe Kürzel es wieder nach vorn.

Das **Ungelesen-Badge** — das Dock-Badge unter macOS, das Taskleisten-Overlay unter Windows, das Unity-Badge unter Linux — verfolgt die Anzahl ungelesener Nachrichten in deinem persönlichen [Postbox](/guide/postbox)-Posteingang. Trifft neue Mail ein, löst die App eine **native Betriebssystem-Benachrichtigung** aus: Eine einzelne neue Nachricht zeigt Absender und Betreff samt Aktion **Archivieren**, mehrere zeigen eine Anzahl.

Die Prüf-Warteschlange des [Team-Postfachs](/guide/team-inbox) wird separat behandelt. Steigt die Zahl der auf Prüfung wartenden Entwürfe, löst die App eine **native Betriebssystem-Benachrichtigung** mit dem Titel „Entwürfe zur Prüfung bereit“ aus. Die Prüf-Warteschlange steuert das Ungelesen-Badge **nicht** — das tut allein die Zahl ungelesener Nachrichten in deinem persönlichen Posteingang.

Jeder Avatar in der Multi-Workspace-Leiste trägt sein eigenes **Live-Ungelesen-Badge** (das die Prüfanzahl des Postfachs und ungelesene Chat-Erwähnungen dieses Workspace zusammenfasst), sodass du auf einen Blick siehst, welcher Workspace Aufmerksamkeit braucht — nicht nur der aktive. Inaktive Workspaces werden über eine schlanke Hintergrundverbindung zu jeder Instanz, bei der du angemeldet bist, aktuell gehalten.

## Offline-Mail-Cache

Die Desktop-App hält eine kleine, schreibgeschützte Kopie der jüngsten Mail auf dem Gerät, sodass [Postbox](/guide/postbox) beim Start sofort öffnet und dein aktueller Posteingang sowie bereits gelesene Nachrichten auch dann lesbar bleiben, wenn die Verbindung abreißt. Es wird ausschließlich bereinigte Mail unverschlüsselt in der lokalen Datenbank der App auf diesem Rechner gespeichert — nie die Rohnachricht und nie irgendwohin synchronisiert.

Das ist **standardmäßig aktiv**, in der Desktop-App wie im Browser, und wird beim Abmelden gelöscht. Schalte es unter **Postbox → Einstellungen → Auf diesem Gerät** aus oder lösche es dort (**Aktuelle Mail auf diesem Gerät speichern** / **Lokalen Cache leeren**). Im Offline-Betrieb zeigt Postbox ein unaufdringliches Banner, liefert die zwischengespeicherte Liste und die Texte aus und pausiert Aktionen, die den Server brauchen. Details findest du unter [Postbox → Offline & lokaler Cache](/guide/postbox#offline-lokaler-cache).

## Globale Tastenkürzel und der Schnellwechsler

Die App registriert einige systemweite Tastenkürzel, die auch dann funktionieren, wenn Owlat nicht das fokussierte Fenster ist (`Cmd` unter macOS, `Ctrl` sonst):

| Kürzel | Aktion |
| --- | --- |
| `Cmd/Ctrl + Shift + O` | Das Owlat-Fenster ein- oder ausblenden |
| `Cmd/Ctrl + Shift + C` | Das Verfassen-Fenster öffnen |

Solange das Owlat-Fenster fokussiert ist, öffnet `Cmd/Ctrl + K` den **Schnellwechsler**: eine filterbare Befehlspalette, mit der du ohne Maus zwischen Orten springst und Schnellaktionen ausführst. Innerhalb von [Postbox](/guide/postbox) ist das die Postbox-Befehlspalette; überall sonst im Dashboard die globale Suchpalette — das Kürzel öffnet also immer genau einen Wechsler, wo auch immer du bist. Es ist ein App-internes Kürzel, kein systemweites, sodass `Cmd/Ctrl + K` in anderen Anwendungen nie Owlat herbeiruft.

Ein globales Kürzel tut stillschweigend nichts, wenn eine andere Anwendung diese Tastenkombination auf deinem System bereits belegt hat.

Die App bietet außerdem ein vollständiges natives Menü — die macOS-Menüleiste bzw. ein am Fenster angebrachtes Menü unter Windows und Linux — mit **Datei**, **Bearbeiten** (Rückgängig/Wiederherstellen/Ausschneiden/Kopieren/Einfügen/Alles auswählen), **Ansicht** (Neu laden, Posteingang, Chat, Vollbild umschalten), **Fenster** und **Hilfe** (Owlat-Dokumentation, Problem melden). **Einstellungen …** (`Cmd/Ctrl + ,`) öffnet die Desktop-Einstellungen.

## Start bei der Anmeldung und Deep Links

### Start bei der Anmeldung

Öffne in der App **Einstellungen > Desktop** (diese Einstellungen erscheinen nur in der Desktop-App, nicht in der Web-Version) und aktiviere **Beim Anmelden starten**. Ist das aktiviert, startet Owlat automatisch, sobald du dich an deinem Computer anmeldest, sodass es bereit ist und sein Ungelesen-Badge lebt, wenn du dich hinsetzt.

### `owlat://`-Deep-Links

Die App registriert das URL-Schema `owlat://`. Über den Anmelde-Handshake `owlat://auth` hinaus öffnen Links dieser Formen die passende Seite im aktiven Workspace:

| Deep Link | Öffnet |
| --- | --- |
| `owlat://thread/<id>` | Einen Thread im Team-Postfach |
| `owlat://chat/<id>` | Eine Chat-Konversation |
| `owlat://knowledge/<id>` | Einen Eintrag im [Wissensgraphen](/guide/knowledge-graph) |
| `owlat://file/<id>` | Eine Datei in [Dateien](/guide/files) |
| `owlat://contact/<id>` | Einen [Kontakt](/guide/contacts) |

### Behandlung von `mailto:`

Die App registriert sich als Handler für `mailto:`-Links. Wenn dein Betriebssystem ein `mailto:` an Owlat schickt, öffnet die App ein eigenes Verfassen-Fenster, das aus dem Link vorbefüllt wird — Empfänger (auch mehrere, kommagetrennt, sowie `to`/`cc`/`bcc`), der Betreff und ein Klartext-Body werden allesamt übernommen.

Damit Owlat die Anwendung ist, die sich beim Klick auf einen `mailto:`-Link öffnet, setze es in deinem Betriebssystem als Standard-Mail-Handler — es gibt keinen verlässlichen Weg, das programmatisch zu registrieren, daher ist es ein einmaliger manueller Schritt. **Einstellungen > Desktop** in der App zeigt die Schritte für deine Plattform:

- **macOS** — öffne **Mail > Einstellungen > Allgemein** und setze **Standard-E-Mail-Programm** auf Owlat.
- **Windows** — öffne **Einstellungen > Apps > Standard-Apps**, suche Owlat und lege es als Handler für `mailto` fest.
- **Linux** — setze Owlat als deinen Standard für `x-scheme-handler/mailto`, z. B. mit `xdg-mime default owlat.desktop x-scheme-handler/mailto`, oder über die Standardanwendungs-Einstellungen deiner Desktop-Umgebung.

## Automatische Updates

Die App ist so verdrahtet, dass sie beim Start nach Updates sucht und ein gefundenes Update herunterlädt und für den nächsten Neustart installiert.

::callout{type="warning" title="Nicht produktionsreif"}
Der Updater ist mit einem öffentlichen Schlüssel und einem GitHub-Releases-Endpunkt konfiguriert, die Verkabelung steht also. Updates funktionieren nur, wenn dein Betreiber signierte Builds — signiert mit dem passenden privaten Schlüssel — in diesem Release-Kanal veröffentlicht; andernfalls werden neue Builds manuell ausgeliefert. Frag deinen Betreiber, wie Updates für deine Installation ausgeliefert werden.
::
