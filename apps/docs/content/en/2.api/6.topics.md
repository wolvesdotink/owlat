---
title: 'Topics API'
description: 'List topics and manage topic membership through authenticated endpoints.'
---

List the topics contacts can be subscribed to, and add or remove a contact.

## Authentication

Listing topics needs an API key with the `topics:read` scope. Adding and
removing a contact needs `topics:write`. Pass the key as a bearer token:

```http
Authorization: Bearer <key>
```

Requests without a valid key return `401`; requests with a key that lacks the
route's scope return `403`.

## Endpoints

| Method   | Path                                          | Description               |
| -------- | --------------------------------------------- | ------------------------- |
| `GET`    | `/api/v1/topics`                              | List topics               |
| `POST`   | `/api/v1/topics/:topicId/contacts`            | Add contact to topic      |
| `DELETE` | `/api/v1/topics/:topicId/contacts/:emailOrId` | Remove contact from topic |

## List topics

```http
GET /api/v1/topics?limit=25&cursor=...
```

Topics come oldest first, a page at a time, like the [contact list](/api/contacts):
`limit` (at most 100, default 25) and the previous page's `pagination.cursor`.
Topics cannot be searched; a `search` parameter is answered with `400`.

Success response (`200 OK`):

```json
{
	"data": [
		{
			"id": "k57t0pic0000000000000000000000",
			"name": "Product updates",
			"description": "New features and changes, about once a month.",
			"requiresDoubleOptIn": true,
			"createdAt": "2026-01-10T08:00:00.000Z"
		}
	],
	"pagination": { "limit": 25, "totalItems": 1, "cursor": null, "isDone": true }
}
```

`id` is the `topicId` the membership routes below take. `requiresDoubleOptIn`
says whether the topic requires double opt-in: a contact whose subscription is
pending double opt-in counts as subscribed once they confirm their address. The
add call's `doiStatus` reports the contact's confirmation state.

## Add contact to topic

```http
POST /api/v1/topics/:topicId/contacts
```

Body accepts either `email` or `contactId`:

```json
{
  "email": "jane@example.com"
}
```

or

```json
{
  "contactId": "j57..."
}
```

Success response (`201 Created`):

```json
{
  "data": {
    "success": true,
    "contactId": "j57...",
    "topicId": "k19...",
    "doiStatus": "pending"
  }
}
```

`doiStatus` can be:

- `not_required`
- `pending`
- `confirmed`

## Remove contact from topic

```http
DELETE /api/v1/topics/:topicId/contacts/:emailOrId
```

`emailOrId` can be URL-encoded email or contact ID.

Success response (`200 OK`):

```json
{
  "data": {
    "success": true,
    "removed": true
  }
}
```
