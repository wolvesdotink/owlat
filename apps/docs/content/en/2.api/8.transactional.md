Send published transactional templates to a recipient.

## Endpoint

| Method | Path                    |
| ------ | ----------------------- |
| `POST` | `/api/v1/transactional` |

## Authentication

Requires an API key in the `Authorization` header with the `transactional:send`
scope. Requests without a valid key carrying this scope are rejected with
`401`/`403`.

## Request body

Provide either `transactionalId` or `slug`.

```json
{
	"slug": "order-confirmation",
	"email": "john@example.com",
	"dataVariables": {
		"firstName": "John",
		"orderNumber": "ORD-12345"
	},
	"language": "en",
	"attachments": [
		{
			"filename": "invoice.pdf",
			"url": "https://example.com/invoices/12345.pdf",
			"contentType": "application/pdf"
		}
	]
}
```

Fields:

- `transactionalId` or `slug` (required, one of these)
- `email` (required)
- `dataVariables` (optional flat object; each value is a string, number, boolean or `null`)
- `language` (optional language code, e.g. `en`, `de`, `en-US`)
- `attachments` (optional array) — file attachments to include with the email

### Attachments

Each attachment object has the following fields:

| Field         | Type   | Required                  | Description                                      |
| ------------- | ------ | ------------------------- | ------------------------------------------------ |
| `filename`    | string | Yes                       | The file name shown to the recipient             |
| `content`     | string | One of `content` or `url` | Base64-encoded file content                      |
| `url`         | string | One of `content` or `url` | URL to fetch the file from                       |
| `contentType` | string | No                        | MIME type (e.g., `application/pdf`, `image/png`) |

**Limits:**

- Maximum **10 attachments** per email
- Maximum **10 MB** (10 MiB, 10,485,760 bytes) total attachment size, counted as decoded bytes of `content`. Files sent by `url` are fetched later and are not part of this total.
- Send `content` as plain base64 without line breaks. This route accepts a request body of up to 14,081,056 bytes: the 10 MiB budget as base64 plus 100,000 bytes for everything else. Every field other than attachment `content` (including `dataVariables`) must fit in those 100,000 bytes, the same body limit as every other API endpoint. A larger body is rejected with `400` before it is read in full.
- An invalid attachment rejects the whole request before anything is stored, and the files of a request that is refused are deleted.

## Response

Accepted sends return queued status:

```json
{
	"data": {
		"status": "queued",
		"email": "john@example.com",
		"transactionalEmailId": "j57...",
		"slug": "order-confirmation",
		"contactId": "j58...",
		"contactCreated": true,
		"language": "en"
	}
}
```

> `transactionalEmailId` is the id of the **send record** created for this
> request (a `transactionalSends` row), not the template id. Use it to
> correlate with delivery webhooks.

## Idempotent retries

Send an `Idempotency-Key` header to make a send safe to retry after a timeout
or a `5xx`:

```http
Idempotency-Key: 3f0c1d9e-6c2b-4a51-9a3e-2f6d1b7c8e90
```

- The key is 1 to 255 printable ASCII characters without spaces, such as a UUID
  or your own order id. It is scoped to your organization.
- The first request with a key is processed normally. A repeat of the **same**
  request with that key within 24 hours queues nothing, returns the first response
  (same status and body) and carries an `Idempotent-Replayed: true` header.
- Reusing the key for a **different** request (another body or another endpoint)
  is rejected with `409` `conflict` (`reason: "idempotency_conflict"`) and has no
  effect.
- If the contact the first request named has been deleted since, a repeat
  within the 24 hours is rejected with `409` `conflict`
  (`reason: "idempotency_erased"`) and has no effect: the request already ran,
  but its response named the deleted person and is no longer kept.
- A request that was refused (for example `404` or `400`) or failed before it
  was applied stores nothing, so retrying it with the same key runs it again.
- After 24 hours the key can be used for a new request.
- Without the header, every request is processed, as before.

## Language resolution order

1. Explicit `language` in request
2. Contact preferred language (if recipient exists)
3. Template default language
4. Fallback default

## Validation and delivery checks

- The **Transactional API** feature must be enabled under **Settings → Features**;
  while it is off, requests are rejected with `403` (`reason: "feature_disabled"`)
- Template must exist and be `published`
- Template must have rendered HTML content
- Sending domain must be verified
- `dataVariables` are validated against template schema when present
