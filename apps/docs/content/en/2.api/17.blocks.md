Email templates, transactional emails and saved blocks store their content as
a JSON array of blocks, in the order they render. This page describes that
JSON for anyone who writes it without the editor: an integration, a script or
an AI agent.

## The schema

Every instance serves the JSON Schema (2020-12) of block content, without an
API key, next to its [OpenAPI document](/api#openapi-document):

```txt
GET <your API base URL>/api/v1/schemas/blocks.json
```

The same file is published at
[docs.owlat.app/schemas/blocks.json](https://docs.owlat.app/schemas/blocks.json)
for the current release. Validate blocks against it before you write them. It
has one `$defs` entry per block type, chosen by the block's `type`, with each
field's type, the required fields, the allowed values and a worked example.
The schema refuses fields a block does not list, so a misspelled field fails
validation instead of being stored and ignored.

## A block

```json
{
	"id": "greeting",
	"type": "text",
	"content": {
		"html": "<p>Hi {{first_name|'there'}}.</p>",
		"blockType": "paragraph",
		"fontSize": 16,
		"textColor": "#1f2937"
	}
}
```

- `id` is unique within the email. Translations and saved-block links refer to
  blocks by it, so keep it stable when you rewrite an email.
- `type` is one of the block types below and decides what `content` holds.
- `savedBlockRef` is set on the blocks of a linked saved block. A change to the
  saved block replaces them.

Sizes are numbers in pixels unless the field says otherwise. The `width` of an
image, a video and a divider is a percentage (1 to 100) of the space the block
sits in. Colors are CSS colors. A write turns a numeric string such as `"16"`
into a number and drops any other non-number, but the schema expects numbers.

## Nesting

Most blocks sit only at the top level. Three places hold other blocks:

- **A column** of a `columns` block holds `text`, `image`, `button`,
  `divider` and `spacer` blocks (`ColumnItem`).
- **A container**, the `items` of a `hero` and each section of an `accordion`
  hold those five and also `columns`, `social` and `container` blocks
  (`ContainerItem`).
- Containers can nest inside each other. There is no hard limit; the
  validator warns past three levels.

A block of another type in one of those places is refused by the schema and
skipped by the render.

## Column widths

A `columns` block has 1 to 4 columns (`columnCount`). Their widths come from
`ratio`, one of five presets; a single column always takes the full width.
`columns` holds one array of blocks per column, and entries past
`columnCount` are ignored.

<!-- block-reference:column-widths -->

| Ratio          | 2 columns | 3 columns                | 4 columns                      |
| -------------- | --------- | ------------------------ | ------------------------------ |
| `equal`        | 50% · 50% | 33.33% · 33.33% · 33.33% | 25% · 25% · 25% · 25%          |
| `left-wide`    | 67% · 33% | 50% · 25% · 25%          | 40% · 20% · 20% · 20%          |
| `right-wide`   | 33% · 67% | 25% · 25% · 50%          | 20% · 20% · 20% · 40%          |
| `left-narrow`  | 33% · 67% | 25% · 37.5% · 37.5%      | 15% · 28.33% · 28.33% · 28.33% |
| `right-narrow` | 67% · 33% | 37.5% · 37.5% · 25%      | 28.33% · 28.33% · 28.33% · 15% |

<!-- /block-reference:column-widths -->

## Variables

A text field can carry variables, which are filled in when the email is sent:

```txt
{{first_name}}
{{first_name|'there'}}
```

- A name is letters, digits and underscores: no spaces, dots or nesting.
- The second form has a fallback in single quotes, used when the value is
  missing or empty. The fallback cannot contain a single quote.
- Without a fallback, a missing variable becomes an empty string. A
  transactional send refuses a request that leaves out a variable the email
  uses without a fallback, unless the email marks the variable optional.
- Values and fallbacks are HTML-escaped when they go into the email body, so
  a value cannot add markup. In the subject, line breaks become spaces.
- Variables work in a text block's `html` and in other text that reaches the
  email, such as a button's `text` and `url` or an image's `alt` and `src`.

For a transactional email the values are the send's `dataVariables` (see the
[Transactional API](/api/transactional)). For a template they are the
contact's fields.

## Conditions and repeats

A top-level block can carry a `condition`, which shows it only when a variable
matches, and a `repeat`, which renders it once per item of an array variable.
Inside a `repeat`, `{{item.name}}` is the `name` of the current item (with
`itemAlias` set to `item`) and `{{$index}}` is its position, from 0. Nested
blocks, such as the blocks in a column, ignore both fields.

```json
{
	"condition": { "variable": "coupon_code", "operator": "exists" },
	"repeat": { "variable": "items", "itemAlias": "item", "maxItems": 20 }
}
```

<!-- Behaviour on the current release. Update this section when conditions and repeats resolve per send. -->

On the current release, conditions and repeats are resolved when the email is
saved, not when it is sent. The stored HTML is rendered without variable
values, so at that moment every variable is empty:

- a block with an `exists`, `equals` or `contains` condition is left out of the
  email, and one with `notExists`, or `notEquals` against a value, stays;
- a block with a `repeat` is left out, since its array variable has no items.

Variables inside the blocks that stay are still filled per send. Content that
has to appear or repeat depending on the send's data cannot rely on a
condition or a repeat yet.

## Translations

A translation stores only a block's translatable text, keyed by the block's
`id`: the `html` of a text block, the `text` of a button and the `alt` of an
image. Everything else comes from the default language's blocks. See
[Translations](/guide/translations).

## HTML in a text block

A write sanitizes a text block's `html`. Tags, attributes, URL schemes and CSS
properties outside the lists below are removed, and a style declaration stays
only when its value matches the pattern listed for it. A variable chip (a
`<span>` with `data-variable`) keeps `contenteditable` only as `"false"`.

<!-- block-reference:text-html -->

Tags kept: `<h1>`, `<h2>`, `<h3>`, `<h4>`, `<h5>`, `<h6>`, `<p>`, `<br>`, `<hr>`, `<span>`, `<div>`, `<section>`, `<article>`, `<header>`, `<footer>`, `<b>`, `<i>`, `<u>`, `<em>`, `<strong>`, `<small>`, `<sub>`, `<sup>`, `<mark>`, `<a>`, `<ul>`, `<ol>`, `<li>`, `<blockquote>`, `<pre>`, `<code>`, `<figure>`, `<figcaption>`, `<table>`, `<thead>`, `<tbody>`, `<tfoot>`, `<tr>`, `<td>`, `<th>`, `<img>`, `<picture>`, `<source>`, `<s>`, `<strike>`

| Tag            | Attributes                                                            |
| -------------- | --------------------------------------------------------------------- |
| every kept tag | `style`, `class`, `id`, `lang`, `dir`                                 |
| `<a>`          | `href`, `title`, `name`, `target`, `rel`                              |
| `<img>`        | `src`, `srcset`, `alt`, `width`, `height`, `loading`                  |
| `<source>`     | `srcset`, `media`, `type`                                             |
| `<span>`       | `data-variable`, `contenteditable`                                    |
| `<table>`      | `width`, `cellspacing`, `cellpadding`, `border`, `align`, `bgcolor`   |
| `<td>`         | `colspan`, `rowspan`, `align`, `valign`, `bgcolor`, `width`, `height` |
| `<th>`         | `colspan`, `rowspan`, `align`, `valign`, `bgcolor`, `width`, `height` |
| `<tr>`         | `align`, `valign`, `bgcolor`                                          |

URLs in `href`, `src` and `srcset` may use `http`, `https`, `mailto`, `tel`. On `<img>` they may use `http`, `https`, `cid` instead. On `<source>` they may use `http`, `https`, `cid` instead.

| Property           | Value must match                                        |
| ------------------ | ------------------------------------------------------- |
| `color`            | `/^.+$/`                                                |
| `background-color` | `/^.+$/`                                                |
| `font-size`        | `/^[\d.]+(px\|pt\|em\|rem\|%)$/i`                       |
| `font-family`      | `/^[A-Za-z0-9 ,"'\-_]+$/`                               |
| `font-weight`      | `/^(normal\|bold\|bolder\|lighter\|[1-9]00)$/i`         |
| `font-style`       | `/^(normal\|italic\|oblique)$/i`                        |
| `text-align`       | `/^(left\|right\|center\|justify\|start\|end)$/i`       |
| `text-decoration`  | `/^(none\|underline\|overline\|line-through)( \w+)*$/i` |
| `line-height`      | `/^[\d.]+(px\|pt\|em\|rem\|%)?$/i`                      |
| `padding`          | `/^[\d.\s\-a-z%]+$/i`                                   |
| `margin`           | `/^[\d.\s\-a-z%]+$/i`                                   |
| `border`           | `/^[\d.\s\-a-z#%(),]+$/i`                               |
| `border-radius`    | `/^[\d.\s\-a-z%]+$/i`                                   |
| `width`            | `/^[\d.\-a-z%]+$/i`                                     |
| `height`           | `/^[\d.\-a-z%]+$/i`                                     |
| `max-width`        | `/^[\d.\-a-z%]+$/i`                                     |

A raw HTML block keeps the same, without `<s>`, `<strike>` and without the variable chip attributes on `<span>`.

## Block types

<!-- block-reference:block-types -->

### `text`

A paragraph or heading of rich text.

| Field            | Type                                                   | Required | Description                                                                                 |
| ---------------- | ------------------------------------------------------ | -------- | ------------------------------------------------------------------------------------------- |
| `html`           | `string`                                               | yes      | The text as HTML. Tags, attributes and styles outside the text policy are removed on write. |
| `blockType`      | `"paragraph"`, `"h1"`, `"h2"`, `"h3"`                  | yes      | Whether the text is a paragraph or a heading level.                                         |
| `fontSize`       | `number`                                               | yes      | Font size in px.                                                                            |
| `textColor`      | `string`                                               | yes      | Text color (CSS color).                                                                     |
| `textAlign`      | `"left"`, `"center"`, `"right"`, `"justify"`           |          |                                                                                             |
| `lineHeight`     | `number`                                               |          | Line height as a multiple of the font size, such as 1.5.                                    |
| `fontWeight`     | `number`                                               |          | Block-level font weight (e.g. 400, 700)                                                     |
| `letterSpacing`  | `number`                                               |          | Letter spacing in px                                                                        |
| `textTransform`  | `"none"`, `"uppercase"`, `"lowercase"`, `"capitalize"` |          | Text transform                                                                              |
| `textDecoration` | `"none"`, `"underline"`, `"line-through"`              |          | Text decoration                                                                             |
| `fontFamily`     | `string`                                               |          | Per-block font family override                                                              |
| `mobileFontSize` | `number`                                               |          | Font size on mobile (rendered via media query)                                              |
| `postalAddress`  | `boolean`                                              |          | Marks the block that prints the sender's postal address, as the brand kit footer does.      |

Takes all the shared fields.

Example:

```json
{
	"id": "greeting",
	"type": "text",
	"content": {
		"html": "<p>Hi {{first_name|'there'}}, your order <strong>{{order_number}}</strong> is on its way.</p>",
		"blockType": "paragraph",
		"fontSize": 16,
		"textColor": "#1f2937",
		"lineHeight": 1.5,
		"paddingTop": 8,
		"paddingBottom": 8
	}
}
```

| ------------------ | ------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `mediaAssetId`     | `string`                        |          | Set by the media library for an uploaded `src`. Leave it out for an external URL.                                                                                                   |
| `darkStorageId`    | `string`                        |          | Set by the media library for an uploaded `darkSrc`. Leave it out for an external URL.                                                                                               |
| `darkMediaAssetId` | `string`                        |          | Set by the media library for an uploaded `darkSrc`. Leave it out for an external URL.                                                                                               |
| `linkUrl`          | `string`                        |          | Where a click on the image leads.                                                                                                                                                   |
| `height`           | `number`                        |          | Optional fixed height in px                                                                                                                                                         |

| `darkSrc`          | `string`                        |          | Alternative image source for dark mode (toggled via prefers-color-scheme CSS)                                                                                                       |

Takes all the shared fields.

Example:

```json
{
	"id": "product-shot",
	"type": "image",
	"content": {
		"src": "https://example.com/images/product.png",

		"width": 100,
		"align": "center",
		"linkUrl": "https://example.com/products/desk-lamp"
	}
}
```
