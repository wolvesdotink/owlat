Send contact events to drive segmentation and automation triggers.

## Endpoint

| Method | Path             |
| ------ | ---------------- |
| `POST` | `/api/v1/events` |

## Authentication

This endpoint requires an API key with the `events:write` scope, passed as a bearer token:

```http
Authorization: Bearer <key>
```

Requests without a valid key return `401`; requests with a key that lacks the `events:write` scope return `403`. The endpoint is rate limited to 10 requests per second, beyond which it returns `429`.

## Request body

```json
{
	"email": "john@example.com",
	"eventName": "purchase_completed",
	"eventProperties": {
		"orderId": "ORD-123",
		"amount": 99.99
	},
	"createContactIfNotExists": true
}
```

Fields:

- `email` (required)
- `eventName` (required)
- `eventProperties` (optional flat object; each value is a string, number, boolean or `null`)
- `createContactIfNotExists` (optional boolean, default `false`)

`eventName` constraints:

- must start with a letter
- allowed chars: letters, numbers, `_`, `-`
- max length: 100

## Success response

Returns `201` with the event result:

```json
{
	"data": {
		"eventId": "evt_m6e...",
		"contactId": "j57...",
		"eventName": "purchase_completed",
		"triggeredAutomations": 1,
		"contactCreated": true
	}
}
```

## Idempotent retries

Send an `Idempotency-Key` header to make an event safe to retry after a timeout
or a `5xx`:

```http
Idempotency-Key: 3f0c1d9e-6c2b-4a51-9a3e-2f6d1b7c8e90
```

- The key is 1 to 255 printable ASCII characters without spaces, such as a UUID
  or your own event id. It is scoped to your organization.
- The first request with a key is processed normally. A repeat of the **same**
  request with that key within 24 hours creates no contact and starts no automation, returns the first response
  (same status and body) and carries an `Idempotent-Replayed: true` header.
- Reusing the key for a **different** request (another body or another endpoint)
  is rejected with `409` `conflict` (`reason: "idempotency_conflict"`) and has no
  effect.
- A request that was refused (for example `404` or `400`) or failed before it
  was applied stores nothing, so retrying it with the same key runs it again.
- After 24 hours the key can be used for a new request.
- Without the header, every request is processed, as before.

## Common errors

Errors use the standard envelope `{ "error": { "category", "message", "data"? } }`:

- `404` `not_found` — contact does not exist and `createContactIfNotExists` is not enabled
- `400` `invalid_input` — invalid event name, missing required field, or malformed JSON body
- `401` — missing or invalid API key
- `403` — key lacks the `events:write` scope
- `409` `conflict` — the `Idempotency-Key` was already used for a different request
- `429` — more than 10 requests per second
