The official `@owlat/sdk-js` package provides a typed client for interacting with the Owlat API from Node.js, Bun, Deno, or any server-side JavaScript runtime.

## Installation

::code-group

```sh [bun]
bun add @owlat/sdk-js
```

```sh [npm]
npm install @owlat/sdk-js
```

```sh [pnpm]
pnpm add @owlat/sdk-js
```

::

## Quick start

```typescript
import { Owlat } from '@owlat/sdk-js';

const owlat = new Owlat({
	apiKey: 'lm_live_...',
	baseUrl: 'https://rest.api.example.com',
});

// Send a transactional email
await owlat.transactional.send({
	email: 'recipient@example.com',
	slug: 'welcome-email',
	dataVariables: { firstName: 'Mira' },
});
```

`baseUrl` is your instance's API URL: the web app shows it as **Your API base
URL** under **Settings → API → API quickstart**. It is the
`NUXT_PUBLIC_CONVEX_SITE_URL` your operator set, `https://rest.api.<your-domain>`
when the setup wizard derived it from your domain. Without `baseUrl` the client
sends requests and your API key to `https://api.owlat.app`, which is not your
instance, and logs a warning. `baseUrl` will become required.

The configuration object also takes a timeout and retry settings:

```typescript
const owlat = new Owlat({
	apiKey: 'lm_live_...',
	baseUrl: 'https://rest.api.example.com',
	timeout: 30000,
	retry: { maxRetries: 2, initialDelayMs: 500, backoffMultiplier: 2 },
});
```

::callout{type="info" title="Retries and idempotency"}
The SDK retries transient failures automatically — up to **2 retries**
(3 attempts total) with exponential backoff (500 ms base, doubling each time).
A `429` is retried regardless of method after its `Retry-After` header, up to
30 s. A longer wait (a send limit that refills in minutes, or the daily limit)
is thrown at once as a `RateLimitError` whose `retryAfter` says when to try
again. A `5xx` or network/timeout error is retried only for **idempotent
methods** (`GET`/`PUT`/`DELETE`).

`POST` sends — `transactional.send(...)` and `events.send(...)` — are retried
on a `5xx` or network error **only when you pass an `idempotencyKey`**. The
server applies a keyed request at most once per key for 24 hours and answers a
repeat with the first response, so the retry cannot send twice. Without a key a
send the server may already have processed is never replayed; those failures
surface as errors for you to handle. Pass `retry: false` to disable retries
entirely, or tune `maxRetries` / `initialDelayMs` / `backoffMultiplier`.

```typescript
await owlat.transactional.send(
	{ email: 'user@example.com', slug: 'order-confirmation' },
	{ idempotencyKey: `order-${orderId}-confirmation` }
);
```

A key is 1 to 255 printable ASCII characters without spaces (a UUID or your own
order id). Reusing it for a different request throws a `ConflictError` (409). A retry whose contact was deleted after the first attempt throws one too, since its response is no longer kept.
Idempotency keys need an Owlat server released after 0.6.16: an older server
ignores the header, so a retried send could go out twice.
::

## Resources

### Contacts

Manage contacts in your audience.

```typescript
// Create a contact
const contact = await owlat.contacts.create({
	email: 'mira@acme.io',
	firstName: 'Mira',
	lastName: 'Chen',
});

// Get a contact by ID
const found = await owlat.contacts.get('contact_abc123');

// Update a contact
const updated = await owlat.contacts.update('contact_abc123', {
	firstName: 'Mira',
	lastName: 'Chen-Lopez',
});

// List contacts with cursor-based pagination
const result = await owlat.contacts.list({ limit: 25 });
// result.data       — Contact[]
// result.pagination  — { limit, totalItems, cursor, isDone }

// Fetch the next page with the returned cursor
if (!result.pagination.isDone) {
	const next = await owlat.contacts.list({ cursor: result.pagination.cursor });
}

// Or iterate every contact automatically (follows cursors until isDone)
for await (const contact of owlat.contacts.listAll()) {
	console.log(contact.email);
}

// Delete a contact
await owlat.contacts.delete('contact_abc123');
```

### Transactional

Send transactional emails using pre-built templates.

```typescript
const result = await owlat.transactional.send({
	// Identify the template by slug or ID
	slug: 'order-confirmation',

	// Recipient
	email: 'buyer@example.com',

	// Data variables merged into the template
	dataVariables: {
		orderId: 'ORD-7291',
		total: '$142.00',
	},

	// Optional: override language
	language: 'de',
});
// result.status === 'queued'
// result.transactionalEmailId — id of the send, carried as sendId by every email.* webhook
// result.contactId, result.contactCreated, result.language
```

#### Attachments

You can attach files using base64-encoded content or HTTPS URLs:

- At most **10 attachments** per email.
- At most **10 MB** (10 MiB, 10,485,760 bytes) in total, counted as the decoded bytes of `content`. Files sent by `url` are fetched later and are not part of this total.
- `content` must be plain base64 without line breaks. MIME-style base64, wrapped every 76 characters, is rejected with a `ValidationError` before anything is sent.

See the [Transactional API](/api/transactional) for the full limits.

```typescript
// Plain base64 without line breaks (pdfBytes is a Uint8Array or Buffer)
const base64String = Buffer.from(pdfBytes).toString('base64');

await owlat.transactional.send({
	email: 'buyer@example.com',
	slug: 'order-confirmation',
	attachments: [
		// Base64-encoded content
		{
			filename: 'invoice.pdf',
			content: base64String,
			contentType: 'application/pdf',
		},
		// URL (fetched server-side)
		{
			filename: 'receipt.pdf',
			url: 'https://your-api.com/receipts/ORD-7291.pdf',
		},
	],
});
```

#### Send status

`transactionalEmailId` is the id of the send. `owlat.transactional.get(id)` reads where that send stands (`queued`, `sent`, `delivered`, `bounced`, `failed`, ...), with `errorCode` and `errorMessage` once it failed, and `bounceType`, `bounceCause` and the receiving server's reply in `errorMessage` once it bounced. Every `email.*` webhook for the send carries the same id as `sendId`, so a webhook on `email.failed` tells you about a failure without polling. See [Send status](/api/transactional#send-status).

```typescript
const { transactionalEmailId } = await owlat.transactional.send({
	email: 'buyer@example.com',
	slug: 'password-reset',
});

const send = await owlat.transactional.get(transactionalEmailId);
if (send.status === 'failed') {
	console.warn(send.errorCode, send.errorMessage); // e.g. MTA_UNREACHABLE
}
```

Without the id, `owlat.transactional.list()` finds the sends by recipient or by status, newest first, within at most the last 30 days. See [List sends](/api/transactional#list-sends) and [Debugging a missing email](/api/transactional#debugging-a-missing-email).

```typescript
const { data: sends } = await owlat.transactional.list({ email: 'buyer@example.com' });
const failedLastHour = await owlat.transactional.list({
	status: 'failed',
	since: new Date(Date.now() - 60 * 60 * 1000).toISOString(),
});
```

### Events

Send custom events to trigger automations and build segments.

```typescript
await owlat.events.send({
	email: 'mira@acme.io',
	eventName: 'plan_upgraded',
	eventProperties: {
		plan: 'pro',
		mrr: 49,
	},
});
```

### Topics

List topics and manage topic memberships. Listing needs the `topics:read`
scope; adding and removing a contact needs `topics:write`. A topic's `id` is
the `topicId` the membership calls take.

```typescript
// Find a topic by name
const { data: topics } = await owlat.topics.list();
const updates = topics.find((topic) => topic.name === 'Product updates');

// Add a contact to a topic
await owlat.topics.addContact({
	topicId: 'topic_abc123',
	email: 'mira@acme.io',
});

// Remove a contact from a topic
await owlat.topics.removeContact({
	topicId: 'topic_abc123',
	emailOrId: 'mira@acme.io',
});
```

### Status

Read whether the instance can send and, if not, why and what fixes it. Needs
the `status:read` scope. See [Status API](/api/status) for the fields and
every reason code.

```typescript
const status = await owlat.status.get();
if (status.level !== 'ok') {
	console.warn(status.reasonCode, status.explanation);
	console.warn('Fix it on', status.fix?.route, 'as', status.fix?.who);
}
if (status.sendingHold) console.warn('Suspended since', status.sendingHold.since);
```

### Domains

List the sending domains with the DNS records each needs and what the last
check found. Needs the `status:read` scope. See [Domains API](/api/domains).

```typescript
for (const domain of await owlat.domains.list()) {
	for (const record of domain.records.filter((r) => r.state !== 'found')) {
		console.log(domain.domain, record.type, record.host, record.value, record.state);
	}
}
```

## Error handling

The SDK exports typed error classes for common failure modes:

```typescript
import {
	Owlat,
	OwlatError,
	AuthenticationError,
	RateLimitError,
	NotFoundError,
	ValidationError,
	ConflictError,
	ForbiddenError,
	InvalidStateError,
	LimitReachedError,
	UnexpectedResponseError,
} from '@owlat/sdk-js';

try {
	await owlat.transactional.send({ email: 'user@example.com', slug: 'welcome' });
} catch (error) {
	if (error instanceof ValidationError) {
		console.error('Validation failed:', error.message);
	} else if (error instanceof InvalidStateError) {
		// 422 — unverified sending domain, blocked recipient, unpublished template.
		// The most common transactional failure mode.
		console.error('Cannot send yet:', error.message);
	} else if (error instanceof ForbiddenError) {
		// 403 — suspended / abuse-blocked account.
		console.error('Not permitted:', error.message);
		// While sending is suspended: whether it lifts by itself, and on what condition.
		if (error.abuseBlocked) console.error('Lifts:', error.abuseBlocked.lift?.mode);
	} else if (error instanceof LimitReachedError) {
		console.error('Plan limit reached:', error.message);
	} else if (error instanceof RateLimitError) {
		console.error('Rate limited — retry after backoff');
	} else if (error instanceof AuthenticationError) {
		console.error('Bad API key');
	} else if (error instanceof ConflictError) {
		console.error('Contact already exists');
	} else if (error instanceof NotFoundError) {
		console.error('Resource not found');
	} else if (error instanceof UnexpectedResponseError) {
		// The answer did not come from the Owlat API: check baseUrl.
		console.error('Not an Owlat API:', error.url, error.statusCode, error.bodyExcerpt);
	} else if (error instanceof OwlatError) {
		console.error('API error:', error.message, error.statusCode);
	}
}
```

| Error class               | HTTP status | When                                                                                                                                                                            |
| ------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AuthenticationError`     | 401         | Invalid or missing API key                                                                                                                                                      |
| `LimitReachedError`       | 402         | Plan or quota limit reached                                                                                                                                                     |
| `ForbiddenError`          | 403         | Authenticated but not permitted (suspended / abuse-blocked)                                                                                                                     |
| `NotFoundError`           | 404         | Resource does not exist                                                                                                                                                         |
| `ConflictError`           | 409         | Duplicate resource (e.g. existing email)                                                                                                                                        |
| `InvalidStateError`       | 422         | Resource state blocks the operation (unverified domain, blocked recipient, unpublished template)                                                                                |
| `RateLimitError`          | 429         | Too many requests                                                                                                                                                               |
| `ValidationError`         | 400         | Request body fails validation                                                                                                                                                   |
| `UnexpectedResponseError` | any         | The response is not the Owlat API's: usually a wrong `baseUrl`, or a proxy answering for the instance. Carries `url` (without the query string), `statusCode` and `bodyExcerpt` |

Every error also has `reason`, the API's `data.reason` code when it sent one (for example `domain_unverified`), typed as `ApiErrorReason`. Branch on it rather than on the message; [Refusal reasons](/api/transactional#refusal-reasons) says what each transactional one means.
