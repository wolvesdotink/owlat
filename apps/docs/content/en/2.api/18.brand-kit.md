Read and change the [brand kit](/guide/email-theme): the colours, fonts,
button style and footer every email starts from. A script or an AI agent
building templates can switch on the web font a design uses, or fill in the
company name and postal address the footer of every marketing email carries,
without opening the web app.

## Authentication

Reading needs an API key with the `brand-kit:read` scope, changing the kit
`brand-kit:write`. The template scopes grant neither. A key created before
these scopes existed does not have them: create a key in **Settings → API**
with the scopes it needs.

## Endpoints

| Method | Path                | Purpose                       |
| ------ | ------------------- | ----------------------------- |
| `GET`  | `/api/v1/brand-kit` | Read the brand kit            |
| `PUT`  | `/api/v1/brand-kit` | Change some or all its fields |

## The brand kit

```json
{
	"data": {
		"isConfigured": true,
		"primaryColor": "#0f766e",
		"secondaryColor": "#282d3a",
		"textColor": "#374151",
		"backgroundColor": "#ffffff",
		"linkColor": "#0f766e",
		"swatches": ["#f59e0b"],
		"headingFontFamily": "'Montserrat', Arial, sans-serif",
		"bodyFontFamily": "'Inter', Arial, sans-serif",
		"buttonRadius": 6,
		"buttonPaddingX": 24,
		"buttonPaddingY": 12,
		"baseWidth": 600,
		"footerCompanyName": "Example Shop GmbH",
		"footerAddress": "1 Example Street\n12345 Example City",
		"footerSocialLinks": [{ "platform": "github", "url": "https://github.com/example" }],
		"logo": { "url": "https://files.owlat.example/logo.png", "width": 160 },
		"logoDark": null
	}
}
```

`isConfigured` is `false` until the kit is saved once, on the brand kit page
or through the API. Until then every field holds its default.

## Changing it

Send only the fields to change. A field left out keeps its stored value, and
the answer is the whole kit after the write, in the shape above.

```sh
curl -X PUT "$OWLAT_API/api/v1/brand-kit" \
  -H "Authorization: Bearer $OWLAT_KEY" \
  -H 'Content-Type: application/json' \
  --data @brand-kit.json
```

```json
{
	"headingFontFamily": "'Montserrat', Arial, sans-serif",
	"footerCompanyName": "Example Shop GmbH",
	"footerAddress": "1 Example Street\n12345 Example City"
}
```

The values are checked as on the brand kit page:

- Colours are hex colours, `#rgb` or `#rrggbb`. There are at most six
  `swatches`.
- `headingFontFamily` and `bodyFontFamily` are one of the font stacks the
  brand kit page offers, spelled exactly; the OpenAPI document lists them. The
  web fonts among them load from Google Fonts in clients that fetch remote
  fonts and show the fallback named after them elsewhere, such as in Gmail and
  Outlook.
- Button radius 0 to 40 px, padding 4 to 64 px across and 4 to 32 px down,
  width 400 to 800 px.
- The company name holds at most 120 characters, the address 300. There are
  at most eight social links, each an absolute http(s) URL.

A refused value is a `400` with `invalid_input` that names the field in
`data.field`, such as `linkColor`, `swatches.2` or `footerSocialLinks.0.url`.
Nothing is stored then.

Unlike the other routes, a field the API does not know is refused, not
ignored, so a misspelt field cannot look like a change that worked. The logos
are refused too (`logo`, `logoDark`): they are files in the media library, and
only the brand kit page can set them. A write keeps the stored logos.

Any write marks the kit as configured, as saving the brand kit page does. As
there, a change does not restyle the blocks of emails that already exist; see
[how the brand kit works with existing emails](/guide/email-theme#how-the-brand-kit-works-with-existing-emails).

The audit log records the write as made by the API.

## Limits and refusals

Writes share the per-key limit of the [template writes](/api/templates#limits):
60 a minute, with bursts of 30.

| Status | `data.reason`                    | Meaning                                        |
| ------ | -------------------------------- | ---------------------------------------------- |
| `400`  |                                  | A field is refused; `data.field` names it      |
| `403`  | `missing_scope`                  | The key lacks the scope; `data.scope` names it |
| `422`  | `workspace_deletion_in_progress` | The workspace is being deleted                 |
| `429`  | `template_write_rate_limited`    | Too many template writes from this key         |
