The Owlat email editor is a block-based visual editor for building responsive, professional emails. Every block you add renders consistently across email clients — desktop, mobile, Outlook, Gmail, and Apple Mail.

## Adding blocks

The primary way to add content is through **slash commands**. Click into the editor canvas and type `/` followed by the block type to insert it.

### Content blocks

| Command | What it creates |
| --- | --- |
| `/text` | A paragraph of body text |
| `/h1`, `/h2`, `/h3` | Headings at three sizes |
| `/image` | An image block with alt text and optional link (supports [Media Library](/guide/media-library) picker) |
| `/button` | A call-to-action button |
| `/video` | A video thumbnail with play button overlay |
| `/social` | Social media icon links (17 platforms including Twitter/X, Facebook, Instagram, LinkedIn, YouTube, TikTok, GitHub, WhatsApp, Telegram, Threads, Pinterest, Discord, Mastodon, Bluesky, Vimeo, Medium, Snapchat) |
| `/table` | A data table with rows and columns (supports `stack`, `scroll`, and `hide-columns` responsive modes on mobile) |

### Layout blocks

| Command | What it creates |
| --- | --- |
| `/columns` | A multi-column layout (1 to 4 columns) |
| `/container` | A wrapper that groups blocks with shared background and padding |
| `/hero` | A full-width hero section with background image support |
| `/divider` | A horizontal line separator |
| `/spacer` | Vertical spacing between blocks |

### Advanced blocks

| Command | What it creates |
| --- | --- |
| `/accordion` | Expandable content sections |
| `/menu` | A horizontal navigation menu |
| `/list` | A styled list with custom markers |
| `/carousel` | A scrollable image carousel |
| `/progress` | A visual progress indicator |
| `/html` | Raw HTML injection for custom code (advanced) |

### Saved blocks

Your [Saved Blocks](/guide/saved-blocks) appear in the slash menu under a **Saved** group, each listed by its own name. Start typing a saved block's name after `/` to filter to it and insert it.

::callout{type="tip" title="Inserting variables"}
Personalization variables are not a slash command. Type `{{` or `@` inside a text block to open the variable picker — see [Personalization with variables](#personalization-with-variables) below.
::

## Text formatting

Within text blocks, select text to reveal the formatting toolbar:

- **Bold**, **Italic**, and **Underline** for emphasis
- **Links** — select text and add a URL
- **Alignment** — left, center, or right

To change text color, set the block's color in its settings popover — color is a block-level property, not an inline selection format.

## Block properties

Click any block to open its settings popover. Common settings include:

- **Padding** — inner spacing around the block's content
- **Background Color** — the block's background
- **Border Radius** — rounded corners
- **Full Width** — stretch the block's background to the full viewport width

Different block types have additional specific settings. For example, image blocks have alt text and link URL fields, while button blocks have button text, URL, and style controls.

## Layout with columns

Columns are the foundation of complex email layouts. Create side-by-side sections for things like image-plus-text, feature grids, or multi-product showcases.

1. Type `/columns` to insert a column layout.
2. Choose the number of columns (1 to 4).
3. Drop content blocks into each column.
4. Adjust per-column settings like background, padding, and vertical alignment.

::callout{type="tip"}
On mobile devices, columns automatically stack vertically so your content stays readable. You can also set columns to reverse their order on mobile or disable stacking entirely for columns that should stay side-by-side.
::

## Personalization with variables

Type `{{` or `@` inside a text block to open the variable picker and insert dynamic content that's replaced with contact-specific data at send time:

- Contact fields like first name, last name, and email
- Custom [Contact Properties](/guide/contact-properties) you've defined
- System variables like unsubscribe links

Variables make your emails feel personal without creating separate versions for each recipient.

## Conditional content

Show or hide sections of your email based on a contact's data. For example, display a premium CTA only for contacts on a paid plan, or show different content based on a contact's language or location.

Conditional blocks evaluate a contact's property values at send time and include or exclude content accordingly.

## Repeat blocks

A block can be repeated once for each item in an array variable — useful for order line items, product lists, or recommendations. In the block's settings panel, set the array variable to iterate over, an item alias to reference each entry (`{{item.key}}`), and an optional maximum number of items. The renderer expands the block for every array element at send time.

## Responsive design

Your emails are automatically responsive:

- Columns stack on small screens
- Images resize to fit the viewport
- Font sizes can be adjusted for mobile readability
- Individual blocks can be set to **hide on mobile** or **hide on desktop** for tailored experiences

## Dark mode

Emails include automatic dark mode support. When a recipient's email client is set to dark mode, your email adapts. You can also configure per-block dark mode overrides and provide alternative images that look better on dark backgrounds.

## Focus mode

Press **Cmd+Shift+F** (Mac) or **Ctrl+Shift+F** (Windows) to enter focus mode for distraction-free editing. The sidebar panels hide and the editor canvas expands to fill your screen.

## Undo & redo

Every edit is tracked in a history stack. Use the **Undo** and **Redo** buttons in the toolbar, or press **Cmd+Z** / **Ctrl+Z** to undo and **Cmd+Shift+Z** / **Ctrl+Shift+Z** to redo. The buttons disable themselves when there's nothing left to undo or redo.

When you edit together with others, undo and redo step through your own edits only. A change a teammate made stays in place.

## Saving your work

How saving works depends on what you edit.

**Draft templates save themselves.** A moment after you stop editing, the draft template is saved on the server. Where the **Save** button used to be, the toolbar shows where your edits stand:

- **Saved · 3s ago**: the server holds everything the editor shows.
- **Saving…**: a save is on its way.
- **Unsaved changes**: a teammate's changes in the shared draft are not saved to the template yet. Their editor saves them; see [Editing together](#editing-together).
- **Offline, not saved yet**: the server cannot be reached. Your edits are saved once the connection is back; keep the tab open until then.
- **Not saved** with **Retry**: the server refused or failed the save. Hover the status to see why.

Edits are not kept on this device. Until the server has saved them, leaving the template asks first (**Save**, **Discard**, or stay on the page), and reloading or closing the tab shows the browser's own warning. Nothing brings edits back after a browser crash, a forced close, or once you dismiss that warning, so wait for **Saved** before you close the tab.

- **Save** in that prompt, and the **S** shortcut, save everything the editor shows right away, teammates' changes in the shared draft included. The prompt lets the page go only once the server holds all of it.
- **Discard** drops what has not been saved or sent yet. A save that was already on its way may still land.
- **Publish** first saves everything the editor shows, teammates' changes included, and publishes only once the template holds it.

Autosaves by one person share one entry in the template's version history per 10-minute slice of the clock; a publish, a send or an editing conflict in between starts a new entry. Owlat looks for that entry among the newest 20 saved versions of the slice, so with more people saving the same template at once, an autosave may add an entry of its own.

**Published templates, transactional emails and saved blocks** are saved manually. Use the **Save** button in the toolbar; while it's writing, the button shows a spinner and reads **Saving...**. If you try to leave the editor with unsaved edits, Owlat prompts you to save or discard them first.

## Version history

**History** in the editor toolbar lists the template's saved versions. A version is captured when the template is saved, published or sent in a campaign, and an editing conflict keeps the version it replaced. Two events of the same kind in a row that change nothing share one version, so sending an unchanged template twice adds a single send version. The newest 50 are kept. For each version you can:

- **Preview** it on its own.
- **Compare** it with the editor as it is now, unsaved edits included. The two versions render side by side with the changed blocks outlined (added, removed, edited, moved), followed by a list of the subject, copy and link changes. Comparing changes nothing.
- **Restore** it. The version loads onto the canvas as one more undoable edit. A draft template then saves it like any other edit; a published template stores it only when you press **Save**.

The campaign **Review** step uses the same comparison: it says whether the email changed since the last campaign that sent it, and **Compare** shows what changed.

## Editing together

Email templates (including the content of your campaigns) and transactional emails can be edited by several people at once. Everyone who has the email open works on the same draft, and every change shows up for the others as soon as it is made.

- **Who is here.** The avatars in the toolbar show who else has the email open. The block each person has selected gets an outline in their colour with their name.
- **Edits merge.** Changes to different blocks never get in each other's way: two people can rewrite two paragraphs, add blocks or reorder them at the same time. A block counts as one unit, including everything inside it, so the columns of one columns block are a single block.
- **One person per block.** As soon as someone starts changing a block or typing in it, the block shows **Name is editing** and a lock, and you cannot select it until they move on. If their tab closes or goes to the background, the block frees up within about 20 seconds.
- **Text appears when it is committed.** Text you type in a block reaches the others when you leave the block, the same moment it becomes part of the draft.
- **When two changes collide.** If two people still change the same block at the same moment (for example on a slow connection), the later change wins. The person whose change was replaced sees a notice with **Put mine back**, which restores their version as a normal, undoable edit. For email templates, the version that was replaced is also kept in the template's version history (**History** in the editor toolbar) as **Before an editing conflict**.

Saving writes the shared draft: every save (a draft template saving itself, **Save**, or **Publish**) writes everything that has reached the shared draft, from everyone, and never writes an older copy over someone's newer change. The shared draft is not the template, though: until a save writes them, the changes in it are unsaved. In the background, a draft template saves after your own edits, and after teammates' changes only once nobody else is left in the editor to save them; until then your status reads **Unsaved changes**, and leaving asks first. **Save** in that prompt, the **S** shortcut and **Publish** write everyone's changes at once. While the prompt is open, your new edits are not sent to the others. **Discard** then drops only what has not reached them yet, also when you are alone in the editor; what you already shared stays in the shared draft, and a save already on its way may still land. Only **Load latest** in a conflict resets the shared draft to the saved template. On a published template or a transactional email, the prompt only appears when you are the last person in the editor and an edit could still be lost. A shared draft that nobody has open for an hour is dropped, so unsaved changes do not linger.

Only members who can edit email templates (owners and admins) take part in editing together. Seeing who else is in the editor does not need any setup or feature flag.

## Preview

Use the preview panel to see how your email will look before sending. The preview uses the same rendering engine as your sent emails, so what you see is what your recipients will receive. The panel includes:

- A **device switcher** — preview at desktop, tablet, or mobile widths
- A **dark-mode toggle** to check how the email adapts in dark clients
- A **code view** to inspect the generated HTML source
- An **email health score** that surfaces rendering and deliverability warnings as you build

::callout{type="tip"}
Preview often as you build — especially after adding columns or conditional content. Catching layout issues early saves time.
::

## Check email

Click **Check email** in the toolbar to run the campaign pre-send checks on the email as it is now, saved or not: size against Gmail's clipping limit, broken links and link addresses, images, contrast in light and dark mode, the sending server's content screening, the subject line, the unsubscribe link and the postal address. **Show me** next to a finding closes the dialog and selects the block it comes from. See [Pre-send checks](/guide/send-campaign#pre-send-checks) for what each check looks at.

## CSS animations

Blocks can use built-in CSS animations for progressive enhancement. Add the `owlat-animate-fade-in` or `owlat-animate-slide-up` class to a block's CSS class field (the field is a raw passthrough, so use the exact class name). Animations respect `prefers-reduced-motion` and only play when the user allows motion. They work in Apple Mail and iOS Mail; other clients silently ignore them.

## Gmail Promotions annotations

If you send to Gmail users, you can add Promotions tab annotations to display rich cards (logo, deal badge, promo code, expiration date) directly in the inbox. These are not set from the visual editor — they're a developer feature configured through the renderer's render options, so they can't be added from the dashboard. See the [Email Renderer](/developer/email-renderer) docs for details.
