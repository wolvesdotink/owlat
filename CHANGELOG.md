## [0.5.3] - 2026-09-21

Three fixes to things that had gone visibly wrong: message bodies rendering as
ciphertext, the Reply Queue asking for answers to mail nobody can answer, and a
failed in-app update leaving an instance dark with no explanation.

**Upgrading.** No schema change. Threads the Reply Queue flagged under the old
rules keep their flag until something touches them, so a mailbox with a stale
queue can be re-checked on demand with
`convex run migrations/0045_recheck_needs_reply:run '{"mailboxId":"..."}'`.
The read is bounded to one queue page and re-enqueueing is idempotent, so it is
safe to re-run.

### Fixed

- **Message bodies are unsealed at the read boundary.** Opening a message in
  the Postbox rendered `atrest:1:<iv>:<ciphertext>` instead of the mail. At-rest
  sealing routed every reader that names a body field through the accessors, but
  the list views, the search, the split-inbox sections, the by-id reads and the
  team-inbox queues name no body field at all — they return whole documents, so
  they slipped past both the migration and its ratchet. Whole-row accessors now
  cover every read that hands rows to a client, rewriting only the body columns
  a row actually has, so a body stored as a blob keeps its inline columns absent
  and the lazy fetch still fires. (#743)
- **Only mail that actually wants a reply reaches the Reply Queue.** Asked
  "does this need a reply?", a cheap model hunts for anything actionable, so an
  auto-generated meeting-notes mail full of action items came back true: the
  queue flagged it "Needs you" and pre-generated a draft that opened by
  explaining the sender is a no-reply address. Both stages are tightened. The
  deterministic screen now carries `Auto-Submitted` and `List-Id` through from
  ingest on both the hosted and IMAP paths, matches unattended senders per token
  so `drive-shares-noreply@` and `github-notifications@` are caught alongside
  `no-reply@`, and rejects a publishing address mailing an informational subject
  on the combination of the two. The model stage names the message from a closed
  intent taxonomy instead of returning a boolean, and the taxonomy decides what
  belongs in the queue. (#744)
- **A failed update restarts the stack instead of leaving it dark.** Every step
  of an in-app update is ordered so that failing it changes nothing — except the
  last. Compose recreate is "create new, stop old, start new", so a `docker
  compose up` that dies mid-way leaves the old containers stopped and the new
  ones never started; the handler answered with a bare "docker compose up
  failed" and returned, and the operator got a site that no longer loaded and
  nothing in the logs. A failed recreate is now followed by a plain `up -d` over
  the same services, which is exactly what finishes a half-applied recreate. The
  response says which of three things happened — serving again, these services
  are still down, or the API could not be read back — and the last two carry the
  host command that fixes it. The same recovery covers applying feature profiles
  and rotating secrets, and the rotation path now checks the exit code instead
  of grepping stderr for "error", which reported 200 for a rotation that
  recreated nothing. (#742)

## [0.5.1] - 2026-09-21

A full-source security audit (2026-09-20) and its eleven remediations, plus the
response-disposition agent: Owlat now works out whether a message actually wants
a reply instead of drafting one for every shipping notice and thank-you.

**Upgrading.** Deploy the API and web changes together — the new upload bridge
fails closed if only one side moves — then run
`migrations/0044_private_chat_media:run` before reopening ordinary traffic. The
migration is bounded and idempotent; it repairs chat media tags that old library
edits removed and classifies duplicate storage aliases, privatizing shared assets
that were posted in chat (upload a separate shared copy where one is needed).
`SITE_URL` must point at the web origin, and `INSTANCE_SECRET` must match in both
web and Convex. Upload URLs minted before the rollout have to be retried. Full
detail in [`docs/security/2026-09-20/README.md`](docs/security/2026-09-20/README.md)
and the self-hosting maintenance guide.

### Added

- **The inbound agent classifies response disposition.** Every non-spam message
  used to get a draft. Classify now decides whether the sender expects a reply,
  detects the language they wrote in, scores importance and writes a
  one-sentence summary per interface locale. A confident "no reply needed"
  parks the message in a new `informational` state instead of drafting;
  complaints, urgent mail, escalations, questions and requests always keep the
  reply path. (#697)
- **Drafts are written in the sender's language**, primary and alternates.
  Clarification questions are translated into every interface locale, and the
  person responsible — assignee, else every shared-inbox reader — is notified
  through the assignment-notice channel instead of waiting silently. (#697)
- **An Updates page for mail that needs no reply**, ranked by importance, split
  into Updates / Promotions / Notifications / Spam tabs. A reader can dismiss a
  message or overrule the classifier and request a draft. The classifier also
  names the kind of mail (personal, update, notification, receipt, newsletter,
  advertising); the four bulk kinds are informational whatever intent label they
  got. (#697)
- **Answer memory for clarification questions.** A question answered before
  arrives with that answer pre-picked and labelled "last time"; any other chip
  or typed text replaces it and becomes the new standing answer. Answer chips
  now say what they are, and a read-back line shows what will be submitted.
  (#697)
- **Spam and promotion filing in the personal Postbox.** A spam label moves the
  thread's inbox messages to the Spam folder and recategorizing brings them
  back; the per-sender override stops the classifier filing that sender as spam
  again. The Spam tab lists what the classifier archived, with blocking the
  sender as its one action. (#697)
- **Structured crash logging and graceful shutdown for the sidecars.** (#701)
- **An any-of feature-flag floor.** A gated surface does not always hang off a
  single flag — the Postbox is reachable through hosted mailboxes (`postbox`)
  or a connected external one (`mail.external`), and chaining `featureGated`
  twice gives AND, not OR. `assertAnyFeatureEnabled` reads storage once for the
  whole set and refuses naming every listed flag; `featureGatedAny` composes it
  onto an authed builder. The Postbox function family is the first user, and
  `ai.visualizations` is now enforced on the backend rather than only on the
  route. (#714)

### Security

All findings below come from the 2026-09-20 source audit and are remediated in
this release. Severities are the audit's own.

- **High — code-worker ran Git with credentials in its argv**, readable by the
  sandbox UID, and a root-owned `.git` could be replaced through its parent.
  Credentials are out of the argv and the directory is protected. (#724, #712)
- **High — sandbox processes survived task completion or cancellation.** The
  dedicated sandbox UID is now reaped through a same-UID helper, and the worker
  stops if cleanup fails. Requires the shipped PID namespace, a positive
  dedicated UID/GID and one job at a time. (#724, #713)
- **High — private chat uploads were reachable by any authenticated member**
  through shared media, export and URL paths. They are excluded from those
  paths, alias registration and private-file reuse are blocked, and legacy
  classification is repaired by migration 0044. (#730, #716)
- **High — an authenticated caller who knew another resource's storage ID could
  bind it.** Uploads now carry server-attested receipts binding the blob to
  user, organization and resource, and binding, transfer and destructive
  cleanup are gated on them. (#730, #717)
- **High — a member with a pending higher-role invitation could accept it
  without owning the invited address** under a legacy verification setting.
  Invited email ownership is always verified before membership is granted.
  (#728, #719)
- **Medium — streamed requests bypassed post-read body limits.** Byte limits are
  enforced while the stream is consumed, including UTF-8 and multipart framing,
  and overflow is cancelled without waiting on the producer. (#730, #710)
- **Medium — the auth callback accepted its redirect origin** and fetched the
  target server-side. Upstream redirects and cookies are relayed instead.
  (#727, #711)
- **Medium — a malicious unsubscribe target could be reached** from the server.
  Unsubscribe now uses a DNS-aware guarded transport with connect-time address
  checks and redirects disabled. (#730, #715)
- **Medium — first-account public signup was open on an exposed production
  instance before setup.** It is blocked outside explicit development mode; the
  trusted seed endpoint still works. (#728, #720)
- **Medium — an authenticated caller could forge upload size metadata.** Native
  storage sizes are read before resource binding or outbound buffering, and
  per-file, count and aggregate limits — inline images included — are enforced
  against the real bytes. (#730, #732)
- **Dependency advisories** resolved with compatible patched versions; the two
  remaining high image-size advisories keep their existing repository patches
  and parser regressions. (#729, #718)
- Addresses and subjects are redacted from Convex process logs and sidecar pino
  output, and gated out of process logs by a lint rule. (#704)
- PostHog capture is gated on the `analytics.posthog` flag on both the backend
  and the client, honours revocation before initialization, and identifies by
  id only — no email, no name. (#705)
- The proxy and static-site images run as non-root, and the updater runs
  privileged commands with an argv rather than a shell. (#701)

### Changed

- The organization permission map moved into `@owlat/shared`, and `usePermissions`
  is built on it, so the web gates and the backend cannot drift apart. Share
  links, topic-membership removal and content-domain writes are now gated on the
  permission they actually need, and the audience hub stops offering three
  creates an editor cannot perform. (#734)
- IMAP folder reads are paged and the change feed is served off its index, so a
  large folder no longer scans. A paging walk that cannot finish now fails
  instead of silently truncating. (#706)
- Agent-metric retention runs on a daily cron and the rollup window is written in
  one transaction (#702); retention cron registrations are grouped under
  maintenance (#700).
- The segment count scan is bounded and checkpointed. (#709)
- Addresses are parsed through the `mail-message` parser everywhere instead of a
  second implementation in shared. (#733)
- The dev, seed and sample-data routes moved onto the shared error envelope, and
  the update endpoint became its own module. (#696, #708)
- 32 Convex indexes that nothing queries were dropped, with a gate to keep new
  ones from accumulating. (#703)
- `imapflow` 2.0.5, `nodemailer` 10.0.10, and the grouped npm minor/patch
  updates. (#735, #736, #739)

### Fixed

- **web**: route guards leaked a Convex subscription per navigation, and
  detached subscriptions were not disposed during hot replacement; queries now
  re-subscribe on args value rather than identity, and `useAuth` is built once
  per `useOrganization` call. (#700)
- **web**: a member's thread page called the admin-only seen marker, and
  `markThreadSeen` is now gated on the shared-inbox floor ADR-0040 set. (#708)
- **web**: transactional snippets pointed at the wrong origin; they are built
  from this deployment's site URL. (#708)
- **api**: `/api/v1/health` answers on an unconfigured deployment, `/sealed-blob`
  answers preflights and keeps CORS on its refusals and when no allow-list is
  configured, and `/attachment-share/` returns the error envelope instead of
  `text/plain`. (#708)
- **api**: `feature_off` is carried through the message gate, the pinned read is
  softened, and the clarification localizer is kept out of the V8 isolate. (#714)
- **api**: the cron sweep walked the wrong batch membership. (#709)
- **mail-sync**: absent messages are handled under ImapFlow 2. (#736)
- **mail-message**: list separators are stripped from a parsed address. (#733)
- **updater**: a rollout no longer tears down its own plumbing, a failed update
  says why, and the Docker socket proxy answers what `compose up` and
  `compose run` need. (#696)
- **docker**: the shared dependency closure is carried into every image (#733),
  and `tsconfig.base.json` is copied into every context that needs it (#698).

## [0.5.0] - 2026-09-20

The team inbox can receive, scan, show and download attachments. Section
navigation for Administration, Preferences, Mail, Chat and Assistant moved into
the main sidebar, so those areas no longer spend a second column on it.

### Added

- **Attachments on received mail.** A message that arrives in the team inbox with files attached now says so. The thread view lists every attachment with its name, size and type, and each one downloads through a signed URL. Before this, `attachmentMeta` was a write-only column: nothing in the web or desktop app read it, and an inbound message with attachments looked exactly like one without. (#695)
- **A standalone inbound route that carries the bytes.** `inbound.received` arrives on `/webhooks/mta-inbound` with the raw MIME and addressable part indexes. The old `/webhooks/mta` pipeline capped a request body at 5 MiB before authenticating it, which no message carrying its own attachments can live with. (#695)
- **The assistant can read inbound attachments, under three ceilings.** The existing 10-part cap stays, a single attachment over 4 MiB is not embedded, and a per-organisation and per-sender budget is charged before ingest runs. A file past any ceiling still delivers, still lists and still downloads, and the row records which ceiling stopped it instead of leaving the reader to guess. (#695)
- **Admin-configurable retention for inbound mail files**, defaulting to 90 days. The sweep releases the stored blobs and keeps the rows, and a swept message says so rather than offering a download that cannot work. (#695)
- **Verified ARC results reach the team inbox** alongside the SPF, DKIM and DMARC verdicts already carried there. (#695)

### Changed

- **Section navigation lives in the main sidebar** for Administration, Preferences, Mail, Chat and Assistant. "App navigation" switches back, with focus restoration, a transition, and reduced-motion support. (#694)
- **One set of control sizes across the app**: 36px default, 32px compact, 48px for large actions, and 44px touch targets, with button and input proportions matched. Page actions were oversized for their content and the compose split button had uneven halves. (#694)
- **Tighter dashboard setup cards, page descriptions, empty-state hierarchy and navigation spacing.** (#694)

### Fixed

- **Only attachments the malware scan cleared are indexed or fed to a model.** A leaf the scan never opened is no longer reported as clean, a quarantined message will not mint a signed URL for its raw `.eml`, and every leaf a reader can download is scanned. Where a file is skipped, the log names what stopped it. (#695)
- **A retry no longer duplicates an inbound message.** (#695)
- **Mail with header names Convex cannot store is delivered without them** instead of being lost outright. (#695)
- **Deleting a message deletes its bytes**, on every path that has them, and purging a workspace purges its sealed inbound `.eml` files. (#695)
- **Unsigned traffic can no longer 429 the MTA.** The raw webhook route verified the body against the shared rate-limit bucket before checking the signature, so forged requests could spend the budget real deliveries needed. (#695)
- **The file-type scanner is harder to fool and harder to break.** It reads an OLE2 container by its name before calling it an installer, and a sender-chosen filename is bounded to something an HTTP header can actually carry. (#695)
- **Escape closes the compose menu without also changing the mail view underneath.** (#694)
- **Nested settings layouts no longer blank out** while switching between them. (#694)
- **The owl logo is visible in dark mode.** (#694)
- **A failed raw `.eml` fetch is not cached as the message.** (#695)

### Documentation

- The inbound-route change is reflected in the API reference and its German translation, and `inbound.received` points at `/webhooks/mta-inbound`. (#695)
- The inbox documentation states that reading attachments needs the scan sidecar, not just storage, and the agent-pipeline notes say what the no-scanner fallback leaves out. (#695)

## [0.4.18] - 2026-09-18

### Fixed

- **"Update now" works on a release install again.** Pressing it answered 500 for every operator: the route opened its audit row through an internal Convex function over a session-authed client, which resolves public functions only, and the rejection took the request down before the updater was ever dispatched. Both record mutations are platform-admin-gated public mutations now, `initiatedBy` is stamped from the admin's session instead of trusted from the caller, and recording is best-effort — an operator reaching for "Update now" is often reaching for it *because* something is unwell, so a Convex that cannot take the audit write must not block the update that fixes it. A static guard keeps `apps/web/server` from importing `internal` at all, since the two visibilities are indistinguishable at runtime and no test could have caught this. (#687)
- **The updater no longer refuses the release compose file.** Its image allowlist covered the installer's VPS template but not the release template both update routes actually download, so validation rejected it outright — `Disallowed image: caddy:2.8-alpine` — before any docker command ran. (#687)
- **A successful update now moves the version pin.** Nothing in the update path rewrote `OWLAT_VERSION` in `.env`, so compose kept interpolating the old version into every container: the dashboard reported the old release as installed with the same update still pending, and `/health` reported permanent version drift. (#687)
- **The update log stops calling a healthy update failed.** Each step's outcome was inferred from whether it wrote to stderr — but docker writes pull and recreate *progress* there on success, so a clean update painted "Pull new container images" and "Recreate containers with new versions" red and offered ` web Pulled` as the error. The list now reads the sidecar's real per-step verdict, falling back to the old reading only for steps that have none. (#687)
- **Admin and preferences no longer flash a white page on navigation.** Both used `NuxtLayout` as their render root; under global out-in layout transitions a navigation could remove the leaving layout without mounting the next one, emptying `#__nuxt`. (#689)

### Documentation

- The platform-operations reference now describes the version pin the sidecar moves during an update, and records that a failed audit write does not stop the update. (#687)

## [0.4.17] - 2026-09-17

### Added

- **Network port checks**: System & Updates now shows which ports an instance actually depends on and whether each one is reachable from outside. Every feature declares the ports it needs (submission, MX, IMAP, HTTP), the updater probes them, and the card reports "could not tell" where the probe was inconclusive rather than claiming all clear. (#662)
- **Disconnect a connected mailbox**: a connected IMAP mailbox can be disconnected from the UI, and an owner can now delete a mailbox an admin removed out from under them. (#686)

### Fixed

- **Connected mailboxes now actually import.** `Buffer` does not exist in the Convex V8 runtime, so every message an IMAP-connected mailbox synced or imported threw on the first line of the ingest action — while the migration reported itself complete. The hosted MX inbound path carried the same defect. CI now gates Node globals in the isolate runtime so it cannot come back. (#667)
- **Large messages import too.** The raw `.eml` used to travel as a base64 function argument, and Convex caps a function-call body at 16 MiB, so anything over ~12 MiB of source was rejected by the backend before any ingest code ran. It is uploaded out of band now, and message size no longer decides whether a message imports. (#667)
- **An import that loses mail says so.** A run that stored nothing now fails instead of reporting a complete import, and one that left some messages behind says how many and that they are still on the server. A failed ingest no longer counts as an imported message. (#667)
- **Message storage stops leaking and over-charging.** A message blob is freed only when its last row goes, the `/dev/reset` wipe no longer strands blobs, an IMAP COPY is charged against the mailbox byte counter, GDPR erasure drops the attachment index rows, and inbound deliveries are audited with a digest instead of a second copy of the message. (#664)
- **Redis no longer grows without bound.** Temporary suppressions actually expire (and an explicit TTL is ignored for permanent ones), the suppression sweep is one atomic script that keeps working at the memory cap, an address's observation counters retire with the address, the two daily counters that shipped without a TTL now expire, `keepFailed` bounds the failed queue, inbound attachments are no longer copied into Redis, per-IP SMTP counters cost one round trip, and the IMAP auth rate-limiter's key space is bounded. (#659, #661, #663)
- **The queue inspector reports the real queue.** It reads the queue GroupMQ actually writes, `/queue/jobs` reports `bytes` in bytes, a delayed job reports when it is due rather than a delay it no longer has, `/queue/pending?domain=` resolves against the groups instead of a sample, and `remove.lua` refuses a reserved job inside the script rather than around it. A delay set holding jobs with no message left to send is now detected. (#658, #660)
- **Implicit TLS on 465 fails cleanly.** The handshake is bound at 30 seconds, a peer whose handshake Node abandons is dropped, the socket is released before a failed handshake is reported, and a handshake window Node would have silently ignored is rejected outright. (#666)
- **Delivery and webhook records survive odd input.** The delivery audit row is kept when the MTA sends an unexpected payload, a disputed webhook body retains four times more content, and the envelope is measured alongside it. (#664)
- **The failed-job trim no longer collects a reused job id**, and a retry delay dictated by a remote server is bounded. (#658, #659)
- **VPS template**: the generated template now carries the variables its compose file demands. (#657)

### Documentation

- Self-hosting docs now list the inbound and outbound ports, size the Redis memory cap against send volume, size the suppression list and say when it expires, and document `IMAP_RUNTIME_USER`. The MTA docs describe the queue endpoints as they now behave, document the implicit-TLS listener and its handshake window, cover the remote-delay ceiling and delay-set integrity, and no longer point operators at a `FLUSHALL` that destroys DKIM keys.

## [0.4.14] - 2026-09-16

### Added

- **Sending domains can keep their existing mail provider**: adding a domain always handed over an apex MX record pointing here, plus an MTA-STS policy — destructive guidance for a domain whose mail lives on Google Workspace or Microsoft 365, where it takes inbound mail away from the provider and the generated SPF omits the provider the customer still sends from. - **Desktop "connect an existing server" works again**: two auth plugins exported a verify endpoint under the same key and the wrong one won the merge, so the cross-domain verify path the desktop app redeems its one-time token against answered an empty 404 on every handshake.

## [0.4.8] - 2026-09-15

### Added

- **Server-managed desktop updates**: the instance a desktop app is connected to now decides which build that app is offered. Admin → Instance settings holds the policy — latest, a pinned release or paused, the stable or pre-release channel, and a defer window — and the server caches each release's signed manifest and serves it back verbatim, which the app checks instead of one hard-coded GitHub URL. An instance older than the route, a plain-http one, or no workspace at all still falls back to GitHub, and the device verifies the bundle signature either way: an operator can withhold a build, never substitute one.

### Fixed

- **Desktop icons render again**: every icon is inline SVG now, instead of a stylesheet the app wrote at runtime to mask a `data:` URL — a chain the Tauri webview can refuse, and when it does, each icon is an empty box with nothing in the console. The bundle those icons are drawn from was also missing every name declared outside a component (36 of them) and the whole shared component layer, which no build ever complained about; the lint now fails on an icon name that does not exist or cannot be bundled.
- **Server setup DNS table**: the SPF, DMARC and PTR notes print their text instead of a raw translation key.

The Postbox reader shows verdict-driven badges — Signed · verified (with fingerprint) / signature invalid / sender key not found / sender key changed — replacing the hardcoded "not verified" label. ## [0.4.0] - 2026-08-04

The largest release since the project opened up: a first-party plugin platform, the removal of every third-party mail library from the runtime path, a rebuilt DNS setup flow, and a deliverability system that measures its own ramp instead of guessing it.

### Added

- **Plugin platform**: Owlat is now extensible across three trust tiers. `@owlat/plugin-kit` defines the public contract (manifests, contributions, capabilities), `@owlat/plugin-host` enforces it through a central kernel, and `@owlat/plugin-codegen` composes bundled plugins into the app at build time. Plugins contribute nav items and settings panels, command-palette providers, dashboard panels and widgets, task-card kinds, email blocks, automation triggers/steps/conditions, webhook events, import providers, crons, assistant tools, draft strategies, send transports, and restrict-only autonomy gates — each through a host-mediated registry that keeps core contributions first. Tenant-bound storage, plugin-scoped API keys, per-plugin LLM spend budgets, flag approvals and a plugin audit log bound what a plugin can reach. Tier-3 plugins run as sandboxed jobs on a dedicated `pluginTasks` worker queue with per-plugin in-flight caps. Ships with schema-rendered settings UI, an `owlat plugins` CLI, and three reference plugins — escalation-guard (Tier 1), Slack approvals (Tier 2) and Deliverability Lab (Tier 3). (#341)
- **Connected apps**: external services register with a lifecycle state machine, sealed secret exchange, a connection-test probe, and a signed synchronous hook protocol (draft / gate / score) with a circuit breaker and redacted, tenant-scoped delivery logs. (#341)
- **Own the Mail**: the whole mail path — parsing, composition, signing, verification, client and listener — is now in-house. New packages: `@owlat/mail-message` (parse + compose), `@owlat/mail-canon` (shared canonicalization), `@owlat/mail-auth` (SPF, DKIM, DMARC, ARC), `@owlat/smtp-client` and `@owlat/smtp-listener`. nodemailer, mailparser, smtp-server and mailauth no longer appear in any runtime dependency; they survive only as devDependencies powering the differential and shadow-replay harnesses that proved parity against them. (#368)
- **Mail capabilities** unlocked by owning the wire: true socket reuse over RSET-based pooled connections (#416), PIPELINING (RFC 2920) (#419), SMTPUTF8 / EAI internationalized addresses end-to-end with a fail-closed downgrade (RFC 6531–6532) (#421), AUTH XOAUTH2 for external Gmail and Microsoft accounts (#423), inbound ARC chain verification (RFC 8617) (#407), and a post-handshake peer verifier hook for DANE.
- **DNS setup revamp**: a zone/PSL foundation now backs DNS setup, so records render against the correct zone everywhere and the tracking-domain picker is guided rather than free-text. (#397)
- **Deliverability — the measured ramp**: a deliverability center that surfaces live mail-infrastructure health, backed by a measurement plane and one AIMD controller driving two actuators (send pace and transport mix). ## [0.3.0] - 2026-07-16

### Added

- **Sealed Mail**: end-to-end encryption for personal mail between Owlat instances (PGP/MIME, RFC 9580 via openpgp.js). Per-address keys are generated and sealed at rest, published over WKD and a signed `/.well-known/owlat.json` instance manifest, discovered with TOFU fingerprint pinning and Signal-style key-change alerts. Mail auto-seals when every recipient has a usable key; the reader shows a "Sealed" badge and decrypt-on-ingest keeps search and the AI agent working. Key rotation, revocation, and a recovery kit (no admin escrow) are included. Postbox 1:1 plane only.
- **Sender authenticity**: honest SPF/DKIM/DMARC badges on personal mail, including a "not authorized to send for this domain" state; inbound ARC verification rescues legitimately-forwarded mail; sender-impersonation heuristics (look-alike domains, reply-to mismatch).

Outbound TLS posture is selectable (`OUTBOUND_TLS_MODE`).
- **At rest**: all message bodies and stored `.eml` blobs are sealed with an instance data key; a fail-closed decrypt-serving proxy streams raw bytes on demand. DKIM private keys and SMTP relay credentials are sealed at rest (`MTA_SECRET`).
